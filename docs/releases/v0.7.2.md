# ZhuyinType 0.7.2

發布日期：2026 年 11 月 18 日
系統需求：macOS 14 或更新版本（Apple 晶片）；Windows 10、11（x64）；Debian 13、Ubuntu 25.04、Fedora 42、openSUSE Tumbleweed 或更新版本（x86_64，Fcitx 5）

## 改進

- 網路用語、店名與日常聊天的句子打得更準，例如 PTT 常見的用語與網路流行語。
- 技術與軟體用語更常一次就選對。
- 按錯鍵時，更常仍然得到正確的句子。
- 符號與 Emoji 面板的搜尋接收所有打字的鍵，數字鍵上的注音（ㄅㄉˇˋㄓˊ˙ㄚㄞㄢ）也能搜尋，例如按 9 4（ㄞˋ）找到愛心。按 ↓ 進入符號格子後，反白那一列才標出 1–9，按數字送出那個符號。
- Windows 與 Linux：預設按鍵和系統以詞為單位移動、刪除的按鍵相同，改用 Ctrl：改前一個字、改後一個字是 Ctrl+← Ctrl+→，翻頁的第三組鍵是 Ctrl+↓ Ctrl+↑，刪掉一個詞是 Ctrl+⌫，在組字中放一個空白是 Ctrl+Shift+空白。Windows 不把 Alt 組合鍵交給輸入法，0.7.1 的 Alt 預設在 Windows 沒有作用；Alt+空白 在 Windows、GNOME 與 KDE 也會開啟視窗選單。沒有改過這些按鍵的人直接換成新的預設，自己改過的按鍵維持不變。
- 加入自訂詞的按鍵（macOS ⌃Return，Windows 與 Linux Ctrl+Enter）只作用在清單開著時反白的字詞，沒有開清單時不做事。要把打的字加入自訂詞，用 Shift+← Shift+→ 選取再按 Return（Windows 與 Linux：Enter）。
- Windows 與 Linux：字詞動作後，候選字視窗的提示寫「Ctrl+Z 復原」，和 macOS 的「⌃Z 復原」相同。介紹、設定頁、設定嚮導與候選字視窗上的按鍵說明都依目前指定的按鍵顯示。
- Windows：「快捷鍵」頁不接受不含 Ctrl 的 Alt 組合鍵，並說明原因；「Alt 加數字或符號鍵打鍵上的符號」一列變暗，中文標點可以改用 Ctrl 加符號鍵。

## 修正

- macOS：選整句時，有些長度的句子評分會算錯（約占所有評分的 5%），現在每次都正確。
- Windows：更新後，開始功能表的搜尋框裡，候選字視窗有時是空白的，或下方的按鍵超出視窗。現在字型在第一次使用時讀進記憶體，更新時不受影響。
- 候選字視窗的大小依畫出的內容計算，大字級、高解析度螢幕、長的注音、只有一個字的清單都完整顯示。選取加入自訂詞時，提示列顯示完整的詞，最多六個字。
- macOS：候選字視窗依整段注音的寬度調整，長的注音完整顯示。
- Windows：在開始功能表的搜尋框開啟符號與 Emoji 面板時，面板出現在搜尋框旁，而不是螢幕下方的角落。
- Windows：App 結束組字或與輸入法服務的連線中斷時，符號與 Emoji 面板留在畫面上，但按鍵已交給 App。現在面板顯示時，按鍵都由面板處理；連線中斷時面板關閉。
- Windows 與 Linux：沒有指定給翻頁的 Alt+↑ Alt+↓ 仍會翻頁；「翻頁」關閉時，Page Up 與 Page Down 不翻頁。現在兩者都和 macOS 相同。

## 已知問題

- 帶前文的百科類長句略差（開發集 86.0% → 84.5%），多是人名與地名。新聞類句子持平。選錯時請從候選字清單選取，選過的字詞下次直接採用。
- 安裝檔約多 12 MB，因為聊天用的語言模型從 7.3 MB 變為 19.2 MB。
- macOS 每個按鍵的反應時間約多 3 毫秒（p95 10.8 → 13.7 毫秒）。
- 在 0.7.1 自己指定的 Alt 組合鍵在 Windows 沒有作用，「快捷鍵」頁會在按鍵旁說明。請改成 Ctrl 組合鍵。
- 簡體輸出是逐字轉換，沒有詞語對照，例如「乾坤」會寫成「干坤」。
- Linux 的 Wayland 工作階段中，符號與 Emoji 面板以候選字清單呈現（一次一列），候選字視窗不跟著主題。

## 準確率

App 的設定，整句全對率。macOS 與 Windows、Linux 使用同一份模型，Windows 與 Linux 的數字差在 1 個百分點以內。

| 評測集 | 0.7.1 | 0.7.2 |
|---|---:|---:|
| 口語 | 87.0% | 90.2% |
| 聊天 | 71.8% | 74.2% |
| 百科 | 81.2% | 81.2% |
| 百科（有前文） | 86.0% | 84.5% |
| 網路用語（善解） | 42.5% | 64.3% |
| 店名與名稱（善解） | 43.9% | 55.5% |
| 新聞（善解） | 85.8% | 85.8% |
| 打錯鍵的句子 | 56.8% | 57.7% |

完整結果見[研究紀錄](https://github.com/henry753951/ZhuyinType/blob/main/docs/research/log.md#072-的模型出貨資料data-11)與[聊天模型的完整評估](https://github.com/henry753951/ZhuyinType/blob/main/docs/research/chat-full-results.md)。
