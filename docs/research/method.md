# 下一代選字方法

這份文件根據[準確率損失分析](loss-analysis.md)與[詞庫與讀音資料調查](lexicon-survey.md)，提出 ZhuyinType 下一階段的選字方法：要解決什麼、怎麼解決、為什麼這樣設計，以及怎麼驗收。各輸入法的做法依其公開資料整理，出處見兩份來源文件。

## 1. 目標

照使用者以為對的注音打，整句的第一選擇就是對的。不需要從清單手動改字，也不靠「改過一次之後記住」。具體來說，下列四種打法的第一選擇都要對，而且前一種的成績不能因為後幾種而變差：

1. 照標準讀音打。
2. 照實際的唸法打：台灣讀音、輕聲照本調或一聲打、口語讀音、變調。
3. 照常見的誤讀打：有邊讀邊（「蚵」打 ㄎㄜ）、聲調記錯。
4. 按錯鍵：相鄰鍵、多按、漏按、順序打反（目前已有）。

同時不增加每鍵延遲與記憶體。

## 2. 問題在哪裡

損失分析把 43 個評測集、2,122 句錯誤逐句歸類，得出三個關鍵事實：

- 79% 的錯句，正解已經在重排模型看的前 16 句裡。大多數的錯不是找不到，而是不知道該選它。
- 詞表類的錯有 71% 引擎已經拼得出正解，缺的是「這是一個詞」與它的機率。只加詞條沒有用。
- 讀音問題在我們自己的評測集裡看不到，因為那些集合的讀音是用我們自己的詞庫產生的。換成獨立來源的讀音（善解的集合），讀音問題佔 12%，在輕聲詞集佔 64%。

歸結成五個根本原因：

| 根本原因 | 錯句 | 現在的做法 |
|---|---:|---|
| 詞彙封閉，新詞沒有機率 | 1,437 | 詞庫一次建好；沒收的詞只能用單字拼，單字的機率很低 |
| 排序與模型推翻 | 454 | 重排的權重固定；模型不知道候選是專有名詞還是一般詞，會把名字換成常見字 |
| 讀音被當成固定答案 | 115（善解集合 12%） | 一個字只能用詞庫列出的讀音打到 |
| 候選生成太窄 | 61 | 候選只來自詞庫的讀音比對，神經模型看不到詞圖以外的字 |
| 異形詞分開計數 | 55 | 宣布／宣佈、里／裡在語言模型裡是不同的詞 |

## 3. 從其他輸入法學到的

| 輸入法 | 值得學的做法 | 不足之處 |
|---|---|---|
| RIME | 「拼寫運算」：模糊音、縮寫當成規則，各帶固定成本 | 成本是人工設定的常數；規則要一條一條寫 |
| 善解 | 輕聲讀音給固定扣分；建置時從論壇語料挖新詞；改選時學新詞 | 扣分是固定值；新詞來自單一語料 |
| 新酷音 | 每次送出都自動學詞 | 不分好壞都學，容易學到碎片 |
| 唯音、小麥注音 | 詞庫裡多列變體讀音 | 變體與標準讀音同分，打對時容易被改錯 |
| 靈犀注音 | 「近音」候選；少數編譯期讀音規則 | 規則與成本未公開 |

共同的限制：沒有一家把「讀音可能不同」當成一個要估計的機率；成本若不是 0 就是人工設定的常數。

我們要合併的是這些做法的長處，再往前一步：**所有的「不確定」都放進同一個機率模型，每一個成本都由資料估計，並且能從真實的使用中持續校正。**

## 4. 方法：一個模型，四種不確定

整句的分數拆成四個相乘的機率（取對數後相加），每一項各自訓練，最後在同一張詞圖上融合：

```text
score(整句) = log P(按鍵 | 讀音)          按鍵通道：按錯鍵（已有，KeyChannel／KeyDecoder）
            + log P(讀音 | 字, 詞)        讀音通道：唸法與誤讀（新增）
            + log P(詞序列 | 前文)        開放詞彙的語言模型（擴充）
            + 神經模型的分數              逐字模型 v3 與整句重排，以學到的融合合併（改寫）
```

這和目前的架構原則一致：多層、可拆、分別訓練再融合。差別在於讀音也變成一個有機率的通道，詞彙變成會長大的，融合由資料學出來。

### 4.1 讀音通道

每個字在詞裡被打成某個讀音的機率，P(打的讀音 | 字, 詞)。讀音分成幾類，每一類有自己的成本：

| 類別 | 例子 | 成本的來源 |
|---|---|---|
| 標準讀音 | 蚵 ㄜˊ | 0 |
| 地區讀音 | 期 ㄑㄧˊ、熟 ㄕㄡˊ（台灣），套用到含這個字的詞 | 多份讀音資料的一致程度 |
| 輕聲的唸法 | 什麼 打 ㄕㄣˊ ㄇㄛˊ、陣子 打 ㄗˇ | 輕聲字的本調與一聲各一類 |
| 口語讀音 | ㄇㄛ／ㄇㄜ、ㄕㄜˊ | 口語語料中的出現比例 |
| 有邊讀邊 | 蚵 ㄎㄜ、綻 ㄉㄧㄥˋ | 同聲旁的字讀音一致的程度：越一致，誤讀越常見，成本越低 |
| 聲調記錯 | 一二聲、三四聲互換 | 按錯鍵資料已有的聲調混淆率 |
| 古音、罕用讀音 | Unihan 的 kHanyuPinyin | 最高成本，只在其他都對不上時出現 |

**成本怎麼學出來（不靠人工）：**

1. **初始值**：用多份互相獨立的讀音資料當成「標注者」，包括 CC-CEDICT、Wiktionary 台灣讀音、全字庫 CNS11643、Unihan、小麥注音。一個讀音被越多資料收錄，成本越低。有邊讀邊的成本則依同一個聲旁的字讀音有多一致來定。
2. **調整**：在誤讀評測集上，用最大概似估計每一類的成本，條件是照標準讀音打的開發集不能變差（帶限制的最佳化）。
3. **持續校正**：使用者開啟改字記錄、並同意分享時，「打的讀音」與「最後要的字」的配對累積成真實資料，重新估計各類成本。這是統計層級的更新，不是記住某個人的某個字。

**實作分兩步：**

- **現在（只改資料）**：單字的變體讀音、台灣讀音套用到詞、輕聲變體，帶成本寫進詞庫。不必改引擎，就能參與整句計算。
- **Rust 引擎換上後**：引擎比對時以音節為單位查字，詞裡允許一個音節走讀音通道。這樣不必把每個詞的誤讀都事先展開；全部展開會多出約 21 萬列，比整個詞庫還大。

### 4.2 開放詞彙與詞的機率

新詞必須有機率，否則收了也選不上。

1. **自動發現新詞**：在語料上做期望次數斷詞，依「凝固度」（字之間的互資訊）與「左右鄰接熵」（前後接的字是否多樣）挑出新詞候選。這是善解從論壇挖詞做法的通用版本，語料用我們已有、授權可用的維基、口語、對話語料。
2. **授權可用的名錄**：小麥注音、全字庫、政府開放資料的地名、學校、機關、公司，以及善解以 CC BY-SA 釋出的詞包。
3. **重新斷詞、重算詞頻**：所有新詞進入語料，重新訓練百科與聊天兩個語言模型，取得真正的詞頻與接續機率。
4. **沒有詞頻的詞用詞類回退**：依詞的來源（地名、店名、自動發現、個人）給一個詞類先驗，取代現在的「詞庫分數＋常數」。這需要改引擎，等 Rust 換上後做。
5. **碰撞檢查**：新詞不得改壞既有詞單獨打時的第一選擇（善解的做法）。

### 4.3 讓神經模型學會唸法與誤讀

逐字模型 v3 依整句的讀音和前文，判斷每個位置是哪個字。重新訓練時，在訓練資料的讀音上加入第 4.1 節的各類變體，比例依各類成本：

- 模型學的是「在這種上下文裡，這個讀音通常是哪個字」，例如「鮮＿」配上 ㄎㄜ 是「蚵」。這是最通用的一層：不需要任何逐字規則。
- 同時讓 v3 在每個位置提出機率高、但不在詞圖裡的字，加進詞圖（候選生成太窄的問題）。這部分需要改引擎。

### 4.4 學到的融合與重排

- **重排模型用自己的前 16 句訓練**：listwise 目標，引擎分數一起進 softmax；補足新聞、公文、聊天等目前不足的語體。損失分析估計可回收 150–200 句。
- **融合帶入候選的來源**：每個候選的特徵包括引擎分數、v3 分數、重排分數，以及來源（專有名詞、詞包、自動發現的詞、個人詞、讀音通道的類別與成本）。由學到的融合取代目前手調的權重，模型就會知道「這是名字，不要換成常見字」。

### 4.5 統一異形詞

語言模型訓練前，把異形詞歸成同一組計數（OpenCC 的台灣異體表，加上修正「里／裡」這類轉換錯誤）。輸出時依「台／臺」設定的寫法規範選字。

## 5. 驗收

| 評測 | 內容 | 標準 |
|---|---|---|
| 誤讀集 `misread-dev` | 真實句子依第 4.1 節的變體比例打成 | 第一選擇的整句全對率明顯提升 |
| 獨立讀音的開發集 | 我們的開發集改用獨立來源的讀音重標 | 讀音類錯誤減少 |
| 標準讀音的開發集 | 現有的四個開發集 | 不變差（成對檢定），打對時被改錯的比例不增加 |
| 按錯鍵 | `zt eval typo`、`typing-errors` | 不變差 |
| 新詞 | 依時間切分的專有名詞集（獨立於善解的詞包） | 提升 |
| 每版報告 | `zt eval losses` 依根本原因列出錯句數 | 每一類逐版下降 |
| 延遲與記憶體 | Mac 上量測 | 每鍵 p95 不增加 |

測試集只在決定之後跑一次。所有比較用成對檢定，結果寫進研究紀錄。

## 6. 執行順序

依賴關係與兩個限制決定順序：訓練要等詞庫與語言模型完成；引擎的改動要等 Rust 換上後只改一次。

| 階段 | 內容 | 依賴 | 預期收益（損失分析的估計） |
|---|---|---|---|
| A（進行中） | 讀音變體資料、輕聲變體、台灣讀音套用到詞、誤讀集、新詞發現與名錄、異形詞統一、語言模型重新斷詞與計數 | 只改資料 | 輕聲詞集 +13.7 pp；辭典例句 +6.3 pp；我們的集合約 +1.5 pp；善解整句集約 +2.7 pp；詞表大幅提升（需獨立集確認） |
| B（Rust 換上後） | 引擎的讀音通道（詞內一個音節）、未知詞的詞類回退、v3 提出候選 | Rust 第五階段 | 讀音類 115 句的 60–80%；候選生成 61 句 |
| C（A 合併後） | v3 加讀音變體重新訓練；重排 listwise 訓練；學到的融合 | A 的詞庫與語言模型 | 排序與推翻 454 句中回收 150–250 句（各集合 2–4 pp） |
| D（持續） | 用改字記錄（使用者同意分享時）重新估計讀音成本、發現新詞 | 改字記錄 | 依累積的資料 |

## 7. 不做的事

- 不針對個別字或詞寫規則或補資料。所有改動都是通用機制，個別例子只用來驗證。
- 不讓變體讀音和標準讀音同分。
- 不使用授權不相容的資料：教育部各辭典與萌典（CC BY-ND）、LGPL 與 GPL 的詞庫、靈犀注音的程式與資料。
- 不把「改過一次記住」當成解法。個人學習保留，但只是輔助。
