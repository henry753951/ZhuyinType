## 2026-10-27

**統計底子 A1：小麥注音詞庫＋期望次數語言模型。** 詞庫併入小麥注音（MIT，23.3 萬列，新增 9.8 萬詞、7.7 千個讀音；既有分數不動）；兩個詞 bigram 改用詞圖上的期望次數重新計數（不是單一斷詞路徑），維基模型放大到 536 萬個 bigram，聊天模型用真實台灣文字重新斷詞。只用引擎（測試集，成對）：口語 71.0 → 80.3%（改對 47／改壞 10，p < 1e-6）、維基 66.5 → 72.0%、有前文 67.0 → 71.3%，但 Taiwan Tongues 79.8 → 76.5%（寫法視為相同）、日常短句 97.1 → 92.6%。整套 app：口語 83.3 → 84.0、維基 81.0 → 82.5、有前文 87.0 → 86.5、Taiwan Tongues 與日常短句不變，全部不顯著；按錯 5% 的開發集兩組都 −1 分、一聲變調 −1／−3 段。詞庫與語言模型必須一起換（只換語言模型、保留舊詞庫：引擎 72.2%）。詞稽核：單獨打每個詞，31% 的詞贏不了（同音詞 78%、新增單字幾乎全輸）。→ **0.4.0 不採用**：app 沒有可測的提升、按錯鍵處理略差、聊天模型含 Taiwan Tongues 訓練文字（TRAIL，不能隨 app 發布）、維基模型大一倍。保留為研究成果（`nlp/training/base/`），之後在神經層重新調權重、拿掉 Taiwan Tongues 後再評估；只用引擎的大幅進步對沒有神經模型的平台（Linux／Windows 輕量模式）有價值。

**在／再微調（第一輪）在 app 設定下的一般開發集。** 口語 87.0 → 86.8%、Taiwan Tongues 71.2 → 71.0%（寫法視為相同 85.5 → 85.2%）、日常短句 100%、維基有前文 83.8 → 83.5%：雜訊範圍內略低。在／再封存測試 86.96 → 91.06%（無前文）、91.63 → 94.77%（有前文）。→ 不採用：微調資料有 25% 來自 Taiwan Tongues。第二輪只用可發布的來源重做（進行中）。

**聊天模型 v2：真實口語。** 立法院公報逐字稿 20.4 萬句、維基百科討論頁 7 千句、Common Voice；產生的多輪對話樣本品質審查沒過，不用。困惑度大降（口語 4,864 → 1,445、Taiwan Tongues 3,084 → 1,719）。轉換（開發集）：口語 85.5 → 87.0%、Taiwan Tongues 70.0 → 71.2%（寫法視為相同 84.0 → 85.5%）、維基有前文 84.2 → 83.8%（c₀ = 0.3；c₀ 越高維基越差）；沒有前文時「或是」不變。→ 採用，c₀ 0.5 → 0.3。新模型不含 Taiwan Tongues，app 不再受 TRAIL 授權限制。

**選字後固定其他字、重排門檻。** 實作「在清單選字後，其他已顯示的字固定」（善解 repick-freeze）與重排門檻 τ／δ（善解 tinylm pick）；新工具 `repick_eval.py` 模擬選字。40 段口語的試跑：不用選字 82.5%、最多選 1 次 95.0%；選字改壞其他字 不固定 5.0% → 固定 2.5%（剩下的是選到跨在詞中間的字）。τ／δ 掃描（開發集，聊天模型 v2、c₀ 0.3）：τ = 8 與不設門檻的輸出完全相同（1,200／1,200），10 音節每鍵 p95 24.1 → 14.7 ms；τ = 4 維基有前文 −0.3、τ = 2 −1.0；任何 δ > 0 都變差（δ = 1：口語 −1.0、維基 −2.6）。→ 採用 τ = 8、δ = 0。和善解不同，我們的重排改對的遠多於改壞，不需要保守門檻；門檻只用來省延遲。

**對打：靈犀注音。** 同一批句子、同樣注音輸入。靈犀只用統計引擎：維基 66.0%、口語 82.3%、日常短句 98.5%、Taiwan Tongues 82.5%；ZhuyinType 只用引擎 68.5／74.0／92.7／67.3%，app 81.0／82.3／100／74.5%（寫法視為相同時 Taiwan Tongues 85.8% 對 85.3%）。→ 我們的統計底子在口語上落後，列為 [program.md](program.md) A1。靈犀的 D512 組在評測主機上逾時，不採用。

**研究：對手的完整研究紀錄。** 讀完善解的研究紀錄（9,353 行）、約 120 份合約與所有實驗，以及靈犀的技術報告與研究頁，整理成約 560 條（[catalogue/](catalogue/)）與 [program.md](program.md)。最重要的三個教訓：在維基與生成句上的進步不一定轉移到真實聊天；重排要有門檻、用改壞率上界選參數；改選後其他字要固定。

**v3 的隱含邊界輸入。** 讓 v3 知道哪些音節是「一聲沒按空白」結束的。error_analysis：一聲不按空白 口語 64.7% 對 64.7%、維基 54.2% 對 54.5%；按錯 5% 64.2% 對 64.0%。→ 沒有可測的差異，維持開啟（這是 v3 訓練時用的訊號）。

**每鍵延遲：前綴樹計分＋沿用上一次結果。** 16 句排成前綴樹，同一份權重（祖先遮罩、深度位置）：11 音節 p95 31.8 → 21.6 ms，25 音節 53.4 → 39.9 ms，每鍵能耗少 36%；只多打未成音節的注音符號時，整句重排與 v3 沿用上一次結果，25 音節 p95 再到 33.0 ms。Linux 決定 5,209／5,209 相同；Mac（fp16）900 句 1 句不同（近乎平手）。→ 採用。先試過「把 16 句的共同開頭當前文」，共同開頭只有 2–7 字，沒有效果，撤掉。

**記憶體：mmap 二進位。** 詞庫與兩個語言模型在建置時編譯成二進位、執行時對應：輸入法常駐 222 → 29 MB，載入 1.25 → 0.08 秒；遠端 2,000 行與 TSV 版完全相同。→ 採用。

**「台／臺」寫法。** Taiwan Tongues 的「錯誤」多半是「臺中／台中」「妳／你」：整句 66.7% 而寫法視為相同 81.7%。→ 評測加上「寫法視為相同」分數；app 預設寫「台」（只改顯示與送出的文字，不改選字）。

**聊天／百科混合與 v3 權重。**（開發集，整句重排開啟）只用百科：口語 85.0%、Taiwan Tongues 67.8%、維基有前文 84.0%；v3 0.5：86.5／71.5／85.8%；v3 1.0：85.2／71.8／85.2%；句尾比例 0.5 單獨使用讓口語變差（84.0%）；聊天 0.5＋v3 0.5：87.0／70.2／85.5%。五項平均打平。→ 採用 v3 0.5＋聊天 0.5：沒有前文時句首 ㄏㄨㄛˋ ㄕˋ 是「或是」（只用百科時是「獲釋」）。測試集：維基 80.8 → 81.0%、口語 82.8 → 83.2%、日常短句 100%、Taiwan Tongues 72.2 → 74.2%（寫法視為相同 82.5 → 85.5%）。

**聊天語言模型。** 590 萬句口語（Qwen3-8B 產生＋Common Voice＋Taiwan Tongues）訓練的詞 bigram，困惑度在三個開發集都比百科模型高（口語 4,864 對 1,349）；價值在句首與日常用詞的機率。→ 只作為混合的一部分；真實口語語料列為下一步。

**v3 逐字模型。** 前文編碼器（6×512，255 字）＋雙向音節編碼器（6×512，交叉注意力），候選限定的 softmax；開發集每個位置首選約 95%（只用詞庫單字頻率 63–66%）。接進詞圖後沒有整句重排時：口語 75.5 → 82.5%、維基有前文 71.5 → 77.2%。

**按鍵層級解碼器。** 比較 slots、boundaries、reorder、timed 四種方法（計時打字錯誤評測，兩個開發集各 100 句）：平均 33.6% → 54.7%（timed），幾乎同時按下 36 → 76.5%，一聲省略空白 0 → 56%。熱點替換成本沒有比固定成本好（40.5% 對 40.5%）。→ 採用 timed，熱點成本預設關閉，個人按錯習慣採用。

**打對的鍵優先。** 修正過的整句要多 4.0 分才成為首選：差距 2 時「今天ㄉㄠˇ」被改成「今天的」；4.0 打對時一樣好或更好（打對時被改錯 0.0%／1.0%）。三四聲互換成本 3.5 → 5.0：打對時被改錯 1.7% → 1.0%。
