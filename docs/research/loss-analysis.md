# 準確率損失分析：錯在哪裡、為什麼錯

這份文件把 ZhuyinType 在 43 個測試集上的每一個錯句分類，找出錯誤背後的根本原因，再依預期收益排出下一步要做的事。數字是 2026-10-28 用 App 的設定量的（main `6e8107f`，資料 data-3）。

和其他輸入法的比較只用來看清楚我們自己的不足。善解與靈犀注音的做法依它們公開的文件整理，見 [相關工作](related-work.md)；比較的條件與限制見 [與其他注音輸入法的比較](../benchmarks/competition.md)。

## 摘要

8,166 句中 ZhuyinType 錯 2,122 句。依根本原因分：

| 根本原因 | 全部 | 一般句子（5,402 句，錯 802） | 詞表（2,764 句，錯 1,320） |
|---|---:|---:|---:|
| R1 詞彙是封閉的：詞庫沒有這個詞，也沒有自動發現新詞的機制 | 1,437 | 212（26%） | 1,225 |
| R4 排序：正解在重排的 16 句裡，但沒有選它 | 338 | 321（40%） | 17 |
| R5 模型推翻：只用引擎是對的，或 v3 之後的首選是對的，被後面的模型換掉 | 116 | 112（14%） | 4 |
| R2 讀音是固定的答案：打的讀音不在詞庫裡這個詞或這個字的讀音中 | 115 | 55（7%） | 60 |
| R3 候選生成：詞庫拼得出正解，但它不在前 16 句 | 61 | 60（7%） | 1 |
| R6 寫法：正解與輸出只差異形詞（宣布／宣佈、公布／公佈、里／裡） | 55 | 42（5%） | 13 |

- 一般句子指我們的維基、口語、對話與日常短句、靈犀的公開回歸案例，以及善解的 dev302、使用者回報、保留集、教育部辭典例句等整句的集合。詞表指善解的店名、人名、網路用語、IT、ACG、輕聲詞等一行一個詞的集合。
- 正解在重排模型看得到的 16 句裡的錯句有 1,672 句（79%）。也就是說，大部分的錯不是找不到正解，而是不知道該選它：詞表的缺詞有 71% 的正解在 16 句裡，缺的是「這是一個詞」的知識與它的機率。
- 模型（v3 與整句重排）改對 1,353 句、改壞 175 句。改壞的集中在詞表（97 句），重排模型把名字換成常見的字。
- 我們自己的四個集合幾乎看不到 R2（1 句），因為它們的讀音是用我們自己的詞庫產生的。善解的集合用教育部或人工的讀音，R2 在這些集合佔 12%，在輕聲詞集佔 64%。
- 建議先做：(1) 用獨立來源重標我們開發集的讀音，讓評測看得到讀音問題；(2) 機率式的讀音通道；(3) 新詞的機率來源（重新斷詞計數與詞類回退），讓詞庫擴充真的打得出來。順序與理由見[突破清單](#突破清單)。

## 方法

### 資料與設定

- ZhuyinType：App 的設定（`--config app`：重排 16 句、權重 1.0，v3 權重 0.5，聊天模型 0.3），每句重設學習，不帶前文的集合不帶前文，善解的集合帶它自己的前文欄。另外跑只用引擎（詞庫與語言模型）。
- 集合：善解的 39 個原始集合（5,583 句，包括沒有排除重疊的原始檔），以及靈犀比較用的 8 個集合（我們的維基、口語、對話開發與測試、日常短句，靈犀的公開回歸案例，共 2,583 句）。讀音與 [h2h 比較](../benchmarks/competition.md)的凍結輸入相同。
- 對方的輸出沿用 2026-10-27 那次比較的逐句輸出：善解聊天、正式配置（commit `bd3b609`），靈犀統計引擎與 D512（v0.2.6 時期，commit `3fb0917`）。這裡的 ZhuyinType 是重排權重 1.0 的 App 設定，所以和比較頁面（權重 0.5）的數字略有不同。
- 正規化：善解的寫法正規化（她妳它牠嘗周臺裏與它固定版本的 `variants.tsv`），三方都套用。靈犀比較頁面用的是我們的 11 組寫法，所以我們的四個集合的數字和那一頁差 1 個百分點以內。

### 每一句記錄什麼

`zt eval losses`（`ml/src/zhuyintype_ml/eval/losses.py`，這次新增）對每一句記錄：App 送出的字、App 的前 64 句（引擎加 v3 的分數，也就是重排模型挑選的範圍）、只用引擎送出的字與前 64 句。錯句先依「正解在哪裡不見」分階段：

| 階段 | 意思 |
|---|---|
| reranker | 重排前的首選是對的，重排換掉了 |
| v3 | 只用引擎是對的，v3 把別句排到前面 |
| pool16 | 正解在重排的 16 句裡，沒被選上 |
| poolK | 正解在前 64 句，但不在 16 句裡 |
| missing | 前 64 句都沒有正解 |

再依詞庫判斷原因（依序取第一個符合的）：

| 原因 | 判斷 |
|---|---|
| sandhi | 錯的字是「一」「不」，打的是變調 |
| neutral、tone、reading | 錯的字打的讀音，詞庫裡這個字的任何詞都沒有；只差輕聲、只差聲調、或音節不同 |
| oov | 覆蓋錯處的詞在參考詞彙裡、不在我們的詞庫；詞表集合的整行也算 |
| word-reading | 覆蓋錯處的詞在我們的詞庫，但沒有打的這個讀音（再細分只差輕聲、只差聲調、音節不同） |
| phrase | 連續兩個以上錯字，任何詞庫都沒有覆蓋它的詞：名字、罕用語 |
| form-word | 只差異形詞的字（布佈、分份、占佔、里裡等 70 組） |
| char-function、char-content | 只錯一個字，前後都對：虛字（的地得、在再、個各）或實字 |
| word | 詞庫裡的詞被另一個同音的詞取代 |

根本原因由原因與階段決定：oov、phrase 是 R1；讀音類是 R2；form-word 是 R6；其餘依階段，missing 與 poolK 是 R3，reranker 與 v3 是 R5，pool16 是 R4。

參考詞彙只用來判斷「這是不是一個詞」，不進詞庫：善解的基底（小麥注音資料，MIT）與疊加層（維基詞典、維基百科標題）、靈犀注音的詞庫（小麥注音、全字庫、CC-CEDICT、內政部路名與村里等），只算兩者都收的詞，避免把「心的」「再進」這類片段當成缺詞；另外加上善解的名單與詞包（店名、創作者、網路用語、IT、ACG）。檔案只在本機使用。

### 人工抽查

自動分類分不出「需要前文才能決定」「專有名詞」「兩種都對的用字習慣」。從我們的四個測試集與善解的 dev302、保留集、使用者回報中，隨機抽 70 句 R3–R5 的錯句人工判讀（種子 3）：

| 判讀 | 句數 |
|---|---:|
| 有明顯較通順的正解（模型可以學到）：誠摯／承製、密封罐／蜜蜂罐、我再換／我在換 | 32 |
| 兩者都通或要更多前文：句子片段、擬訂／擬定、反映／反應、喝久了／喝酒了 | 20 |
| 專有名詞：黃慧／黃惠、靖堂、延溪公路 | 11 |
| 新詞：版控、絲滑、薅羊毛 | 4 |
| 參考答案本身可疑（利於期經營、心理微微不悅） | 2 |
| 異形詞（沈積岩／巖） | 1 |

R4 的錯句裡，正解排第 2 的有 43%，前 4 名內的有 72%。

### 限制

- 原因是用詞庫自動推斷的，抽查之外沒有逐句確認。R1 依賴參考詞彙，參考詞彙沒有收的詞會落到 phrase 或 char-content。反過來，參考詞典也收了一些片語（「只為了」「再不走」「查到」）：一般句子 oov 抽看 26 句，約 7 句是這類片語，實際是排序錯，所以一般句子的 R1 約高估三成、R4 低估。
- 我們的四個集合的讀音由我們自己的詞庫產生，看不到 R2（見 R2 一節）。
- 詞表集合是善解從自己的詞包與名單挑出的（店名 225 句全部在它的 `names-stores.tsv`，網路用語兩輪全部在它的疊加層）。這些集合量的是「詞庫有沒有收這些詞」，對任何從同一份名單建的詞包都是樣本內。
- 只看整句全對；只跑一次；p 值與成對檢定見比較頁面。

## 根本原因

每一節先寫看到的症狀，再寫背後的機制。

### R1 詞彙是封閉的

**症狀**：店名 162 句、網路用語 791 句、創作者 77 句、IT 42 句、ACG 119 句缺詞；一般句子 212 句（26%），例如「大賺特賺」打成「大篆特撰」、「話家常的婦女」打成「畫家長的婦女」、「拭鏡布」打成「試鏡不」、「酷澎」打成「庫彭」。

**根本原因**：詞庫是一次從 CC-CEDICT、Unihan 與 wordfreq 建的封閉清單，沒有機制把語料裡出現的新詞加進來；語言模型只認得斷詞時用的這份詞彙。不在詞彙裡的詞只能由單字拼出，單字的 bigram 會輸給同音的常用詞。

證據：

- 詞表的缺詞有 71% 的正解已經在重排的 16 句裡（869／1,225）。引擎拼得出來，缺的是「這是一個詞」的知識與它的機率。
- 一般句子的 R1 中，116 句的詞同時收在小麥注音系與靈犀的詞庫（公開詞典已經有），83 句任何參考詞彙都沒有（人名、地名、罕用語，例如「斯氏鼬鯰」「花岡楓士雄」「苪氏規模」），12 句只在善解的名單。
- 善解量過「只加詞、不給語料次數」的效果：詞包詞拿到同字數第 25 百分位減 1.0 的分數，兩字詞 98.7% 輸給常用字的組合（[names-lexicon 契約](https://github.com/Nanako0129/shanjie/blob/bd3b6095e170012e5675b15b9443786a04103790/docs/contracts/names-lexicon.md)、研究紀錄 2026-10-10）。他們的做法是把名單放進語料斷詞的詞彙重算次數（model-v6），選用詞包的詞則不走通語的統計，用詞包自己的分數（[pack-oov 契約](https://github.com/Nanako0129/shanjie/blob/bd3b6095e170012e5675b15b9443786a04103790/docs/contracts/pack-oov.md)）。
- 我們的引擎對語言模型沒有收的詞，用詞庫的 unigram 加上 `unknown_word_shift`（目前 0），沒有前文，也沒有詞類。

### R2 讀音是固定的答案

**症狀**：115 句。期中 ㄑㄧˊ、足跡與戰績 ㄐㄧ、意識 ㄧˋ ㄕˋ、攜手 ㄒㄧ、熟悉與成熟 ㄕㄡˊ、露出 ㄌㄡˋ、儲值 ㄔㄨˊ、汐止 ㄒㄧˋ、紅檜 ㄍㄨㄟˋ、波 ㄆㄛ、癌 ㄧㄢˊ；輕聲字打本調（陣子、椅子的子打 ㄗˇ，29 句）；口語讀音（什麼 ㄕㄣˊ ㄇㄛˊ、什 ㄕㄜˊ、怎 ㄗㄜˇ、兒 ㄦ）。

**根本原因**：讀音是詞庫裡每個詞的固定答案，不是機率。

- 詞的讀音整筆來自 CC-CEDICT，多數是大陸讀音。字的台灣讀音（期 ㄑㄧˊ、識 ㄕˋ）沒有傳到含這個字的詞；MODEL §2.3 的「台灣讀音至少 25%」只作用在單字。
- 打的讀音不在詞的讀音裡時，只有 KeyChannel 的聲調容錯（三四聲 5.0、二聲與輕聲 4.5）能救；一聲與二聲、輕聲與三聲、ㄇㄛ 與 ㄇㄜ 都不在裡面，所以 41 句的正解根本不在前 64 句。
- 輕聲與變調是規則（MODEL §2.4 一、不變調），不是學到的變體。

在善解的集合，善解聊天對了我們錯的 R2 有 43 句（54 句中）。它的基底詞庫（小麥注音）本來就是台灣讀音，另外有輕聲詞的本調列（[neutral-tolerance 契約](https://github.com/Nanako0129/shanjie/blob/bd3b6095e170012e5675b15b9443786a04103790/docs/contracts/neutral-tolerance.md)）、教育部「一／不／法」的讀音變體，以及 v0.5.0 的讀音通道項。

我們的四個集合只有 1 句 R2，因為句子的讀音是用我們的詞庫產生的：詞庫沒有的讀音不會出現在測試裡。善解也記錄了同樣的教訓：評分用到讀音時，只用工具產生讀音的集合會看不到改壞（[methodology](https://github.com/Nanako0129/shanjie/blob/bd3b6095e170012e5675b15b9443786a04103790/docs/methodology.md) 2026-10-21）。

### R3 候選生成

**症狀**：61 句的正解拼得出來（詞都在詞庫裡），但不在 16 句裡；「蛤蠣」「親子丼」「權限」「姊姊快幫我戴項鍊」。

**根本原因**：候選只來自詞圖的 N-best，v3 只能替詞圖裡已有的字（每個位置依詞庫分數取前 64 個）加分，不能提出新的字；正解在引擎排名靠後時就進不了重排。v3 把只用引擎時在 16 句內的正解擠出去 67 次，拉進來 294 次，整體是正的。

### R4 排序

**症狀**：321 句一般句子（40%）。正解排第 2 的佔 43%，前 4 名內 72%。抽查中約一半有明顯較通順的正解（誠摯／承製、密封罐／蜜蜂罐、我再換／我在換）。一般句子只錯一個字的錯句中，虛字 82 句（再／在、的／地／得、個／各），實字 223 句。

**根本原因**：

- 重排模型（v2b）是一般的字級語言模型，用語言模型的目標訓練，不是用「在我們自己的 16 句裡挑對」的目標訓練（[plan](plan.md) B1）。
- 語料的分布：百科模型以維基為主，聊天模型以立法院逐字稿為主。善解保留集的新聞（政府新聞稿、公文用語：嗣、俟、復查、提攜）與網路聊天（版控、反灰、絲滑）都不在主要語料裡。
- 約三分之一要更多前文或本來就兩可（擬訂／擬定、反映／反應），16% 是專有名詞；這部分靠前文與個人記憶，不靠語言模型。

### R5 模型推翻

**症狀**：所有錯句中，階段是重排的有 187 句、v3 的有 96 句；扣掉原因已歸到詞彙、讀音或寫法的，116 句歸到 R5。詞表裡重排常把名字換成常見的字（「旺宏」換成「王鴻」）。一般句子 112 句，例如「簡易行政工作」換成「檢疫行政工作」、「還有一般地鐵票」換成「還有一班地鐵票」。

**根本原因**：融合是固定權重（引擎 + 1.0 × 重排），重排模型不知道一個候選來自專有名詞、詞包或個人學過的詞，也沒有自己的信心。對照：模型改對 1,353 句、改壞 175 句；δ > 0 的門檻已證實整體變差（MODEL §7），所以不能用單一門檻擋。

### R6 寫法

**症狀**：55 句只差異形詞：公布／公佈、宣布／宣佈、布告欄／佈告欄、占有／佔有、分布／分佈、部份／部分、扎根／紮根、污水／汙水，以及村里名「中華里」「埔心里」被寫成「中華裡」「埔心裡」。

**根本原因**：語料轉換成正體時留下了兩種寫法，語言模型分開計數，偏好的寫法依語料來源而定，沒有一致的用字規範；「里→裡」是轉換對照表把村里的「里」也換掉了。善解遇過同類問題（OpenCC 把台灣字形當簡體，[s2f-variant-forms 契約](https://github.com/Nanako0129/shanjie/blob/bd3b6095e170012e5675b15b9443786a04103790/docs/contracts/s2f-variant-forms.md)），做法是用 OpenCC 的 `TWVariants.txt` 統一字形。

### 沒有從真實的改字學習

這不是單獨一類錯句，而是 R1 與 R4 在使用者回報集的來源：使用者回報（dev）的 57 個錯句中 19 句是新詞（版控、落檔、反灰、盲狙、吉鶴卡），27 句是排序。App 現在有改字記錄（0.4.2，選用），但只用來重播評測，個人模型也只記「同一讀音的整段或部分」，不會把逐字改選拼出的新詞當成詞庫詞在其他前文使用。善解的新詞 B（[newword-b 契約](https://github.com/Nanako0129/shanjie/blob/bd3b6095e170012e5675b15b9443786a04103790/docs/contracts/newword-b.md)）在模擬中學到 9 個詞、7 個是真的缺詞。

- **讀音**（善解，R2）：見 R2 一節。
- **詞類回退**（善解，R4）：Brown 式 512 個詞類，兩個詞沒有一起出現過時，用詞類 bigram 補估計；起因正是「詞態→磁態」「對齊→對其」這種罕見組合退回單字頻率的錯（[s2k-word-classes 契約](https://github.com/Nanako0129/shanjie/blob/bd3b6095e170012e5675b15b9443786a04103790/docs/contracts/s2k-word-classes.md)），在 dev302 聊天 +12（15／3）。這兩個例子在我們這裡也錯（「對其」「慈太」）。
- **口語統計**（靈犀，R4）：統計引擎的詞頻來自新聞與 PTT 的斷詞次數。在我們的口語與對話集合，它的統計引擎和我們的整套 App 差異不顯著，而我們只用引擎時低 8–14 個百分點。

我們較高的部分主要在書面維基句子、有前文的句子，以及虛詞集（fw）；使用者回報集反映的是善解自己挑出的錯句，比較的意義有限。

### 引擎層的想法（Swift 與 Rust 兩版都要改）

1. 讀音通道（第 1 項）：比對時以音節為單位查字，再用通道成本組成詞的讀音分數，取代「（讀音, 詞）完全相符或聲調容錯」。詞的特定讀音（多音字的詞義）仍以詞的讀音機率表示。
2. 未知詞分數（第 2 項）：語言模型沒有收的詞，用詞類 bigram 與詞類內機率，或依詞的來源（詞包、個人、自動發現）分層的先驗，不再用詞庫 unigram 加常數。
3. 候選字來自 v3（第 8 項）：`scoreCharacters` 的字集除了詞圖的字，加入 v3 在該位置的前幾個字，作為單字邊。
4. 融合（第 5 項）：重排與 v3 的分數加上候選來源的特徵，由學到的融合決定。

這四項都改變輸出，要用 `engine/parity/` 確認兩版逐位元相同。

## 給同時進行的工作

- **詞庫擴充**：只加詞條、不給機率，多半打不出來（詞表 71% 的錯已經是「正解在 16 句、輸在機率」）。請和第 2 項一起做：新詞進語料斷詞重算次數，或在引擎給未知詞詞類先驗；並用 `zt eval losses` 看「詞庫有／16 句裡有／首選」三層。用善解的名單建的詞包，在善解的詞表集合上是樣本內，請另建獨立的檢查集。
- **比較工具**：每個集合請記錄讀音的來源（工具產生、教育部、人工），並把 `zt eval losses` 的階段與原因一起存，跨版本才看得出是哪一類在變。

## 重現

```sh
# 在 GPU 主機上收集每句的輸出與前 64 句（約 20 分鐘，16 個行程）
tools/zt --remote --export --push data/build/loss-analysis/rows --env ZT_BUILD_JOBS=16 --detach \
  eval losses --jobs 16 -k 64 --set data/build/loss-analysis/rows/*.txt \
  --whole-words names acg it-words net-slang neutral-words --json data/build/remote_eval/loss/losses.json
# 在本機加上參考詞彙重新分類（不跑引擎）
python -m zhuyintype_ml.eval.losses losses.json --lexicon data/build/lexicon.tsv \
  --reference general_both.tsv sj_packs.tsv --shanjie-variants shanjie-variants.tsv \
  --whole-words names acg it-words net-slang neutral-words --out reclassified.json
```

`data/build/loss-analysis/rows/` 是由 h2h 比較的凍結輸入轉成的列檔（善解 39 個、靈犀 8 個）。參考詞彙由善解（`bd3b609`）與靈犀注音（`3fb0917`）的詞庫檔轉成，只在本機使用。form-word 細分、根本原因對應與各表的彙整在分析腳本裡，沒有放進版本庫。
