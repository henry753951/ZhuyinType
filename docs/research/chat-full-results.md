# 聊天模型候選的完整評估結果（2026-11-17）

這份文件列出 `chat-full` 評估的每一個指標，比較的是出貨中的聊天模型（`shipped`）與建議的候選 `ptt-cns-genpub`。後者用的語料是 PTT 八卦版、篩選後的大陸語料，加上 Haiku 產生的主題句。做法與結論見[研究紀錄](log.md)的「聊天模型的完整評估」一條，語料授權見 [corpus-sources.md](corpus-sources.md)。

## 條件

- 評估都在 GPU 主機上跑，用 App 設定，只以 `--chat-lm` 換掉聊天模型，其他元件和出貨版相同。
- 延遲是在 Mac 上量的，出貨版和候選交錯各跑 8 次。
- 矩陣是 `ml/src/zhuyintype_ml/eval/matrices/chat-full-{conversion,rows,typing,corrections}.json`。
- 每一項的原始報告（含每段的輸出）不放進版本庫，存在 `data/build/remote_eval/chat-full/`，可以用 `zt eval stats` 重新配對。
- 開發集用來做決定，測試集只追蹤。
- 「改對／改壞」是逐項配對：出貨版錯、候選對的數目，以及出貨版對、候選錯的數目。p 是 McNemar 雙尾精確檢定，只在 p < 0.05 時列出。
- Δ 是候選減出貨版，單位是百分點。CER 是字錯誤率，數字越低越好，所以 Δ 為負表示變好。

## 摘要：有沒有指標變低

- 7 個表、所有集合與指標加起來，候選比出貨版低的共 77 項，沒有任何一項 p < 0.05。下降的每一項列在[附錄](#7-附錄候選比出貨低的每一項)。
- 開發集的整句全對率有 5 組上升或持平，只有「維基有前文」少 1 段（2／3）。開發集的字準確率沒有一組下降；測試集維基的字準確率低 0.02 個百分點。
- 下降集中在以下幾處。每一處都把同類的集合合起來重做配對檢定，結果都在雜訊內：
  - 善解新聞三組：top-1 改對／改壞 3／6（p = 0.51），前 16 名 2／7（p = 0.18），CER 三組都高 0.05–0.21 個百分點。新聞是正式文體，聊天模型加了口語語料後，這裡可能略差，下次換模型時要再看。
  - 善解對話三組 5／5，ACG 與 IT 六組 10／11，都持平。只看 ACG 近期作品是 0／2，但這組只有 23 列。
  - 按鍵錯誤：口語 15 種條件合計 33／43（p = 0.30），維基合計 25／9（p = 0.009）。各條件用的是同一批 200 段，所以不是獨立樣本；口語被改壞的只有 11 個不同的句子。
  - 注音文 8 列兩邊都是 0%，CER 從 52% 變 61%。
  - 能耗多 6%，每鍵 p95 多 3%，記憶體相同。
- 主要上升的項目：
  - 善解網路用語兩組 top-1 從 42.5% 變 52.3%；
  - 店名、創作者、人名從 43.9% 變 50.2%；
  - 測試集聊天 73.8% → 76.0%（9／0）；
  - 探針的技術詞從 82.0% 變 90.2%，語氣詞從 61.9% 變 66.7%；
  - 改字重播「對」的比例從 7.3% 變 8.7%（46／8），其中沒做過種子的部分是 18／6。
- 模型大小：`lm.bin` 從 7.3 MB 變 19.2 MB。
