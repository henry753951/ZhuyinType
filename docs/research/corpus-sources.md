# 語料與詞庫來源：授權與用途

這份文件整理補「現代用語、網路用語、新詞與技術詞」時被提到的語料與詞庫，逐一寫出內容、授權與我們能怎麼用。它是 [現代用語盤點](slang-inventory.md) 與 [詞庫與讀音資料調查](lexicon-survey.md) §3 的補充。授權判斷是我們依各來源公開的條文整理的，不是法律意見；引入前要再確認現行條款。

查證日期：2026-11-17。

## 判斷原則

ZhuyinType 的詞庫與語言模型以 CC BY-SA 4.0 散布，程式是 AGPL-3.0。一份資料要能進出貨的詞庫或模型，要同時滿足：

1. **授權允許修改與再散布**，而且和 CC BY-SA 4.0 相容：
   - 相容的有 CC0、CC BY、CC BY-SA、MIT、Apache-2.0、政府資料開放授權條款第 1 版、ODC-By；
   - 不能用的有 ND（禁止改作）與 NC（禁止商業使用）。
2. **授權的人有權授權**。整理者把別人的貼文放上 GitHub 並標上 MIT 或 Apache-2.0，不會讓原作者的著作權消失。社群平臺的貼文著作權屬於各發文者，平臺條款通常也禁止自動擷取。
3. **語域與用字合適**：以台灣華語、正體字為主。中國大陸平臺的簡體語料即使授權沒問題，轉成正體後的用詞與語氣也不是台灣的，[lm_chat2 的報告](../../ml/src/zhuyintype_ml/training/lm_chat2/REPORT.md)已經記錄過這個問題。

用途分四級：

| 用途 | 意思 |
|---|---|
| 出貨 | 可以進 App 的詞庫或語言模型（要署名） |
| 統計 | 只用來算詞頻、找新詞或決定參數，不散布原文；能不能這樣用，依授權與平臺條款而定 |
| 評測 | 只在評測時讀取，不訓練、不散布 |
| 不用 | 授權或來源有問題 |

## 使用者提出的來源

| 來源 | 內容 | 授權與條款 | 判斷 |
|---|---|---|---|

| [zake7749/Gossiping-Chinese-Corpus](https://github.com/zake7749/Gossiping-Chinese-Corpus) | PTT 八卦版 2015–2019 年的「標題→推文」問答對，2.0 版 774,114 對 | 儲存庫標 Apache-2.0；但內容是 PTT 使用者的貼文，整理者沒有權利替原作者授權；作者自述噪聲大 | 不用於出貨。語域極口語、偏政治與攻擊性，也不適合當聊天模型的主體 |
| [海大 TOCP 中文不雅文字資料集](https://nlp.cse.ntou.edu.tw/resources/TOCP/) | 16,450 句取自 PTT 與 Twitch 的句子，標出不雅詞的位置與替代說法 | 網頁聲明 CC BY-SA 4.0（Hsu Yang、Chuan-Jie Lin，LREC 2020 TRAC-2）；句子本身仍是平臺使用者的文字 | 評測。可以做「不雅詞與網路用語打不打得出來」的檢查集，署名並保留出處；量小，不夠當訓練語料 |
| [Taiwan-Social-Media-Corpus（GitHub）](https://github.com/Taiwan-Social-Media-Corpus) | 台大 PTT 語料庫的程式：PTT 爬蟲（`async-scraptt` 為 Apache-2.0，`scraptt` 沒有授權）、斷詞轉 TEI XML、語料庫前端 | 只有程式，沒有釋出語料 | 不用。用爬蟲自己建語料，會碰到同樣的著作權與平臺條款問題 |
| [zh-meme-sft-8k（HyperAI 50050）](https://hyper.ai/cn/datasets/50050) | 8,680 段中國網路梗的指令微調對話，取自抖音、小紅書、B 站的評論，再經 LLM 增強 | Hugging Face 標 MIT，README 的徽章寫 Apache-2.0，兩者不一致；原始評論來自禁止擷取的平臺；部分內容是 LLM 改寫 | 不用。授權不清，而且是簡體、中國大陸的語域 |
| [清華 CoAI LCCC（CDial-GPT）](https://coai.cs.tsinghua.edu.cn/tools/6) | 680 萬與 1,200 萬段微博多輪對話，加上其他開源對話集 | 程式為 MIT；README 說明資料用於促進研究，沒有給資料本身開放授權；來源是微博 | 不用。授權不足，而且是簡體、中國大陸的語域 |
| [MNBVC（liwu/MNBVC）](https://huggingface.co/datasets/liwu/MNBVC) | 超大規模的中文語料合集：論壇、問答（知乎）、維基、爬蟲語料等 | Hugging Face 標 MIT，但各子集取自不同來源，原文的著作權各自不同 | 不用。以簡體為主；其中可用的部分（維基百科）我們已經直接從原始來源取得 |

**小結**：這七個來源都不能直接進出貨的模型。要嘛沒有授權，要嘛授權人無權替原作者授權，要嘛是中國大陸的語域。台灣社群平臺的文字（PTT、Dcard、Threads、巴哈姆特）目前沒有任何以開放授權釋出的版本。唯一可以考慮的是 TOCP，而且只當評測集。

## 用語言模型產生或篩選資料

- **篩選與分類：可以用。** 2026-11-17 用 Haiku 5.5 把這台 Mac 改字記錄裡抽出的 1,417 個候選片段分成詞與碎片，留下 44 個。保留的 44 個人工看過，判斷大致合理。模型只做判斷，詞仍來自真實資料，再由語料的次數決定機率。
- **產生語料：效果不好。** lm_chat2 兩次用 Qwen3-8B 產生多輪對話，都沒有通過樣本審查（虛構的設施、前後不一致、格式錯誤）。要產生時，用權重開放、輸出沒有限制的模型（Qwen3-8B，Apache-2.0），並且只當補充、要先審查樣本。

## 從改字記錄看到的缺口

- 2026-11-17 分析這台 Mac 的 2,659 筆改字記錄。腳本先抽出 1,417 個候選：詞庫沒有、在改字處出現至少 2 次的 2–5 字片段，加上記住的字詞。Haiku 判斷後留下 44 個，分類是技術詞 25、軟體與日常詞 10、網路用語 5、人名 4。
- 具體的詞只留在本機，不放進版本庫。
- 和探針的網路用語相比，真實打字的主要缺口是技術、軟體與學術詞。所以新增了技術詞探針（`slang-tech`，61 句，新寫的句子），結果見 [盤點的第 12 類](slang-inventory.md#12-技術軟體與學術詞)。
