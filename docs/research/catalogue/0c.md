## 4. 設計差異

以下說明兩種設計的不同之處。這些差異反映不同的目標與平台（0c 也在 Windows、Linux 與手機上發布），不是排名。

1. **打錯字**：ZhuyinType 有按鍵層級的修正，KeyDecoder `timed` 加上 KeyChannel（在我們自己的合成基準上，混合真實錯誤：38 → 57 %；幾乎同時按下的按鍵：36 → 76.5 %）。0c 公開的文件描述了模糊音處理與近音成語修正，但沒有按鍵層級的打錯模型。
2. **神經模型作用的位置**：ZhuyinType 把 v3 的逐字分數加進 Viterbi，並以 v2b 重排前 16 個結果。0c 以讀音為條件的模型重排引擎前 ≤8 個完整字串。
3. **上下文來源**：ZhuyinType 從 App 讀取最多 128 字（v3 保留 255 字）。0c 只使用自己驗證過的送出內容，最多 64 字，這是較嚴格的隱私設計。
4. **語言模型**：ZhuyinType 使用 chat/百科語言模型混合，權重依上下文調整，另有具兩種半衰期的三層個人 n-gram、刪除重打學習與打錯習慣學習。0c 使用內插 bigram/unigram 引擎加上本機個人詞庫。
5. **記憶體**：ZhuyinType 常駐 29 MB（mmap）。0c 的兩個模型 ≈250 MB，在 Python worker 中執行。
6. **執行環境**：ZhuyinType 在行程內執行 Core ML，並逐鍵報告能耗與記憶體。0c 在行程外的 worker 中執行 ONNX Runtime，可以跨平台運作。
7. **異體字**：ZhuyinType 以 台／臺 偏好評分與輸出。0c 以原文字形評分。

## 5. 可比較性的注意事項

- 對方的主要數字 86 % 是**案例層級**的準確率，案例組成有一半是困難同音短詞，讀音由詞典合成並要求完全相符。我們的 80–87 % 是 400 句測試集上的**整句**準確率。這些數字不能比較。要比較，需要一組共同測試，讓兩個系統在相同條件下重播（方向 1）。
- 對方的外部輸入法基準把 Chewing 與 McBopomofo 的上下文限制在 ≤39−n 個音節，並把無法轉換的讀音算錯。這可能壓低了這些基準在長句段上的分數。
- 對方的延遲數字是在未註明的 CPU 上量測的模型呼叫。我們的是在 Apple M5 上量測的整個按鍵、端到端延遲。
- 標點測試使用參考答案的文字，而不是選字後的文字，且不計句段結尾的標點。

## 6. 這次閱讀帶出的研究方向

每個方向都有具體的產出，以及在執行前就固定的通過標準。標準是我們自己的目標。0c 有公開數字的地方，只作為參考點引用，那些數字是在對方自己的條件下測得。

1. **把 0c 納入為參考系統的共同測試基準。** 從原始碼建置 0c 0.2.6，搭配對應的 HF 模型。以 `0c-cli -replay` 重播；只為量測而建置與執行，不複製任何程式碼。在*收集之前*凍結並雜湊一組前瞻登記的測試集：
   - 台灣新聞，加上 PTT 風格或聊天文本，日期在 2026-10-28 之後；
   - 6,000 個案例（3,000 困難短詞 / 1,500 自然短詞 / 1,500 自然長句段，依對方的 D4–D6 規則建構）；
   - 另加 2,000 個整句。

   為每個系統報告依文件群組與依讀音群組叢集的配對 bootstrap 95 % CI，兩個 seed，並附有害改寫數。**通過：** 所有系統都在同一組凍結測試集上重播；ZhuyinType 案例準確率 ≥ 88 %，且 CI 下界高於我們的 0.4.0 引擎；相對我們引擎的有害改寫 ≤ 案例數的 3.7 %。作為參考，0c 在自己的第 2 次封存測試上報告 86.03/86.13 % 與 220/217 個有害改寫（共 6,000）；新的測試會得到不同的數字。
2. **把引擎分數放進 softmax 的重排模型列表式排序微調**（B15–B17）。資料池來自*我們的* N-best，包含修正與打錯路徑，再加三分之一的文字重播。使用 512–2,000 步，並在獨立的校準切分上以「有害改寫 ≤ 0.9 × 正式版」校準 (w, τ)（C3）。**通過：** 困難同音詞 dev +4 pp，整句 dev +1.5 pp，改寫數 ≤ 0.4.0 的 90 %。
3. **以讀音為條件、詞彙表更大、並做曝光量掃描的句子重排模型**（B4–B6、B13）。輸入為上下文 + 基底／聲調讀音嵌入 + 目標；詞彙表 ≈28 k 字。以接續 + 讀音→文字任務預訓練到 ≥1.2 B 輸出單位，並以 WSD 排程畫出 4 個曝光點。併入或取代 v2b。**通過：** 在我們的困難短詞 dev 上，僅神經模型的困難短詞準確率 ≥ 80 %（0c 在自己的困難短詞 dev 上報告約 77 %）；測試集的詞彙外比率 < 0.05 %。
4. **真實的台灣文本與乾淨的切分**（B7–B10、A5）。取得有授權的 2024–26 年新聞、論壇與聊天文本（目標 ≥1 B 漢字）；對所有評測文件套用 MinHash 5-gram + Jaccard 0.85 的連通分量排除，並以日期切分 holdout。以文件頻率 ≥ 3 重新估計 bigram。**通過：** chat dev 的 perplexity 低於 wiki 模型（ROADMAP #8）；困難短詞 +3 pp；沒有任何評測文件與訓練資料的 Jaccard 達 0.85（獨立稽核）。
5. **詞庫覆蓋率提升與 CI 關卡**（J9、J11–J13、N6）。匯入教育部標準讀音（與 0c 一樣只留在本機），加上學校、醫院、村里與機關的政府開放資料、上市股票名稱與擴充區漢字。在 `make checks` 中加入讀音評測（覆蓋率、可達性、對照教育部簡編本的 top-1）與單字排序關卡。**通過：** 教育部詞彙可達性 ≥ 99.5 %；報告教育部清單的 top-1 比率，並以 0c 在同一份清單上的結果作為參考點；1,000 個台灣專有名詞的測試比我們 0.4.0 詞庫高 ≥ +5 pp。
