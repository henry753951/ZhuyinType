# ZhuyinType 產品與架構設計

ZhuyinType 是開源、在本機運作的 macOS 注音輸入法。

本文件列出完整設計規格；目前提供的功能與後續開發階段見 §7。容錯通道、四層個人記憶與神經選字為後續規劃，效能數值為設計目標。

模型與訓練方式見 [MODEL.md](MODEL.md)。

---

## 1. 設計原則

1. **每個按鍵都即時回應。** 主執行緒處理按鍵與統計結果；模型推論與 I/O 在背景執行。先顯示統計結果，再依時限與請求序號套用神經選字結果。
2. **單一行程。** 輸入法、引擎與模型在同一行程內直接呼叫，讓輸入方式切換快速、可靠。
3. **組字一律顯示在游標處。** 透過 marked text 呈現組字；浮動組字由使用者依應用程式設定。
4. **標準操作優先。** Backspace 逐字刪除、方向鍵移動游標、選字鍵選取候選字；容錯與選字模型沿用這套操作。
5. **集中設定。** 約 15 個核心選項依用途分頁，進階選項集中在「進階」。
6. **本機資料處理。** 輸入與個人詞彙在本機處理、儲存；記住的字詞可檢視、刪除、匯出。Secure Input 啟用時，前文輸入為空、學習處於暫停狀態。更新連線由使用者啟動。

## 2. 功能規格

### 2.1 組字與按鍵

| 按鍵 | 行為 |
|---|---|
| 注音鍵 | 加入組字。整句連續輸入，即時顯示最佳句子 |
| 空白 | 一聲／送出目前音節；組字中再按一次可開候選（可設定） |
| Backspace | 音節未完成時刪除一個注音符號；已成字時刪除游標前一個字及其注音。候選字視窗開啟時先關閉視窗 |
| Option+Backspace | 刪游標前一個詞 |
| ← → | 在組字區內移動游標，可以回頭改中間的字 |
| ↓ 或 空白 | 開啟游標所在位置的候選字視窗：先列照實際按鍵對得上的詞與字（長的在前），按錯修正的放在最後；修正明顯更可能時，每段最多兩個排在前面 |
| Shift-↓ | 只列游標處單一個字、照實際按鍵對得上的字；視窗開著時切換兩種清單 |
| 1–9（或 asdfghjkl，可設定） | 直接選字 |
| Tab | 接受目前的補全建議；一般狀態交由應用程式處理，候選字視窗開啟時換頁 |
| Enter | 送出整段；候選字視窗開啟時選取目前候選字 |
| Esc | 依目前狀態關閉候選字視窗、清除目前注音或清空組字（可設定） |
| Shift + 符號鍵 | 中文標點：，。？：！「」『』… |
| Option + 數字或符號鍵 | 鍵上印的符號原樣輸入：Option-. 是「.」，Option-Shift-. 是「>」 |
| Shift（單按） | 中英切換（左／右／兩側可設定） |
| Caps Lock | 英文大寫模式，或依系統設定切換輸入法 |

**按鍵預設組（規劃）**：提供兩組空白鍵、Shift 與選字鍵設定，使用者可複製後自訂。

### 2.2 容錯輸入
- 自動處理按到相鄰鍵、漏按、多按、兩鍵順序打反、忘了打聲調。
- 精確符合按鍵的候選優先；修正後的整句要比最好的未修正整句多 2.0 分，才成為首選（[MODEL.md §2.4](MODEL.md#24-打對的鍵優先)）。
- 候選字視窗會用小標記標出「這是修正後的結果」，讓使用者知道為什麼出現這個字。修正的候選排在照實際按鍵對得上的候選之後，除非比它們都明顯更可能（多 2.0 分，每段最多兩個）。
- 「容錯強度」設定：關／標準／積極。

### 2.3 選字
- 統計語言模型先產生候選句，神經網路再參考游標前的文字（最多 64 字）重新排序。
- 神經選字的融合分數超過統計首選指定門檻時，才更新首選；門檻依開發集校準。
- 支援模糊音（ㄗ／ㄓ、ㄘ／ㄔ、ㄙ／ㄕ、ㄣ／ㄥ、ㄢ／ㄤ，可逐項開關）。同樣常用時完全符合的排前面，另一個詞明顯更常用時才換上。
- 「一」「不」打變調後的讀音也能找到（一直 ㄧˋ ㄓˊ、不要 ㄅㄨˊ ㄧㄠˋ）；罕用讀音的分數較低（「說」打 ㄕㄨㄟˋ 時，「睡」優先）。
- 一段組字送出後，下一段接著前面送出的詞選字；按了送給 App 的鍵、點進文字、切換輸入框或標點之後，才重新當作句首。

### 2.4 個人記憶
| 層 | 做什麼 | 什麼時候學 |
|---|---|---|
| 精確回想 | 用「你實際按的鍵」與「正確的鍵」兩把 key 記住送出的結果。下次打一樣的鍵（包括同樣的錯），直接給你上次的答案 | 每次送出 |
| 讀音融合 | 兩個字以上的詞用讀音記住寫法（人名、術語）。候選句裡只要出現同樣的讀音，就換成你的寫法 | 每次送出 |
| 語境偏好 | 記住「什麼詞後面你常接什麼」，用來調整排序 | 手動選字權重高、直接送出權重低 |
| 負面記憶 | 送出後 30 秒內刪掉再打成別的字，或選字時換掉某個候選，就降低它在原本前文的排名 | 送出後的短時間內 |

- 長期保留：分數以約 90 天的半衰期衰減，手動確認過兩次以上的詞設有最低保留分數。
- 容量約 20,000 筆，滿了就先刪分數最低的。
- 設定頁「記住的字詞」：搜尋、移除、不再記住、匯出／匯入、暫停學習。

### 2.5 其他
- 中英混打：依按鍵序列辨識英文並保留原文（可關閉）。
- 自訂詞：在設定頁或候選字視窗（右鍵或快捷鍵）加入，加入後馬上生效。
- 全形標點、符號表（`` ` `` 開啟）、Emoji 選單（可關閉）。
- 繁簡輸出切換。
- 產品範圍：注音輸入、本機詞彙管理與本機選字模型。

## 3. 系統架構

```
┌──────────────────────── ZhuyinType.app（單一行程）────────────────────────┐
│                                                                           │
│  IMK 層（Swift）                                                          │
│   ZhuyinInputController ── KeyInput ──┐                                   │
│   ControllerCore ← Presentation ─────┤  主執行緒：只做輕量運算            │
│   CandidatePanel（AppKit + SwiftUI）  │                                   │
│                                       ▼                                   │
│  ZhuyinCore（純 Swift 核心，可獨立執行命令列檢查）                       │
│   KeyboardLayout ─► KeyChannel ─► Lattice ─► NGramLM ─► N-best            │
│        （排列）     （容錯）     （詞圖）   （統計）                     │
│                                              │                            │
│   PersonalMemory ◄────────── 套用 ◄──────────┤                            │
│                                              ▼                            │
│  神經選字層（規劃：Core ML，背景 actor）                                  │
│   Reranker：前文 + 讀音 + 候選 → 分數，時限 40 ms，逾時用統計結果         │
│                                                                           │
│  SettingsWindow（SwiftUI）  ·  Updater（使用者確認後才下載）              │
└───────────────────────────────────────────────────────────────────────────┘
```

### 3.1 狀態機
`Composer` 管理組字狀態，接收 `KeyInput` 後回傳 `KeyResult`，並更新 `Presentation`。IMK 層依結果設定 marked text、送出文字與顯示候選字視窗；後續神經選字層依狀態發出重排請求。
- 按鍵行為透過純核心命令列檢查驗證。
- 神經網路結果帶有請求序號；只有與目前組字狀態相符的結果會套用。

### 3.2 完整模型的逐鍵流程（規劃）
1. 按鍵 → 依鍵盤排列轉成注音符號（目前提供標準排列，倚天與許氏為後續規劃）。
2. **KeyChannel**：對新出現的按鍵片段（1–6 鍵），算出每個合法音節的通道成本，最多容許 2 處修改（片段 5 鍵以上可到 3 處）。結果依片段快取，所以每鍵只需要算新增的部分。
3. **Lattice**：把「音節假設 + 通道成本」和詞庫比對，建成詞圖。
4. **NGramLM**：在詞圖上用 Viterbi 與 k-best 取前 16 句。分數 = 詞頻 + 雙詞機率 + 通道成本 × λ。
5. 套用個人記憶（精確回想、融合、語境偏好）→ **立即顯示**。
6. 背景請求 Reranker 重新排序；在時限內回來，而且首選有變，才更新畫面。

### 3.3 文字客戶端整合
- 透過 `setMarkedText` 傳遞組字，僅在文字、游標或子句標記改變時更新。網頁引擎型應用程式也採相同流程。
- `flagsChanged` 依實體按鍵狀態與已記錄的 Shift 狀態判斷單按；相同狀態的事件合併處理。
- 候選字視窗位置：依序採用 `firstRect(forCharacterRange:)`、行高矩形、上一次有效位置。
- 浮動組字以應用程式 bundle ID 儲存，使用者可在「進階」檢視與修改。

### 3.4 資料與檔案

目前詞庫為 TSV，個人詞彙儲存於本機資料檔；完整模型的儲存格式規劃如下。
| 內容 | 位置 | 格式 |
|---|---|---|
| 系統詞庫、n-gram | App bundle | 自訂 mmap 二進位格式（建置時從 TSV 編譯） |
| 神經網路模型 | App bundle | `.mlpackage`（int8） |
| 個人記憶 | `~/Library/Application Support/ZhuyinType/` | SQLite（WAL），寫入在背景執行 |
| 設定 | UserDefaults | 只存核心選項 |

### 3.5 更新
- 檢查更新只在使用者開啟此選項或手動按「檢查更新」時進行。
- 新版安裝後，在切換輸入方式或重新登入時載入；更新提示說明生效時機。

## 4. UI

整體採用 macOS 26 之後的系統設計語言；以 macOS 27 SDK 建置並標記實際 SDK 版本，系統會以目前的樣式繪製所有標準控制項。

- **候選字視窗**：NSPanel，背景在 macOS 26 以上為 Liquid Glass（`NSGlassEffectView`），較舊系統為 popover 材質。直式或橫式、字級可調，選取列為強調色圓角矩形。修正過的候選以小圓點標示；個人記憶來的候選以細微圖示標示（規劃中）。
- **狀態提示**：中英切換時在游標旁以同樣的玻璃材質顯示「中」或「英」0.8 秒。
- **App 圖示**：Icon Composer 格式（`Resources/AppIcon.icon`），藍色背景加上一層玻璃材質的「ㄓ」字形（取自 PingFang TC），由系統渲染淺色、深色與透明外觀；`scripts/make_icons.swift` 產生並以 actool 編譯。
- **選單列圖示**：實心圓角方塊鏤空「ㄓ」，為 template 影像。
- **設定視窗**：與系統設定相同的版面——左側原生 source list 側欄（彩色圖示），右側為 SwiftUI 分組表單。
  1. 一般：空白鍵、Esc、中英切換鍵、切換提示、開始時的語言。
  2. 候選字視窗：排列、字級、選字鍵，以及使用真實候選字視窗元件的預覽。
  3. 自訂詞：清單、加入、移除；工具列提供搜尋。
  4. 記住的字詞：開關、清單（依次數排序）、移除與全部清除；工具列提供搜尋。
  5. 進階：以浮動視窗顯示組字的 App、回復預設設定。
  6. 關於：版本、授權、資料來源。
- **清單**：NSTableView（列重複使用，大量資料也流暢），版面比照系統設定的分組清單：主要文字在前、次要值在後、列間內縮分隔線；底部為 ＋／－，支援多選與 Delete 鍵。

## 6. 授權

- 程式碼：AGPL-3.0-only。
- 詞庫：只使用允許再散布的開放資料，每個來源記錄在 `data/SOURCES.md`（網址、版本、授權、署名）。
- 模型權重：只用授權允許再散布的語料訓練，跟權重一起附上資料清單；詳見 [MODEL.md](MODEL.md)。

## 7. 開發階段

| 階段 | 內容 | 完成標準 |
|---|---|---|
| **P0 基本輸入** | IMK App、標準注音、整句轉換、候選字視窗、基本詞庫、自訂詞、記住選字、設定視窗、pkg 安裝 | 核心按鍵與詞彙檢查、文字客戶端整合及安裝流程驗證 |
| **P1 統計選字** | 詞圖 + bigram Viterbi + k-best、模糊音 | 建立首選正確率評測基準 |
| **P2 容錯** | KeyChannel、通道權重估計、修正標記、容錯強度設定 | 模擬 10%／20% 按錯時，第一頁正確率達到目標 |
| **P3 個人記憶** | 四層記憶、記住的字詞進階管理、隱私開關 | 記憶模擬評測：同一句第二次輸入時首選正確率提升 |
| **P4 神經選字** | 訓練 Reranker、Core ML 匯出、背景排程與時限 | M1 上每鍵 P95 < 40 ms，首選錯誤率比 P1 明顯下降 |
| **P5 打磨** | 中英混打、Emoji、繁簡、更新機制、文件 | 公開 beta |

目前完成 P0 到 P4，P5 尚未開始。P4 的選字模型在 CPU 上同步執行，每次 2–11 ms，所以不另外排程到背景；成績見 [MODEL.md §4](MODEL.md#4-神經選字模型reranker)。
