# ZhuyinType 產品與架構設計

ZhuyinType 是一個 macOS 原生的注音輸入法，完全開源、免費、在本機運作。

目標只有一句話：**按錯也打得對、少選字、記得住你、而且操作跟你習慣的一樣。**

模型與訓練方式見 [MODEL.md](MODEL.md)。

---

## 1. 設計原則

1. **打字永遠不卡。** 主執行緒不等待任何模型或 I/O。神經網路沒在時限內算完，就先用統計結果，算完再悄悄更新候選。
2. **單一行程。** 輸入法、引擎、模型都在同一個行程，不靠 IPC 或子行程。行程越少，「切不過來」「按鍵變英文」這類故障就越少。
3. **組字一律顯示在游標處（inline）。** 包括 Electron、Chromium 類 App。不會預設改用浮動視窗；只有確認某個 App 真的不支援時，才讓使用者對那個 App 手動開啟浮動模式。
4. **標準操作優先。** Backspace、方向鍵、數字鍵選字的行為，跟大家用慣的注音輸入法一致。聰明的功能只能「加在上面」，不能改掉基本操作。
5. **少而精的設定。** 預設值就要好用；設定頁約 15 個核心選項，進階選項收在一頁。
6. **隱私。** 不連網（除了使用者主動檢查更新）。學習資料只存在本機，可以檢視、刪除、匯出。遇到密碼欄（Secure Input）就不讀前文、不學習。

## 2. 功能規格

### 2.1 組字與按鍵

| 按鍵 | 行為 |
|---|---|
| 注音鍵 | 加入組字。整句連續輸入，即時顯示最佳句子 |
| 空白 | 一聲／送出目前音節；組字中再按一次可開候選（可設定） |
| Backspace | 音節還沒打完：刪**一個注音符號**。音節已成字：刪游標前**一個字**（連同它的注音）。**絕不一次清空整段** |
| Option+Backspace | 刪游標前一個詞 |
| ← → | 在組字區內移動游標，可以回頭改中間的字 |
| ↓ 或 空白 | 開啟游標所在位置的候選窗 |
| 1–9（或 asdf…，可設定） | 直接選字 |
| Tab | 有補全建議時接受補全；沒有時交還 App |
| Enter | 送出整段 |
| Esc | 關閉候選窗；再按一次清空組字 |
| Shift（單按） | 中英切換（左／右／兩側可設定）；切換時保留已組好的字 |
| Caps Lock | 英文大寫模式，或依系統設定切換輸入法 |

**按鍵風格預設組**：提供「Windows 注音習慣」與「macOS 注音習慣」兩組。差別在空白鍵選字、Shift 行為、選字鍵等；使用者可以複製一組再自訂。

### 2.2 容錯輸入
- 自動處理按到相鄰鍵、漏按、多按、兩鍵順序打反、忘了打聲調。
- 打錯的結果**不會蓋掉**正確打出來的結果。只有在完全沒按錯的解讀明顯不通順時，修正版才會排到第一名。
- 候選窗會用小標記標出「這是修正後的結果」，讓使用者知道為什麼出現這個字。
- 「容錯強度」設定：關／標準／積極。

### 2.3 選字
- 統計語言模型先產生候選句，神經網路再參考游標前的文字（最多 64 字）重新排序。
- 只有在神經網路的分數「明顯更好」時，才覆蓋統計引擎的首選，避免亂改。
- 支援模糊音（ㄗ/ㄓ、ㄘ/ㄔ、ㄙ/ㄕ、ㄣ/ㄥ、ㄢ/ㄤ，可逐項開關），模糊音結果一律排在後面。

### 2.4 個人記憶
| 層 | 做什麼 | 什麼時候學 |
|---|---|---|
| 精確回想 | 用「你實際按的鍵」與「正確的鍵」兩把 key 記住送出的結果。下次打一樣的鍵（包括同樣的錯），直接給你上次的答案 | 每次送出 |
| 讀音融合 | 兩個字以上的詞用讀音記住寫法（人名、術語）。候選句裡只要出現同樣的讀音，就換成你的寫法 | 每次送出 |
| 語境偏好 | 記住「什麼詞後面你常接什麼」，用來調整排序 | 手動選字權重高、直接送出權重低 |
| 負面記憶 | 送出後立刻刪掉，或選字時跳過某個候選，就降低它下次的排名 | 送出後的短時間內 |

- 長期保留：用很長的半衰期（約 90 天）慢慢衰減。手動確認過兩次以上的詞，有不會消失的下限。
- 容量約 20,000 筆，滿了就先刪分數最低的。
- 設定頁「學到的詞」：搜尋、移除、設為「不再學」、匯出／匯入、暫停學習。

### 2.5 其他
- 中英混打：打出不是注音的英文字串時自動保留英文（可關閉）。
- 自訂詞：在設定頁或候選窗（右鍵或快捷鍵）加入，加入後馬上生效。
- 全形標點、符號表（`` ` `` 開啟）、Emoji 選單（可關閉）。
- 繁簡輸出切換。
- 不做的事：拼音、雙拼、其他輸入方式、雲端同步、遙測。

## 3. 系統架構

```
┌──────────────────────── ZhuyinType.app（單一行程）────────────────────────┐
│                                                                           │
│  IMK 層（Swift）                                                          │
│   InputController ── 按鍵 → KeyEvent ─┐                                   │
│   CompositionPresenter ← 狀態 ────────┤  主執行緒：只做輕量運算            │
│   CandidatePanel（AppKit + SwiftUI）  │                                   │
│                                       ▼                                   │
│  ZhuyinCore（純 Swift 套件，不依賴 AppKit，可在 Linux 上跑單元測試）      │
│   KeyboardLayout ─► KeyChannel ─► Lattice ─► NGramLM ─► N-best            │
│        （排列）     （容錯）     （詞圖）   （統計）                     │
│                                              │                            │
│   PersonalMemory ◄────────── 套用 ◄──────────┤                            │
│                                              ▼                            │
│  ZhuyinML（Core ML，背景 actor）                                          │
│   Reranker：前文 + 讀音 + 候選 → 分數，時限 40 ms，逾時用統計結果         │
│                                                                           │
│  SettingsWindow（SwiftUI）  ·  Updater（使用者確認後才下載）              │
└───────────────────────────────────────────────────────────────────────────┘
```

### 3.1 狀態機
`Composer` 是值型別：`(狀態, 事件) → (新狀態, 副作用)`。副作用包括設定 marked text、送出文字、顯示候選窗、送出重排請求。
- 所有按鍵行為都能用純單元測試覆蓋，不需要啟動 App。
- 神經網路的結果以「請求序號」回傳；序號過期就丟掉，不會蓋到使用者新打的內容。

### 3.2 每一鍵的流程
1. 按鍵 → 依鍵盤排列轉成注音符號（支援標準、倚天、許氏等排列，先做標準）。
2. **KeyChannel**：對新出現的按鍵片段（1–6 鍵），算出每個合法音節的通道成本，最多容許 2 處修改（片段 5 鍵以上可到 3 處）。結果依片段快取，所以每鍵只需要算新增的部分。
3. **Lattice**：把「音節假設 + 通道成本」和詞庫比對，建成詞圖。
4. **NGramLM**：在詞圖上用 Viterbi 與 k-best 取前 16 句。分數 = 詞頻 + 雙詞機率 + 通道成本 × λ。
5. 套用個人記憶（精確回想、融合、語境偏好）→ **立即顯示**。
6. 背景請求 Reranker 重新排序；在時限內回來，而且首選有變，才更新畫面。

### 3.3 Electron／Chromium 相容
- 一律使用 `setMarkedText`。內容相同時不重送，避免 Chromium 閃爍或游標跳動。
- 過濾 Chromium 重複送出的 flagsChanged（判斷 Shift 單按時，比對按鍵實際狀態）。
- 候選窗位置：優先用 `firstRect(forCharacterRange:)`，結果無效時改用行高矩形，再不行就沿用上一次的有效位置。
- App 相容表只放「已確認需要特殊處理」的項目，而且使用者可以在設定頁看到、修改。

### 3.4 資料與檔案
| 內容 | 位置 | 格式 |
|---|---|---|
| 系統詞庫、n-gram | App bundle | 自訂 mmap 二進位格式（建置時從 TSV 編譯） |
| 神經網路模型 | App bundle | `.mlpackage`（int8） |
| 個人記憶 | `~/Library/Application Support/ZhuyinType/` | SQLite（WAL），寫入在背景執行 |
| 設定 | UserDefaults | 只存核心選項 |

### 3.5 更新
- 檢查更新只在使用者開啟此選項或手動按「檢查更新」時進行。
- 新版裝好後提示「切換輸入法或重新登入後生效」。**不在打字中途熱抽換程式。**

## 4. UI

- **候選窗**：原生 NSPanel，跟隨系統深色／淺色模式與強調色。支援直式與橫式；字級可調。修正過的候選以小圓點標示；個人記憶來的候選以細微圖示標示。
- **狀態提示**：中英切換時在游標旁顯示「中／英」0.8 秒。
- **設定視窗（SwiftUI）**：
  1. 一般：按鍵風格、中英切換鍵、選字鍵、候選窗樣式
  2. 輸入：容錯強度、模糊音、中英混打、標點
  3. 詞彙：自訂詞、學到的詞（搜尋、移除、不再學、匯出入）、暫停學習
  4. 進階：App 相容表、神經選字開關與狀態、重設
  5. 關於：版本、授權、資料來源

```
└── docs/
```

## 6. 授權

- 程式碼：AGPL-3.0-only。
- 詞庫：只使用允許再散布的開放資料，每個來源記錄在 `data/SOURCES.md`（網址、版本、授權、署名）。
- 模型權重：只用授權允許再散布的語料訓練，跟權重一起附上資料清單；詳見 [MODEL.md](MODEL.md)。

## 7. 開發階段

| 階段 | 內容 | 完成標準 |
|---|---|---|
| **P0 骨架** | IMK App、Composer 狀態機、inline 組字、標準按鍵、原生候選窗、基本詞庫 + unigram、pkg 安裝 | 在 TextEdit、Safari、VS Code、Slack、Discord 正常打字與選字 |
| **P1 統計選字** | 詞圖 + bigram Viterbi + k-best、自訂詞、模糊音、設定視窗 | 首選正確率評測基準建立 |
| **P2 容錯** | KeyChannel、通道權重估計、修正標記、容錯強度設定 | 模擬 10%／20% 按錯時，第一頁正確率達到目標 |
| **P3 個人記憶** | 四層記憶、學到的詞頁面、隱私開關 | 記憶模擬評測：同一句第二次輸入時首選正確率顯著提升 |
| **P4 神經選字** | 訓練 Reranker、Core ML 匯出、背景排程與時限 | M1 上每鍵 P95 < 40 ms，首選錯誤率比 P1 明顯下降 |
| **P5 打磨** | 中英混打、Emoji、繁簡、更新機制、文件 | 公開 beta |
