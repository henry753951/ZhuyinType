# Qt 介面移植

2026-10-29：以主線 `d27cf74d`（0.4.7、AGPL-3.0-only）為基準。Linux 與 Windows 共用 `platforms/qt/`，macOS 維持 Swift 原生介面。原生 Fcitx5／TSF 透過同一個 Qt 服務操作引擎、設定、快捷鍵與候選字視窗，已有開發用建置與部署流程；正式發行套件尚未完成。介面外觀修正已交由另一項工作接續，以下畫面狀態不代表最終視覺驗收。

## 視覺與架構

保留原版資訊層級、側欄順序與控制項種類；字級用拉桿、互斥的少量選項用分段控制、布林值用開關。視覺不模仿 macOS 或其他平台：中性灰底、一個取自 App 圖示的靛藍強調色、單色線條圖示，所有控制項由共用元件組成。App 圖示直接共用 macOS 資產。元件、token 與自動檢查的規則見 [設計系統](../../platforms/qt/DESIGN_SYSTEM.md)。

QML 只負責畫面；設定驗證及儲存由 `Settings` 負責，候選選取及翻頁狀態由 `Candidates` 負責。儲存物件由入口注入，頁面透過訊號請求導覽。頁面註冊在 `Pages.js`，各頁共用控制項，不在各平台複製一份。正式輸入法接入時沿用 Rust C ABI，Fcitx／TSF 分別處理系統焦點、按鍵與文字送出。

## 窄視窗與動畫

視窗最小寬度為 640 px。窄寬度使用較小的側欄與內容邊距，設定列的文字與控制項改為上下排列，長說明換行；側欄在低高度可捲動。視窗與提示頁依可用寬度將五種情境重新排列，不縮放整張畫面。

翻頁使用與 macOS 相同的 140 ms、10 px 淡入位移；頁面切換、開關、說明展開與對話框各有短轉場。動畫遵循預覽的動畫設定。候選字預覽取得鍵盤焦點後可用方向鍵、選字鍵、Return、Page Up／Down 及切換清單按鍵操作；浮動輸入法視窗仍不取得焦點。

## 驗證與下一階段

`tools/zt check desktop` 包含 Qt Quick 的鍵盤／排版互動測試，並檢查設定驗證、持久化、回復預設與候選索引邊界，並產生十九頁在 900／640 px 寬度下的深淺色截圖，另加橫式候選情境，共 80 張。渲染遇到 QML 警告會失敗。macOS 上的 Qt 預覽只用來核對共用程式與畫面，不能代替 Linux／Windows 的桌面驗證。

2026-10-29：前一輪介面快照在 macOS Qt 6.12.0、Ubuntu 26.04 Qt 6.10.2 與 Windows Server 2025 Qt 6.10.2／MSVC 2022 通過 8 組檢查，包含 80 張渲染。加入原生通訊測試後，Linux 的整合快照通過共用 Qt 9 組與原生 4 組測試；Mac 最新功能測試 6 組通過。Windows 已部署 Qt runtime 並在 RDP 桌面實測原生輸入。11:40 介面快照的 Windows 狀態測試與渲染通過，但 `desktop-interactions` 在字詞頁達到 60 秒上限，留給介面工作處理；不能將更早的通過結果當成持續修改中介面的完整驗收。Wayland 定位、神經模型回呼與正式發行套件尚未完成。

Linux 原生前端現位於 `platforms/linux/`，透過 Unix socket 接入共用 Qt 服務；addon 不載入 Rust 或 Qt。已在 Xfce／X11 的實際使用者 profile 部署，驗證文字送達、共用候選視窗與游標定位、滑鼠選字、安全欄位、斷線保留已確認組字，以及同一個 Qt 服務內的設定搜尋欄位輸入。完整環境、測試與未驗證範圍見 [Linux 驗證紀錄](../../platforms/linux/VALIDATION.md)。

Windows x64 的 TSF 已在測試 VM 登記，通過 Windows 實際分派按鍵到 EDIT／RichEdit、Qt 候選窗定位與滑鼠選字、安全欄位、不可用服務，以及同 GUI 執行緒的隔離 Qt 輸入欄位測試。開發安裝、移除與重裝保留既有語言及其他輸入法；已設定登入啟動。完整 Main 設定頁、第三方應用程式、32 位元程式與實體混合 DPI 桌面尚未驗證，詳見 [Windows 驗證紀錄](../../platforms/windows/VALIDATION.md)。
