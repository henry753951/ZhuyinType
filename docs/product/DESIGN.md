# ZhuyinType 產品設計

ZhuyinType 是開源、在本機運作的 macOS 注音輸入法。

本文件寫使用者看得到的部分：按鍵、狀態、預設值與介面。程式內部的流程見 [ARCHITECTURE.md](../engine/ARCHITECTURE.md)，演算法與模型見 [MODEL.md](../engine/MODEL.md)，尚未完成的項目見 [ROADMAP.md](../ROADMAP.md)。

## 1. 設計原則

1. 每個按鍵都即時回應。按鍵處理、整句轉換與模型推論都在主執行緒同步完成。模型只用 CPU，每次數毫秒。畫面一次更新到最終結果，個人資料在背景寫入。
2. 單一行程。輸入法、引擎與模型在同一個行程內直接呼叫，切換輸入方式快速而可靠。
3. 組字顯示在游標處。組字以 marked text 顯示；使用者可以指定個別 App 改在候選字視窗上方顯示組字。
4. 標準操作優先。Backspace 刪除游標前的一個字，方向鍵移動游標，選字鍵選取候選字。容錯與選字模型都沿用這套操作。
5. 設定集中。約 15 個選項依用途分頁，少用的選項放在「進階」。
6. 資料留在本機。輸入的文字與個人詞彙都在本機處理與儲存，記住的字詞可以檢視、移除、匯出與匯入。App 自己的網路連線只有檢查與下載更新，每天檢查一次，可以關閉。沒有遙測，也沒有自動上傳：更新內容隨 App 附上，意見與問題由使用者在瀏覽器開啟 GitHub 的頁面、看過內容後自己送出（§4.5.2）。系統開啟安全輸入時（例如密碼欄位），輸入法不讀取游標前的文字，也不學習。「記錄改字」預設關閉，開啟後記錄也只存在這台 Mac（§2.7）。

## 2. 功能規格

### 2.1 組字與按鍵

按鍵依使用頻率分成四組，越常用的越靠近打字的手。設定視窗的「快捷鍵」頁依目前的設定列出同一份表。

#### 按鍵的原則

1. **打字的鍵固定，指令的鍵可以改。** 注音鍵、聲調、空白、Return、⌫、Esc 與方向鍵的意思不變；其他功能是「指令」，各有預設按鍵，可以在功能旁或「快捷鍵」總覽改（§「自訂按鍵」）。
2. **方向鍵只有一條規則**：上下在清單裡移動，左右沿著句子移動。加 ⇧ 是同一個方向的另一種做法：⇧↓「只列一個字」、⇧↑「列出修正的字」、⇧← ⇧→ 選取字（再按 Return 加入自訂詞）。直式清單的 ← → 改前一個或後一個字；橫式清單的 ← → 移動反白，所以改字另用一組鍵。
3. **修飾鍵照系統的文字編輯習慣。** macOS 用 ⌥ 一次移動或刪除一個詞（⌥← ⌥→ ⌥⌫），Linux 與 Windows 用 Ctrl（Ctrl+← Ctrl+→ Ctrl+⌫），所以改前一個字、改後一個字、刪掉一個詞與第三組翻頁鍵在 macOS 是 ⌥，在 Linux／Windows 是 Ctrl。Linux／Windows 的預設都不用 Alt：Windows 的 App 看到 Alt 放開會顯示選單的按鍵提示並取走焦點（例如記事本），Alt+空白 在 Windows、GNOME 與 KDE 是視窗選單。
4. **⌃（Ctrl）加 Return 或刪除鍵，是對候選字視窗中反白字詞的動作**：加入自訂詞、不要再推薦、忘記這個選字，5 秒內按 ⌃Z 復原。這三個只在清單開著時作用；要把打的字加入自訂詞，用 ⇧← ⇧→ 選取。
5. **一件事一種按法。** 只有翻頁同時有幾個預設按鍵（Tab、Page Down、⌥↓），因為各家輸入法的習慣不同；其他功能一個預設按鍵，需要的話自己加。
6. **顯示按鍵的地方都讀同一張按鍵表。** 候選字視窗的開關與提示、設定頁的說明、ⓘ 示範、「快捷鍵」總覽、介紹與設定嚮導都顯示目前指定的按鍵；改了按鍵立即更新，功能關閉時不顯示它的鍵。

Linux／Windows 的寫法：⌃ 寫成 Ctrl、⌥ 寫成 Alt、Return 寫成 Enter（鍵盤上印的字），⌃⌫ ⌃⇧⌫ 改用 Ctrl+Del Ctrl+⇧Del（Ctrl+⌫ 是刪掉一個詞）。下面的表寫 macOS 的鍵，Linux／Windows 不同的寫在括號中。

按鍵依美式鍵盤上的位置判斷。使用 ZhuyinType 時，鍵盤配置固定為 ABC。

#### 狀態

| 狀態 | 說明 |
|---|---|
| 英文 | 所有按鍵交給 App。單按 Shift 切回中文。從其他輸入法切換到 ZhuyinType 時，一律從中文開始（「開始輸入時使用英文」開啟時從英文開始）；只是換 App 或輸入框時，維持目前的中英模式。 |
| 中文，沒有組字 | 打注音、標點、⇧ 加字母或符號鍵、⌃ 加符號鍵或 ⌥ 加數字或符號鍵時開始組字，其他按鍵交給 App。 |
| 組字中 | 組字顯示在游標處，畫面即時顯示最佳整句。按 Return 送出。 |
| 候選字清單開著 | 由 ↓ 開啟；「空白鍵」設為「開啟候選字視窗」時空白也可以。選字後回到組字中。 |
| 選取中 | 由 ⇧← 或 ⇧→ 開始。候選字視窗顯示「↩ 加入自訂詞：」與選取的字，按 Return 加入自訂詞，按 Esc 取消選取。 |

候選字清單另有兩種，預設都不開，都用 Shift 加上下鍵切換：⇧↓「單字」只列一個字，⇧↑「修正」把按錯修正與模糊音的字排在前面。這兩種清單用 Shift 而不用 Option，因為很多 App 把 Option 組合鍵當成自己的快捷鍵，有的 App 會先於輸入法處理；Option（Linux／Windows：Ctrl）只用在另有其他按法的地方（翻頁的第三組鍵、橫式清單的改字）。候選字視窗下方顯示這兩個開關與它們的按鍵，開著時以強調色顯示，也可以直接點；關閉「單字與修正按鈕」後，開關只在開著時顯示。

| ← → | 在組字中移動游標。 |
| Home、End | 游標移到組字的開頭或結尾。 |

| 按鍵 | 行為 |
|---|---|
| ⇧↓ | 只列一個字。清單開著時切換。 |
| ⇧↑ | 列出按錯修正與模糊音的字，排在前面，用一般的方向鍵瀏覽；再按一次還原。點候選字視窗的「⇧↑ 修正」也一樣。「按錯鍵修正」為「關閉」、「按鍵順序」不是「只列出」，且沒有開啟任何模糊音時，這個鍵開啟一般清單，清單開著時不作用。 |

#### 符號與 Emoji

按 ⌃⌥,（Linux／Windows：Ctrl+Shift+/；可以在「標點與符號」頁更改或關閉）開啟符號與 Emoji 面板。面板在游標旁，App 保有鍵盤焦點，按鍵由輸入法交給面板。有組字時，組字目前顯示的文字（例如「笑」）成為搜尋的內容，組字從 App 中取消、不送出；面板開著時按的第一個鍵取代它，⌫ 清除它，Esc 不會恢復組字。

面板開啟時按鍵在搜尋列，打字的鍵一個也不拿走：所有字母、數字與符號鍵都打進搜尋，數字也一樣（中文模式是注音，ㄅㄉˇˋㄓˊ˙ㄚㄞㄢ 都在數字鍵上；英文模式是數字本身）。這時格子不標按鍵。按 ↓ 進入格子，反白那一列才標出 1–9，這時數字選取。規則和聯想詞相同：標在符號前的鍵才選取那個符號，其他打字的鍵不被拿走。

| 按鍵 | 搜尋列（開啟時） | 格子（按 ↓ 之後） |
|---|---|---|
| 字母、數字、符號鍵 | 打進搜尋：中文模式依標準注音鍵盤讀成注音（聲調可省略），也當作英文；英文模式照原樣 | 1–9：送出反白那一列的第幾個；其他鍵（含 0）回到搜尋列並打進搜尋 |
| ↓ | 進入格子（沒有符號時不動） | 往下一列 |
| ↑ | — | 往上一列；在第一列時回到搜尋列 |
| ← → | — | 移動反白；在一列的頭尾接到上一列或下一列 |
| Page Up、Page Down | Page Down 進入格子並往下一頁 | 移動一頁（六列） |
| 空白 | 有搜尋時打進搜尋（一聲或音節結束） | 送出反白的符號 |
| Return | 送出反白的符號（搜尋時是第一個結果） | 送出反白的符號 |
| Tab、⇧Tab | 下一個、上一個類別；正在搜尋時，回到類別 | 同左 |
| ⌫ | 刪掉搜尋的最後一個鍵 | 回到搜尋列並刪掉最後一個鍵 |
| Esc；再按一次開啟面板的鍵 | 關閉面板 | 關閉面板 |
| ⌘、⌃、⌥ 組合 | 關閉面板，按鍵交給 App（Linux／Windows：不做事） | 同左 |

面板下方寫出目前狀態的按鍵：搜尋列時「↓ 選取」，格子時「1–9 選取」，再加上 Esc 關閉（macOS 另寫 Tab 類別）。

點一下符號即送出，點類別切換類別，滑鼠滾輪捲動。送出的符號經由一般的送出流程進入 App（如同選了一個候選字，之後從句首選字），加入「最近使用」，面板關閉。

類別依序為：最近使用（沒有時不顯示）、常用標點、括號、數學、箭頭、單位、注音符號、希臘字母、框線，以及 Unicode 的 Emoji 分組：笑臉與情緒、人物、動物與自然、食物與飲料、旅遊與地點、活動、物品、符號、旗幟。

「最近使用」存在這台 Mac 的 `recent-symbols.txt`，最多 32 個，最新的在前；密碼欄位中送出的符號不記錄。「回復預設設定」與「記住的字詞 › 全部清除」會刪除它。記錄中不出現送出的符號。

搜尋的內容是在面板中按的鍵，引擎（`engine/crates/zhuyin-symbols`）同時把它讀成標準鍵盤的注音與英文：注音比對 CLDR 正體中文關鍵字的讀音（取自詞庫，聲調可省略，最後一個音節可以只打一部分，也比對關鍵字中間的音節，例如 ㄒㄧㄠ 找到「大笑」的 😂），英文比對 CLDR 的英文關鍵字；從組字帶入的中文直接比對中文名稱與關鍵字。排序：名稱完全相同、關鍵字完全相同、開頭相同、包含，同分時依類別順序。注音的 ㄅㄉㄓㄚㄞㄢ 與聲調在數字鍵上，在搜尋列一樣打進搜尋（例如 9 4 是 ㄞˋ，找到愛心）。英文模式的搜尋列照原樣顯示按的鍵。Emoji 不含膚色變化。

Linux（X11）的面板畫在候選字視窗中（格子、搜尋列、類別、名稱，可以點選）；Windows 的文字服務在它的候選字視窗裡畫同樣的格子（同一份 `zt_panel::picker` 資料與尺寸，Direct2D 畫，Emoji 彩色，跟著外觀、強調色與高對比，點符號插入、點類別切換）。Linux 的 Wayland 工作階段由 Fcitx 畫候選字清單，面板以反白的那一列（1–9）呈現，類別與列數寫在提示裡；Windows 的文字服務在沒有組字或英文模式時先取得面板的按鍵。Linux／Windows 的預設不用 Alt：Windows 的 WinUI App（例如記事本）看到 Alt 放開會顯示選單的按鍵提示並取走焦點，面板就關閉了。

| ⌥ 加數字鍵或符號鍵 | 打出鍵上印的符號。例如 ⌥ 加句點鍵是「.」，⌥⇧ 加句點鍵是「>」。主要用在「標點按法」為 macOS 時。 |
| Caps Lock | 開著時打英文，正在組的字先送出。系統設定以 Caps Lock 切換輸入方式時，由系統處理；切到其他輸入方式後的延遲事件不再觸發提示。Caps Lock 的暫時英文狀態不存成下一個輸入框的中英模式。 |

組字中沒有開啟清單時，↑、Tab、⇧Tab、Page Up、Page Down 不做事，也不交給 App。沒有組字時，這些鍵與 `` ` `` 都交給 App。按 ⌘ 組合鍵、沒有對應標點的 ⌃ 組合鍵、⌥ 加字母，或輸入法不處理的其他按鍵時，先送出組字，再把按鍵交給 App。

macOS 的中文模式啟動時使用全形標點。⇧ 空白只切換之後輸入的標點，保留目前組字、游標、選取範圍與候選字清單。標點按法與輸出寬度分開：例如 Windows 按法的 ⇧3 可輸出「＃」或「#」，⌃ 句點可輸出「。」或「.」。英文模式與 Caps Lock 英文模式使用半形字元；英文字母、數字及一般空白維持半形。⌥ 加符號鍵仍明確輸出鍵面符號。切回中文、切換輸入欄位及重新載入引擎時保留本次執行的標點寬度，重新啟動輸入法時回到全形。

#### 自訂按鍵

打字用的鍵固定，包括注音鍵、聲調鍵、空白、Return、⌫、Esc 與方向鍵。下表的功能可以重新指定按鍵：點按鍵，再按下新的組合；按 Esc 取消。每個功能最多五個按鍵，每個按鍵一個按鍵圖示（§4.5「按鍵欄位」），任一個都有作用；可以加入、移除、還原成預設值。按鍵是一個鍵加上修飾鍵，不支援先後按兩個組合。使用者自己指定的按鍵優先：新版加入的預設按鍵若已被使用者指定給另一個功能，就留給那個功能，不算衝突。舊版儲存的按鍵若和當時的預設相同，讀取時換成新的預設。筆電上以 fn 打的鍵照鍵盤上印的顯示：fn ↑、fn ↓（Page Up、Page Down）可以設為「上一頁」「下一頁」的按鍵；fn ←、fn →、fn ⌫（Home、End、向後刪除）單獨按時是固定的打字鍵，加上修飾鍵才能指定。

以下組合無法指定，設定頁會在按鍵旁說明原因：

- ⌘ 組合鍵：「⌘ 組合鍵留給 App」；
- 不加修飾鍵的方向鍵、空白、Return、Esc、⌫、⌦、Home、End、Page Up、Page Down：「這個鍵用在打字、選字或送出」；
- 不加修飾鍵的字母、數字與符號鍵（`` ` `` 除外）：「這個鍵用在打注音、聲調或標點」；
- ⇧ 加字母、數字或符號鍵：「Shift 加這個鍵打中文標點或大寫字母」；
- ⌥ 加數字或符號鍵：「Option 加這個鍵打鍵上印的符號」（Linux／Windows：「Alt 加這個鍵打鍵上印的符號」）；
- Linux／Windows 的 Ctrl 加字母：「Ctrl 加字母留給 App」；Win（Super）組合鍵：「Win 組合鍵留給系統」；
- Windows 的 Alt 組合鍵（不含 Ctrl）：「Windows 的 Alt 組合鍵交給 App，輸入法收不到」（系統鍵，TSF 不交給文字服務；0.7.1 存下的這種按鍵仍會顯示，但沒有作用）；
- 已指定給其他功能的組合：「已用於「（功能）」」。

「還原預設值」回到上表。功能改用其他按鍵後，原本的預設按鍵交給 App。候選字視窗、設定頁的說明文字、預覽與 ⓘ 示範都顯示目前指定的按鍵，改了快捷鍵立即更新。

兩個功能用到同一個按鍵時（例如從舊版移轉，或重新開啟一個功能之後），兩個按鍵都以紅色標出，並寫出另一個功能的名稱；「快捷鍵」頁最上方列出所有衝突。同一個按鍵只有一個功能會作用。

舊版每個功能存一個按鍵（`shortcuts`）；讀取時當成只有一個按鍵，第一次修改後改存成按鍵清單（`keyBindings`）。設定檔中這一版沒有的功能（較新的版本加入的，或已移除的），它的按鍵略過，其他功能的按鍵照常讀取。

#### 要改哪個字

游標在句尾時，清單改最後的字詞。游標移到句中時，↓ 要改的字先以強調色粗底線標出；預設是游標右邊的字，可在「游標在句中時改」改成左邊。游標在開頭時一律改右邊的字。

清單開著時，正在改的部分以強調色粗底線加淡色底標出。反白移到不同長度的詞時，標出的範圍跟著改變。

#### 候選字清單的內容

- 一般清單只列照按鍵打出的詞與字。從要改的字開始，長的詞在前（最多 6 個字），再來是較短的詞，最後是單字；同樣長度的依前後文排序。
- 第一個是目前畫面上顯示的寫法。
- 清單只列詞庫的詞、自訂詞、記住的字詞與單字，不把轉換結果的片段拼成新詞。
- 「台」與「臺」兩種寫法的同一個詞只列一次，以設定的寫法顯示。
- 清單保留所有候選，每頁 3–9 項（「每頁的候選字」，預設 9），用選字鍵的前幾個選取。
- 修正清單把按錯修正與模糊音的字排在前面，其後是一般清單的內容。修正過的字旁邊以灰字標出修正後的注音。
- 在標點上開啟的清單列出同類的標點。

#### 選字後

在清單選了候選字後，畫面上其他的字詞維持原樣，和系統內建的注音輸入法相同。選的字在一個較長的詞中間時，這個詞在它前面的字也維持原樣；後面的字可能跟著選的字一起改對。之後只有新打的字依前後文調整。

#### 聯想詞

「選字 › 聯想詞 › 送出後列出聯想詞」開啟時（預設關閉；更新到 0.7.7 時，原本開啟的也關閉一次，之後可以再開啟），按 Return 送出、結尾是中文字時，候選字視窗列出常接在後面的詞，例如送出「謝謝」後列出「你、大家、你們…」。這時沒有組字，清單上方以「聯想詞・按 ↓ 選擇」標出，和一般的候選字分開。

清單剛出現時是「沒進入」的狀態：不反白任何一項，詞前面也不標選字鍵，因為這時 1–9 仍是注音鍵（1 是 ㄅ）；標出來的鍵一定是按下去會選那一項的鍵。按 ↓ 進入清單後，反白第一個詞，每個詞前面出現選字鍵，標題改為「聯想詞」，這時按詞前面的鍵就送出那個詞。

| 狀態 | 按鍵 | 結果 |
|---|---|---|
| 剛出現 | ↓ | 進入清單：反白第一個詞，標出選字鍵 |
| 剛出現 | 點一下 | 送出那個詞 |
| 剛出現 | 其他所有鍵 | 關閉清單，按鍵和沒有清單時完全相同：1 打 ㄅ、⇧1 打「！」、⇧/ 打「？」，空白鍵、Return、Tab、Esc、⌫、其他方向鍵與 Ctrl 組合鍵交給 App |
| 進入後 | ↑ ↓ | 移動反白；在第一個詞按 ↑ 回到剛出現的狀態 |
| 進入後 | 詞前面標的鍵（預設 1–9）、⇧ 加這個鍵、Return、點一下 | 送出那個詞 |
| 進入後 | Esc | 關閉清單，App 不會收到 Esc |
| 進入後 | 其他鍵 | 關閉清單，按鍵照常處理 |

送出聯想詞後，接著列出它後面常接的詞（同樣是剛出現的狀態）。三個平台的按鍵與顯示相同。

- 為什麼先按 ↓，而不是像其他輸入法一樣用 ⇧ 加數字：微軟注音（[說明](https://support.microsoft.com/help/5001290)：聯想詞視窗以 Shift 加數字鍵選取）、小麥注音的傳統注音模式（[使用手冊](https://github.com/openvanilla/fcitx5-mcbopomofo/wiki/%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8A)）與威注音的關聯詞語（摁住 ⇧ 再按選字鍵）都用 ⇧ 加選字鍵選聯想詞。這在清單出現時就占用 ⇧1「！」、⇧9「（」這些常接在詞後面的標點，所以小麥注音的自動選字模式（沒開啟聯想詞時）與威注音都在需要時才叫出清單：以 ⇧Return 送出才列出。ZhuyinType 在每次送出後都列出清單，所以清單出現時不占用任何會打出字的鍵：1–9 是注音鍵，⇧ 加數字是標點，空白鍵是聲調或空白。只有 ↓ 會被清單接走（沒有組字時它原本是把游標移到下一行），按 ↓ 等於叫出清單，之後選字鍵才用來選詞，和一般的候選字清單相同。
- 0.7.0 的清單在進入前就標出 1–9，使用者照著按 1 卻打出 ㄅ、清單消失，以為選不了（0.7.1 修正）。進入前不標選字鍵、標題寫明「按 ↓ 選擇」之後，畫面上標出的鍵都能直接用。
- Tab 不進入清單，因為送出後按 Tab 換到下一個欄位很常見。
- Windows 的文字服務在清單剛出現時只攔下 ↓（和會打出注音或標點的鍵），其他鍵交給 App，同時告訴服務關閉清單：Win32 的欄位中被文字服務攔下的鍵即使服務沒處理也不會回到 App，0.7.0 在這時會吃掉送出後的第一個 Return、方向鍵或 Ctrl 組合鍵。
- 「空白鍵：送出並輸入空白」送出時結尾是空白，不列出聯想詞。
- 詞來自內建的語言模型與個人連詞：以前接在同一個詞後面選過的詞排在前面，其次依語言模型的機率。只列詞庫中的中文詞；不列標點、「的、了、之」這類只用來連接的字，也不列罕用的單字。選聯想詞和選字一樣會被記住（「記住選過的字詞」關閉時不記，只依內建模型列出）。
- 密碼欄位、安全輸入與私密視窗中不列出，也不學習。

| 關於 | 自動檢查更新 | 開、關 | 開 |
| 關於 | 自動安裝更新 | 開、關 | 開 |
| 關於 | 更新後提示更新內容 | 開、關 | 開 |

「快捷鍵」頁的預設值見 §2.1 的「自訂按鍵」。

固定的上限：一段組字最多 60 個音節；一個詞最多 6 個字。

組字已有 60 個音節時再打一個字，前面一段先自動送出，其餘留在組字中，這個字照常打出：

- 最後一個標點（。！？，、；： 等）之後剩下 40 個音節以內時，送到那個標點為止；否則送出前面約 20 個音節，在詞與詞之間斷開，不拆開一個詞。
- 送出的就是畫面上的字，包括選過的字；和按 Return 送出一樣記住選過的字詞，也是後面組字的前文。畫面上留下的字維持原樣。
- 游標在組字中間時，只送出游標前的部分；游標在開頭時先不送出，這段組字暫時多於 60 個音節。

### 2.3 容錯輸入

- 自動處理按到相鄰鍵、多按一鍵、漏按一鍵、兩鍵順序打反（在同一個音節內或跨音節）、三聲與四聲互換、二聲與輕聲互換，以及一聲沒按空白就打下一個字。
- 幾乎同時按下（35 毫秒內）的兩鍵，順序打反或多按一鍵的修正成本很低；分開按的鍵視為刻意這樣打。
- 照按鍵打出的整句優先。修正過的整句，分數（引擎分數加上整句重排模型的分數）要比最好的未修正整句高 4.0 以上，才成為首選。
- 修正過的字詞列在修正清單（⇧↑，或點候選字視窗的「⇧↑ 修正」），旁邊以灰字標出修正後的注音。畫面上目前顯示的寫法若是修正過的，也列在一般清單的第一項。
- 選了修正過的字詞，就記住「哪個鍵常按成哪個鍵」，同樣的錯之後更容易修正。
- 「標示自動修正」（預設開啟，在「修正 › 修正過的字」）：畫面上修正過的字（按錯修正、模糊音、有邊讀邊），在組字中以強調色的點線標在字下方（macOS 的標示文字、Windows 的 TSF 顯示屬性；Fcitx 沒有點線，改為斜體），候選字視窗開在修正過的字上時，下方顯示「你打的是 ㄊㄜˇ」。只改顯示，不改轉換；選過的字不標。
- 「⌫ 還原自動修正」（預設開啟，同一段）：某個鍵讓修正出現後，緊接著按 ⌫，這段改回照按鍵打出的字（詞圖在這段不用修正與模糊音重新轉換，結果維持原樣，不算選字、不學習）；再按一次 ⌫ 才刪除。候選字視窗開在修正過的字上時，⌫ 也是改回並關閉清單（下方寫「· ⌫ 還原」），否則 ⌫ 照舊只關閉清單。有未完成的注音、打了其他鍵或游標移開後，⌫ 照常刪除。用 ⌫ 而不用 Esc：各平台的自動修正都是緊接著按刪除鍵還原，而 Esc 依設定會清除整段組字，按錯的代價太大。
- 「按錯鍵修正」設定（按到旁邊的鍵、多按、漏按與聲調）：「關閉」按鍵照打出的解讀；「只列出」組字照按鍵，修正過的字列在候選字清單（一般清單接在後面，⇧↑ 的清單在前面）；「標準」；「積極」的修正成本為「標準」的 70%。
- 「按鍵順序」設定（同一個字的注音順序打錯，例如 ㄠㄔ ㄢㄗˋ 打「超讚」），和「按錯鍵修正」分開：「自動修正」照修正後的順序組字；「只列出」組字照按下的順序，候選字清單第二項是順序修正後的詞，選了就換成那些字；「關閉」照按下的順序解讀。0.7.7 以前「按錯鍵修正」關閉時順序也不修，所以升級後預設「自動修正」：只想關閉其中一種的人不必兩個都關。
- 「接受常見的其他讀法」（預設開啟，在「修正 › 按錯鍵」）：照常見的另一種念法打也找得到要的詞。輕聲照本調或其他念法打（有什麼 打 ㄧㄡˇ ㄕㄣˊ ㄇㄚˊ）、詞裡的字照台灣讀音打，算是打對，不標注音；有邊讀邊（和睦相處 打 ㄏㄜˊ ㄌㄨˋ ㄒㄧㄤ ㄔㄨˇ）算是修正，修正過的整句要比照按鍵打的最好整句高 4.0 以上才成為首選，旁邊以灰字標出字典的讀音。每個詞最多一個字用其他讀法；單字詞與三聲變調不在內。關閉後只照字典的讀音找詞。

### 2.4 選字

- 整句轉換：詞庫、語言模型與音節對字模型一起在詞圖上找出分數最高的整句，再由整句重排模型依游標前的文字，從前 16 句中重新挑選。
- 語言模型有聊天用語與百科用語兩個。沒有前文時以聊天為主，例如打 ㄏㄨㄛˋ ㄕˋ 是「或是」。游標前的文字或最近在這個 App 打的字偏向書面用語時，百科的比重跟著提高。
- 游標前的文字：組字開始時向 App 讀取最多 128 個字，之後送出的字接在後面，最多保留 255 個字。音節對字模型讀全部，整句重排模型讀最後 24 個字。同時保留同一個 App 最近 1 分鐘的前文，輸入框清空或讀不到文字時仍可接續。讀得到的文字會合併並去除重複部分；只讀取前文或移動游標不延長保留期限。這段文字只放在記憶體中。關閉「參考游標前的文字」後，清除已保留的前文，也不向 App 讀取。
- 「台／臺」：預設寫「台」，可在「選字」改成「臺」。模型與詞庫內部照原本的字選字，只有顯示、候選字清單與送出的文字換成選定的寫法。
- 「繁／簡」：選「簡體」時，組字、候選字清單與送出的文字換成簡體字。詞庫、模型、學習與改字記錄仍用繁體，所以切回繁體不必重新學習。轉換是逐字的（OpenCC 的 `t2s` 單字表，`engine/crates/zhuyin-core/src/simplified/`），每個字換成第一個對應的簡體字，沒有詞語表：「乾坤」會寫成「干坤」，兩個繁體候選字也可能變成同一個簡體字（髮、發都是「发」）。
- 模糊音：ㄗ／ㄓ、ㄘ／ㄔ、ㄙ／ㄕ、ㄣ／ㄥ、ㄢ／ㄤ，可逐項開啟。開啟的兩個音互相通用。兩個詞同樣常用時，讀音完全符合的排在前面；另一個詞明顯更常用時才換上。
- 「一」「不」打變調後的讀音也找得到，例如一直打 ㄧˋ ㄓˊ、不要打 ㄅㄨˊ ㄧㄠˋ。罕用讀音的分數較低，例如「說」打 ㄕㄨㄟˋ 時「睡」排在前面。
- 自訂詞在選字時優先列出。
- 一段組字送出後，下一段接著前面送出的詞選字。按了交給 App 的鍵、點進文字、切換輸入框、中英切換或打了標點之後，下一段重新當作句首。

### 2.5 個人記憶

| 記住什麼 | 怎麼用 | 什麼時候學 |
|---|---|---|
| 選過的字詞 | 同樣的讀音再打一次時，直接採用選過的寫法。範圍包括整段組字、選字處前後的幾個音節、修正過的字與詞庫沒有的詞。把常用詞修正成別的詞，要選兩、三次才會一直採用；改選之後以最後選的為準。 | 手動選字；送出後刪掉重打 |
| 個人的一、二、三連詞 | 調整語言模型，反映你在某個詞後面常接什麼。 | 每次送出。手動選的字詞權重高，直接送出的權重低。 |
| 被換掉的寫法 | 選字時被換掉的寫法，以及送出後 30 秒內刪掉重打的舊寫法，在原本的前文中個人統計減半。 | 選字時；送出後 30 秒內刪掉重打 |
| 按錯習慣 | 常把哪個鍵按成哪個鍵，修正成本跟著降低。 | 選了修正過的字詞 |

以前在同樣位置選過的字詞會保留，整句重排模型只在保留這些字詞的整句之間挑選。「同樣位置」指接在同一個詞後面；兩個字以上的詞，在任何位置選過都算。

- 短期與長期：選過的字詞與個人連詞都同時有 8 小時與 90 天兩種半衰期。手動選過 3 次以上的保留最低分數。
- 容量：選過的字詞約 20,000 筆，個人連詞 50,000 筆。滿了先刪分數最低的。
- 設為「不記住」的字詞，之後送出也不學。
- 在候選字上按右鍵（或用 ⌃⌫、⌃⇧⌫、⌃Return；Linux／Windows：Ctrl+Del、Ctrl+⇧Del、Ctrl+Enter）可以「不要再推薦」「忘記這個選字」「加入自訂詞」，對象是反白的字詞，只在清單開著時作用。候選字視窗顯示結果，加上「⌃Z 復原」（Linux／Windows：「復原」連結），5 秒內按 ⌃Z 或點提示就復原。不推薦的字詞存在 `blocked.tsv`，在這個讀音的分數低 30（自然對數），整句轉換不會選它，清單中排到最後；沒有不推薦的字詞時沒有這個檔案，轉換結果和以前相同。它列在「記住的字詞」，標示「不推薦」，移除後恢復推薦。清單前 5 次打開時，下方顯示「⌃⌫ 不要再推薦・右鍵看更多」（Linux／Windows：「Ctrl+Del 不要再推薦・右鍵看更多」；`wordActionHintCount`），按鍵是「不要再推薦」目前的第一個按鍵，沒有按鍵時只寫「右鍵看更多」。
- 「選取的字加入自訂詞」（`addSelectedText`，預設沒有按鍵）：沒有組字時按下，讀取 App 裡選取的文字（最多 32 個 UTF-16 單位；安全輸入時不讀），打開「加入自訂詞」小視窗，詞是選取的文字，讀音是引擎最可能的讀法，兩者都可以修改。詞需為 1 到 6 個中文字，讀音的音節數要和字數相同，不符合時在視窗內說明原因。輸入時需要鍵盤，所以視窗打開時 ZhuyinType 成為使用中的 App，關閉後回到原本的 App。組字中按下不做事。
- 「字詞 › 記住的字詞」與「字詞 › 自訂詞」頁面下方說明這些動作與目前的按鍵。關閉「記住選過的字詞」後停止學習；系統開啟安全輸入時暫停學習。
- 記住的字詞在設定的「字詞 › 記住的字詞」管理，見 §4.5。

### 2.6 其他

- 自訂詞：在設定的「字詞 › 自訂詞」加入，或在組字中用 ⇧← ⇧→ 選取 1–6 個字後按 Return。加入後馬上生效。
- 標點預設為全形（見 §2.1），在標點上按 ↓ 可換成同類的其他寫法。
- 符號與 Emoji 面板見 §2.1「符號與 Emoji」，簡體輸出見上方「繁／簡」。中英混打尚未提供，見 [ROADMAP.md](../ROADMAP.md)。

「空白鍵」以前另有「送出文字」（送出整段，不輸入空白）；這個選項已移除，存著它的設定讀取時改為「送出並輸入空白」，舊版的開關設定也一樣對應。

### 2.7 改字記錄

「進階」頁的「記錄改字」開啟後，每一段有改字的組字在送出時記成一行，供改進引擎使用：重播當時的按鍵，看引擎現在能不能不靠改字就打對（`zt eval corrections`，見 [EVALUATION.md](../ml/EVALUATION.md)），以及統計常見的按錯與改字（`zt data corrections`）。

算作改字的情況：

| 改字 | 記錄的事件 | 什麼時候算 |
|---|---|---|
| 從候選字清單選字（一般、⇧↑ 修正、⇧↓ 單字） | `pick` | 選字改變了畫面上的字 |
| ⌫ 或 ⌥⌫ 刪掉注音或轉好的字，再打 | `backspace` | 刪掉之後接著打字 |
| Esc 清除注音或整段組字，再打 | `escape` | 清除之後接著打字；清除整段後 30 秒內再打的組字算同一筆 |
| `` ` `` 把字改成注音本身，以及立刻再按 `` ` `` 或 Esc 還原 | `literal_zhuyin`、`undo_literal` | 一律 |
| ⇧← ⇧→ 選取，按 Return 加入自訂詞 | `select`、`add_phrase` | 一律；加入自訂詞要成功 |
| 游標移進句中之後修改 | `cursor`，加上標為 `mid` 的打字或刪除 | 在句中打字或刪除 |
| 送出後 30 秒內按 ⌫ 刪掉剛送出的字，再打一段 | `delete_after_commit` | 新的一段開頭和刪掉的字不同 |

沒有改字的組字不記錄。每一筆記錄是一個 JSON 物件（`schema` 1）：

| 欄位 | 內容 |
|---|---|
| `schema`、`id`、`date`、`app_version` | 格式版本、隨機編號、日期（只到日）、App 版本 |
| `settings` | 影響按鍵結果的設定：按錯鍵修正、接受常見的其他讀法、模糊音、標點按法、空白鍵、台／臺、游標在句中時改、選字鍵、排列、記住選過的字詞、參考游標前的文字 |
| `context` | 引擎讀到的游標前文字（最多 255 個字），只在開啟「一併記錄游標前的文字」時記錄 |
| `keys` | 每個按鍵與點按，以 `zhuyin-cli` 批次語法寫成，第二個鍵起前面加 `<dt:毫秒>`。點選候選字寫成那一頁同位置的選字鍵，⇧↑ 修正按鈕寫成 `<sup>`，其他方式送出（點進文字、切換中英、⌘ 組合鍵）寫成 `<enter>` |
| `typing`、`replayable` | 打出最後那段組字的按鍵：不含清單的按鍵與選字，刪掉重打的部分只留重打的鍵；重播時在後面加 `<enter>`。在句中修改過、或有 `zhuyin-cli` 寫不出的鍵（⌥ 或 ⌃ 加 `>`）時，`replayable` 為 false |
| `original_typing`、`original_replayable` | 第一次打的按鍵：把每次 ⌫、Esc 的改字換回刪掉的鍵 |
| `shown` | 第一次改字之前畫面上的字；組字超過 60 個音節、前面一段已自動送出時，前面加上已送出的字 |
| `committed` | 送出的字。組字超過 60 個音節時前面一段會自動送出，同一段組字仍是一筆記錄，這裡是全部送出的字；重播 `typing` 時也一樣分段送出 |
| `corrections` | 這一段有哪幾種改字，依第一次出現的順序 |
| `events` | 依序的事件，每個有 `type`、`t`（從第一個鍵起的毫秒數）與 `shown`（事件之後畫面上的字），其他欄位依種類而定：`type`（連續打的鍵）、`open_list`、`switch_list`、`close_list`、`pick`（`before`、`after`、`start`、`removed`、`inserted`、`rank`、`list`、`via`）、`backspace`／`escape`（`shown_before`、`removed`、`deleted_keys`、`retyped_keys`、`replaced_by`、`cleared`）、`literal_zhuyin`、`undo_literal`、`cursor`（`position`）、`select`、`cancel_select`、`add_phrase`（`phrase`、`added`）、`delete_after_commit`（`deleted`、`previous_committed`、`previous_typing`、`previous_replayable`）、`commit`（`text`；自動送出前面一段時 `shown` 是留下的組字） |

`deleted_keys` 是刪掉的字當初打的鍵，`retyped_keys` 是之後補打、直到組字回到原本長度的鍵，例如打 `1j6`（ㄅㄨˊ）刪掉後改打 `1j4`（ㄅㄨˋ）。刪掉的鍵依畫面回推：回到上一次畫面有同樣多的字與注音的時候；在句中刪除時無法回推，記為空。

選字事件另外保留實際選中的完整詞、讀音與組字範圍，供本機分析確認引擎學習了哪個候選；這和畫面上改變的字分開記錄。舊紀錄仍可讀取，不補猜缺少的候選身分。

隱私：

- 預設關閉；關閉後立即停止記錄，正在打的那一段也不記錄。
- 系統開啟安全輸入時（密碼欄位）不記錄，已開始的那一段也捨棄。
- 游標前的文字只在開啟「一併記錄游標前的文字」時記錄。
- 不記錄在哪個 App 打字，也不記錄時刻，只記日期。
- 檔案是 `~/Library/Application Support/ZhuyinType/corrections.jsonl`，只有使用者本人可以讀（權限 600），在背景佇列逐行附加，結束程序前寫完；輸入法只在這台 Mac 上讀寫它。設定頁可以在 Finder 中顯示、匯出與清除。

### 2.8 使用統計

「分析」頁的「記錄使用統計」（預設開啟）計算這台 Mac 的打字次數與輸入法的反應時間，只記錄數字：

| 計數 | 內容 |
|---|---|
| 送出的字、組字、按鍵 | 送出的字數（含標點）、送出的組字數與其中一次就對的組字數、組字中由輸入法處理的按鍵數 |
| 從清單選字 | 依清單分：一般、修正（⇧↑）、單字（⇧↓）、標點；按選字鍵、Return 或點選 |
| 改字 | 組字中按 ⌫ 或 ⌥⌫、Esc 清除、送出後 30 秒內刪掉（每次送出最多算一次）、打出注音本身、恢復成原本的字 |
| 自動修正 | 整句有按錯修正的字的組字數：出現過的、送出時仍是修正後寫法的（由整句重排模型挑選的整句判斷；沒有這個模型時不計）；還原自動修正的次數（⌫ 還原或候選字視窗中還原，`correctionsReverted`） |
| 加入自訂詞 | 打字時選取後加入的次數 |
| 按鍵反應 | 從輸入法收到按鍵到組字與候選字視窗更新完成的時間，記成分布（1 毫秒到 1 秒的 21 個區間）與最慢的一次 |

- 總數與每天一筆，保留最近 60 天。全部在記憶體中累加；`~/Library/Application Support/ZhuyinType/stats.json`（只有使用者可讀，一個小檔案）每 10 分鐘最多寫入一次，另在切換到其他輸入方式、打開設定視窗與結束程式時寫入，沒有變動就不寫。寫入在背景進行。
- 不記錄打的字、讀音、按了哪些鍵、App 名稱或 bundle ID。系統開啟安全輸入時（密碼欄位）不計數。
- 計數在 App 這一層觀察組字的結果（`UsageStatsObserver`），不改引擎。每個按鍵的成本固定：兩次讀時間、幾個整數相加與固定大小陣列的累加，不配置記憶體；自我測試量測每個按鍵的成本，超過 2 微秒即失敗（目前約 45 奈秒）。沒有在背景執行的計時器；CPU、記憶體與耗電只在「分析」頁顯示時每 2 秒讀一次。
- 「分析」頁寫出：「統計只在記憶體中累加，每 10 分鐘最多寫入一次，不影響打字。」

打字節奏（只算數字）：

| 項目 | 怎麼算 |
|---|---|
| 打字速度 | 送出的字數 ÷ 打字時間（字/分鐘）。打字時間只算連續打字中兩鍵之間的時間 |
| 打字時間、思考停頓 | 兩鍵間隔不超過停頓門檻時算打字；超過門檻、不超過 1 分鐘算思考停頓；超過 1 分鐘兩者都不算。門檻為「平常兩鍵間隔中位數的 4 倍」，至少 2 秒，在每次使用（輸入法這次被選用）開始時決定，之後不變 |
| 最長連續 | 一段連續打字（中間沒有超過門檻的停頓）送出的最多字數；另記沒有任何改字的最長一段 |
| 一次就對 | 送出的組字中，沒有選字、⌫、Esc 或 `` ` `` 的比例；清除後重打的算同一次 |
| 每個字按幾個鍵 | 按鍵數 ÷ 送出的字數，包含改字的按鍵 |
| 什麼時候打字 | 一週七天 × 24 小時送出的字數 |
| 思考停頓的中位數 | 停頓長度分布的中位數 |
- 關閉時不計數；「清除統計…」確認後刪除檔案與所有計數。

「效能」另外顯示這個程式本身的數字，不儲存：CPU 時間（`getrusage`）、目前與最高的記憶體（`proc_pid_rusage`）、耗電（`proc_pid_rusage` 的 `ri_energy_nj`，macOS 的估計；系統沒有提供時寫「macOS 沒有提供」），以及詞庫、整句重排與逐字模型上次載入的時間。

預設開啟的理由：只有次數與時間，不含任何文字，資料不離開這台 Mac；關閉時「分析」頁沒有內容可看。

## 3. 系統整合

完整的逐鍵流程、分數公式與模型位置見 [ARCHITECTURE.md](../engine/ARCHITECTURE.md)。這裡只列和 macOS 文字客戶端有關的規則。

### 3.1 行程

輸入法、引擎與模型在同一個行程內直接呼叫。引擎與模型在背景載入。載入期間打的文字鍵（不含 ⌘、⌃、⌥ 組合鍵，最多 64 個）先保留，載入完成後依序送進組字。英文模式下的按鍵與組合鍵直接交給 App。載入失敗時，保留的按鍵照原本的字元交給 App。

### 3.2 文字客戶端

| 項目 | 做法 |
|---|---|
| 組字 | 透過 `setMarkedText` 傳遞，只在文字、游標或底線改變時更新，網頁引擎型 App 也一樣。 |
| 浮動組字 | 「進階 › 在候選字視窗顯示組字的 App」清單中的 App（依 bundle ID），組字顯示在候選字視窗上方，預設清單是空的。 |
| 重複的按鍵事件 | 同一個按鍵、時間戳記相同的事件只處理一次。 |
| 單按 Shift | `flagsChanged` 依系統旗標中的左右 Shift 狀態判斷；設定練習以原始事件中的側鍵狀態判斷，兩處共用側鍵解碼。0.35 秒內放開，且期間沒有按其他按鍵或修飾鍵，才算單按。相同狀態的事件合併處理。焦點不在可以輸入文字的地方時（遊戲、沒有文字欄位的視窗：App 回報不出選取範圍、組字範圍或游標所在的行），單按 Shift 不切換中英，也不顯示「中」「英」提示；Caps Lock 的提示也一樣。 |
| 點進文字 | App 要求結束組字時（例如點進文字），送出組字，下一段當作句首。 |
| 候選字視窗位置 | 依序採用組字起點的行高矩形、游標前的組字、組字起點、選取範圍、上一次有效位置、滑鼠位置。視窗依「位置」放在該行下方（預設）或上方，空間不足時換到另一邊，並一律留在螢幕內。 |

### 3.3 資料與設定

- 內建資料：詞庫與兩個語言模型在建置時編譯成二進位檔（`lexicon.bin`、`lm/lm.bin`、`lm_chat/lm.bin`），執行時以 mmap 對應，不佔行程本身的記憶體。目錄裡放 TSV 也能讀。
- 個人資料：`~/Library/Application Support/ZhuyinType/` 下的 `user_phrases.tsv`、`learned.tsv`、`excluded.tsv`、`typos.tsv`、`personal_ngrams.tsv`，在背景以原子寫入更新。
- 替換用的資料與模型：放在 `~/Library/Application Support/ZhuyinType/Models/`，見 §3.5。
- 改字記錄：開啟「記錄改字」時，同一個資料夾的 `corrections.jsonl`，在背景逐行附加，見 §2.7。
- 最近使用的符號：`~/Library/Application Support/ZhuyinType/` 的 `recent-symbols.txt`，一行一個符號，最新的在前，最多 32 個。「回復預設設定」與「記住的字詞 › 全部清除」會刪除它。（Linux／Windows：使用者資料夾的同名檔案；「回復預設設定」刪除它，Windows 解除安裝時勾選刪除個人資料也會刪除）
- 設定：存在 UserDefaults。

### 3.4 自動更新

自動更新使用 Sparkle，每天向 GitHub 上的 `appcast.xml` 檢查一次。appcast 與更新檔都以 EdDSA 簽章驗證，並盡量下載差分更新（只下載改變的檔案）。

輸入法很少結束，所以下載的更新不等程式結束才安裝，而是在所有輸入框都沒有組字時安裝並換上新版。每次按鍵後與每 5 秒各確認一次。

相關選項在設定視窗「關於」頁的「更新」區塊：

- 「自動檢查更新」，預設開；
- 「自動安裝更新」，預設開，關閉「自動檢查更新」時無法切換。關閉時，背景檢查找到新版本後以 Sparkle 的視窗詢問；
- 「檢查更新」列的「立即檢查…」按鈕，開啟 Sparkle 的視窗。

區塊下方的說明列出已下載、等待安裝的版本與上次檢查的時間。沒有設定更新來源的開發版不顯示這個區塊。

### 3.5 更新後換版

輸入法以 FSEvents 監看 app 所在的資料夾與模型目錄（`~/Library/Application Support/ZhuyinType/Models/`），檔案變動停止 2 秒後才處理。

- 裝了新版 app（版本號或執行檔改變）時，等所有輸入框都沒有組字就結束行程，下一個按鍵由 macOS 啟動新版。中英模式保留，不需要登出。
- 模型目錄裡放了新的資料或模型時，在背景載入。`lexicon.bin` 或 `lexicon.tsv` 連同 `lm/`、`lm_chat/` 為一組，`reranker/` 與 `v3/` 各自獨立。載入完成後，各輸入框在組字結束時換用新的，行程不重新啟動。移走這些檔案就換回 app 內建的。
- 載入期間打的文字鍵依 §3.1 的規則保留。
- 每個 app 附 `manifest.json`，記錄版本與每個資料、模型檔的 SHA-256。

### 3.6 更新後的提示

更新後第一次打字，停下來 4 秒時提示一次「ZhuyinType 已更新到 X.Y.Z」與最多三項重點，可以點「查看更新內容」或「回報問題」。三個平台的規則相同（macOS：`Update/ReleaseNotes.swift`、`Update/UpdateNotice.swift`；Linux／Windows：`zt_core::release_notes`、`update_notice.rs`）：

- **每一版一次**。記下提示過的版本（`updateNotesSeenVersion`）與它之前的版本（`updateNotesPreviousVersion`），「回復預設設定」不會清除。新安裝、裝回舊版、關閉「更新後提示更新內容」時只記下版本，不提示。從沒有這項記錄的版本（0.7.6 以前）更新時，看有沒有使用過的痕跡分辨更新與新安裝。
- **不打斷打字**。還沒打字、組字中或清單開著、密碼欄位、設定或嚮導開著、有全螢幕的 App、遊戲或簡報時都不跳，等到可以時再提示；那之前重新啟動也還會提示。
- **不取得焦點**。macOS 是螢幕右上角不會成為焦點的小面板，20 秒後自己消失（滑鼠停在上面時留著），不出現在全螢幕的空間，不需要通知權限。Windows 是系統的通知（沒有聲音），「請勿打擾」時由系統收進通知中心；全螢幕與簡報依 `SHQueryUserNotificationState` 判斷。Linux 是桌面的通知（`org.freedesktop.Notifications`）；X11 另外確認作用中的視窗不是全螢幕，Wayland 由桌面決定全螢幕時要不要顯示。
- **跨好幾版**：重點依新功能、改進、修正的順序挑選，同類以新版在前，最後一行寫「N 個版本，另有 M 項」。「更新內容」逐版列出，略過在這個系統沒有變更的版本。
- **內容隨 App 附上，不上網**。建置時 `tools/release_notes.py` 把 `docs/releases/vX.Y.Z.md` 的「新功能」「改進」「修正」整理成 JSON；以「Windows：」「Windows 與 Linux：」開頭的項目只出現在那些系統。這一版在這個系統沒有變更時，提示寫「這一版沒有 macOS 的變更」。

「關於 › 更新內容 › 這一版的更新內容 ›」隨時可以看，開過就不再提示；頁面最下方有「更新後提示更新內容」的開關與 GitHub 上完整的發布說明。「新功能導覽」（設定嚮導的新課程）和它分開，仍只從選單與「介紹」開啟。

## 4. 介面

Linux／Windows 版（`platforms/desktop/`，GPUI）的功能與版面依本文件的 macOS 版逐頁移植，視覺則是 ZhuyinType 自己的現代設計語言，不模仿 macOS 或 Windows 原生外觀。Fcitx5／TSF 透過本機通訊接入同一個程式的輸入法服務，處理系統焦點、按鍵、組字與游標位置；程式本身負責引擎、設定與候選字視窗。見 [Linux 與 Windows 版](DESKTOP.md)。

整體採用 macOS 26 之後的系統設計語言。App 以 macOS 27 SDK 建置，並在執行檔標記實際使用的 SDK 版本，系統因此以目前的樣式繪製所有標準控制項。最低系統需求為 macOS 14。

### 4.1 候選字視窗

候選字視窗是 NSPanel，圓角 14 pt。背景在 macOS 26 以上為 Liquid Glass（`NSGlassEffectView`），較舊的系統為 popover 材質；系統開啟「減少透明度」時由系統改用不透明的背景。反白的候選字以強調色圓角矩形標出，滑鼠移過的候選字以淡灰色標出。點一下候選字即選取。

「候選字視窗」與「色彩」頁可以調整：

- 版面：排列（直式、橫式）、字級（13–36 pt）、每頁的候選字（3–9）、選字鍵、間距（標準、緊湊；緊湊的列高與邊距較小）；
- 內容：顯示注音、標出修正的讀音、單字與修正按鈕；
- 位置與動畫（候選字視窗）：位置（游標下方、游標上方）、動畫；
- 色彩：外觀（跟隨系統、淺色、深色，也套用到中英切換提示）、強調色（跟隨系統、ZhuyinType 藍）。

「動畫」開啟時，候選字視窗出現時以 0.12 秒淡入並向游標方向移動 4 pt；系統開啟「減少動態效果」時只淡入。之後的更新與關閉都立即完成。

翻頁（Tab、fn ↓、⌥↓、清單中的空白、在最後一個字按 ↓ 等）時，反白固定在原位不動；舊的一頁的字沿著清單的方向移出 10 pt，在前 0.05 秒淡出，新的一頁的字從另一邊移入，從 0.04 秒開始淡入，0.14 秒時就位（ease-out），兩層字不會同時清楚可見：直式清單下一頁往上、上一頁往下，橫式清單左右移動。頁碼同時淡入淡出。按鍵一律立即處理，反白立即出現在新的一頁；動畫進行中再翻頁，會直接從新的一頁開始，不排隊。在第一頁或最後一頁翻頁停住時，清單往翻頁的方向輕推 3 pt 再回來。同一個清單翻頁時視窗大小不變：寬度保持翻過的頁中最寬的，直式清單保留一整頁的高度。「動畫」關閉時不做任何動態；「減少動態效果」時只淡入淡出，停住時以短暫變淡代替輕推。

由上到下依序為：

1. 提示：需要時顯示一行，例如「↩ 加入自訂詞：」加上選取的字、「已加入自訂詞：」加上加入的詞，或「自訂詞需為 1 到 6 個字」。只有提示時，視窗是一個小圓角框。
2. 浮動組字：只在「在候選字視窗顯示組字的 App」中，以及 App 不能顯示組字時（Linux：Fcitx 說沒有組字能力；Windows：「看不到注音時改用懸浮打字框」開啟時的遊戲，視窗放在遊戲視窗左下角上方）顯示，加底線。
3. 注音：要改的部分的注音，前面是 `` ` `` 的按鍵圖示。點一下打出注音本身。標點的清單不顯示這一列；關閉「顯示注音」時也不顯示。
4. 候選字：每一列前面是選字鍵。聯想詞（§2.1「聯想詞」）沒有注音，注音那一列改為「聯想詞・按 ↓ 選擇」；按 ↓ 進入清單前沒有反白，也不標選字鍵（這時選字鍵仍是注音鍵），進入後標題改為「聯想詞」並標出選字鍵。修正過的候選字旁邊以灰字標出修正後的注音（可關閉「標出修正的讀音」）。
5. 下方：「⇧↓ 單字」與「⇧↑ 修正」兩個開關，以及頁碼與 ‹ › 翻頁按鈕。開關開著時以強調色顯示，可以點。「⇧↑ 修正」只在可以修正時顯示；關閉「單字與修正按鈕」時，開關只在開著時顯示。只有一頁且沒有開關時，不顯示這一列。

按鍵圖示依目前的快捷鍵設定顯示。

視窗的寬度容納所有內容：整列注音與它的按鍵圖示、每個候選字、下方的開關與頁碼，以及提示的整段文字（「↩ 加入自訂詞：」後最多 6 個字），任何字級與螢幕縮放都不截斷。

#### 無障礙

- **強調色**（`accentColor`）：「跟隨系統」時反白的候選字是系統強調色的實心圓角矩形；「ZhuyinType 藍」用淺色 #4257D8、深色 #7A8CF0。反白上的字一律是白色，和反白至少 4.5:1（WCAG 2）：強調色不夠深時，淺色與深色視窗都逐步加深（每步 8%，最多 6 步），仍不夠就改用 #4257D8。反白靠底色和白字一起和其他列區分，不要求反白和視窗背景的對比；「增加對比」時另有外框。下方開著的開關也用強調色。
- **增加對比、減少透明度**：系統開啟其中一個時，候選字視窗與中英切換提示改用不透明的背景；「增加對比」另外加上 2 pt 的邊框、反白的 2 pt 外框與較深的滑鼠移過顏色。跟著系統即時改變，優先於透明效果。
- **VoiceOver**：候選字清單是一個清單，每一列讀出選字鍵、字與修正的注音（「3，在」），反白的列標為已選取；橫式清單是橫向的清單。VoiceOver 執行時另外朗讀：開啟清單時「ㄗㄞˋ，候選字清單，共 11 個，2 頁，候選字 1，在」（修正清單叫「修正的字」，單字清單叫「單字」），翻頁時「第 2 頁，共 2 頁，候選字 1，……」，移動反白時「候選字 3，在」；中英切換時讀「中文」「英文」（關閉中英提示也一樣），切換全形、半形標點時讀「全形標點」「半形標點」。內容沒有改變的更新不重複朗讀。VoiceOver 沒有執行時，每次更新只多一次檢查。

### 4.2 中英切換提示

中英切換時，在游標旁以同樣的材質顯示「中」或「英」0.8 秒，再以 0.2 秒淡出（關閉「動畫」時在 1 秒後直接消失）。在中文模式下打開或關閉 Caps Lock 時也顯示，切換到其他輸入方式時立即消失。Windows 在全螢幕的 App（遊戲）裡切換到 ZhuyinType 時也顯示，因為 Windows 自己的切換提示被遊戲擋住。位置與外觀跟著候選字視窗的設定。可以在「打字」頁關閉「中英提示」。

「繁／簡」為簡體時，中文模式的提示是「简」而不是「中」。暫停學習時，提示的右上角多一個小圓點（次要文字色），不另加文字。

### 4.3 圖示

App 圖示採用 Icon Composer 格式（`platforms/macos/Resources/AppIcon.icon`）：藍色背景加上一層玻璃材質的「ㄓ」字形，字形取自 PingFang TC。淺色、深色與透明外觀由系統繪製。圖示由 `platforms/macos/scripts/make_icons.swift` 產生，並以 actool 編譯。

輸入法圖示是 16 × 16 pt 的正方形，圓角 2.5 pt，鏤空一般字重的「ㄓ」，比例與系統內建的輸入法圖示相同。圖示為 template 向量 PDF，選單列、輸入法選單與游標旁的指示器由系統著色。輸入方式的名稱為「注音 ZhuyinType」。

### 4.4 輸入法選單

選單列的輸入法選單最上面是快速設定的四個勾選項目：「英文」「半形標點」「簡體」「暫停學習」，打勾表示開啟，選了立即生效；有符號表時接著是「符號…」。分隔線下是「設定…」「自訂詞與學到的詞…」「設定嚮導…」（有新課程時加上「新功能導覽…」）、「回報問題…」（「關於 › 意見與問題」）與「關於 ZhuyinType」，都開啟設定視窗。

- 「英文」：和單按 Shift 相同，正在組的字先送出。
- 「半形標點」：和「切換標點全半形」的快捷鍵相同，英文模式中也可以切換，切回中文時套用。
- 「簡體」：設定「選字 › 繁／簡」。
- 「暫停學習」：和設定「字詞 › 暫停學習」是同一個開關。暫停期間照常打字，但不記住選過的字詞、不記錄改字、不讀取也不保留游標前的文字（和密碼欄位的安全輸入相同）；正在組的字也立即停止學習。只存在記憶體中，關閉、重新登入或更新後一律恢復學習。

### 4.4.1 快速設定

「開啟快速設定」快捷鍵（預設沒有按鍵，在「中英切換 › 快速設定」或「快捷鍵」頁指定）在游標旁開一個小視窗，標題「快速設定」：同樣四個勾選項目（右邊標 1–4），分隔線下是「設定…」「自訂詞與學到的詞…」，以及有符號表時的「符號…」。中文與英文模式都可以開，所以也是切回中文的一個方法。視窗是不會成為焦點的面板，打字的 App 不失去焦點：點項目或按 1–4 切換，視窗留著顯示新的狀態；Esc、點視窗以外的地方或按其他鍵就關閉，那個鍵照常交給輸入法。點連結會開啟設定視窗並關閉快速設定。符號表由 `QuickSettings.openSymbols` 接上，沒有時不顯示這一項。

### 4.5 設定視窗

設定視窗的架構見 [SETTINGS_IA.md](SETTINGS_IA.md)。版面與系統設定相同：左側是原生 source list 側欄（彩色圖示），以小灰字的段落標題分成「概覽」（介紹、分析）、「輸入」（打字、標點與符號、中英切換）、「選字與字詞」（選字、修正、字詞）、「外觀」（候選字視窗、色彩）、「一般」（快捷鍵、檢查輸入法、進階、關於）；右側是 SwiftUI 分組表單。各頁的設定與預設值見 §2.2。第一次打開時顯示「介紹」，之後回到上次的頁面（舊版的頁面 id 對應到新的頁面，見 SETTINGS_IA.md §4.4）。

- **下一層**：以「›」結尾的列開啟下一層頁面，列上顯示目前的狀態（例如「模糊音　已開啟 2 項」）。下一層的上方是「‹ 上一層」與頁名，⌘[ 也回到上一層。
- **設定列**：每一頁、下一層、總覽、分析與進階都用同一個列元件。左邊是名稱，下面可以有換行的說明；右邊依序是值、控制項，有 ⓘ 或 › 時接在最後；每一列的右邊一組都結束在卡片內容的右緣，不留空白的欄位。右邊整組對左邊整組垂直置中。縮排的子列（功能下的「快捷鍵」「往左選取」）用同一個元件，只把左邊內縮固定的距離，右緣和上一列的開關相同。開關、選單、按鍵圖示、› 與 ⓘ 在每一頁大小相同；文字按鍵與符號按鍵同高、同基線。
- **間距**：所有間距是 `RowMetrics` 中的常數，每一頁共用：頁面左右 20 pt、卡片最寬 700 pt（較寬的視窗置中）；卡片內左右各 16 pt，每列上下各 10 pt，分隔線的左右也是 16 pt；段落標題與卡片、卡片與頁尾說明相距 7 pt，段落之間 22 pt；段落標題、頁尾說明與下一層的頁名都對齊卡片內容的左緣。分析與介紹的磚塊本身就是小卡片，直接放在頁面上（不再包一層卡片），內距 14 pt、間距 10 pt。UI 預覽會量每一列與每一張卡片：右邊一組沒有置中、一列的左右內距不同，或卡片第一列上方與最後一列下方的空間不同，都會失敗；並畫出格線（名稱的左緣、右邊一組的右緣、每列的中線、卡片的外框與內容邊界）。
- **功能與按鍵**：有按鍵的功能佔兩列以上：先是功能列（名稱、說明與開關），說明可以換行；下面縮排一列「快捷鍵」（有兩個動作時各一列，例如「往左選取」「往右選取」），放按鍵欄位；按鍵和預設不同時，欄位前有文字按鈕「還原預設」，相同時不顯示。功能關閉時不顯示按鍵列，功能列寫出按鍵交給 App。被其他設定關掉的功能，說明寫原因並連到那個設定。頁尾有一個文字連結「在快捷鍵總覽中查看全部按鍵」。
- **到達提示**：每一個連到某一列的連結（總覽的列、按鍵衝突、「已關閉 ›」、介紹的卡片與摘要、「在快捷鍵總覽中查看全部按鍵」、變暗功能的原因、快速設定的說明）由同一處程式處理（macOS `SettingsWindowController.open(_:)` 與 `SettingsPaneView.reveal`）：切換頁面，目標在下一層時先打開那一層，在收起的區塊中時先展開；捲到目標約在上方三分之一（段落標題與目標列都看得到）；鍵盤焦點移到目標列，Tab 從那裡往下走；目標列的底色以強調色約 17% 亮一次（0.2 秒淡入、停 0.8 秒、0.8 秒淡出），所在段落的標題同時變成強調色；目標是整個段落時，整張卡片一起亮。不畫外框，不改變版面。「減少動態效果」時不做捲動動畫，只淡入淡出。從側欄點頁面不做到達提示。
- **指標移過不改變版面**：指標移過時才出現的控制項（例如「＋」）一直佔著位置，只改變透明度；錄製、接受、拒絕與「還原預設」也不改變欄位的高度。只有狀態改變（例如出現按鍵衝突）時才加入一行說明。自我測試量欄位在平常、指標移過與錄製時的高度，必須相同。
- **說明**：每個設定一段說明，隨選項改變。ⓘ 以小示範呈現每個選項的效果，目前的選項標為「目前的設定」：空白鍵、Esc、標點按法、游標在句中時改、按錯鍵修正、記住的字詞、記錄改字、使用統計。「減少動態效果」時示範先停在結果，游標不閃爍。
- **按鍵欄位**：同一個元件用在每一處。每個按鍵組合是一個按鍵圖示，修飾鍵在裡面（「⌃]」「⇧Tab」「fn↓」）；同一個動作的幾個按鍵就是幾個圖示，不寫「或」（VoiceOver 與工具提示仍說「或」）。平常只有按鍵：指標在這一列上時，按鍵左邊出現虛線的「＋」（新增按鍵），和預設不同時再左邊出現「還原預設」；指標在某個按鍵上時，那個按鍵的右端出現 ✕，按鍵不變大。這些都一直佔著位置或疊在上面，所以版面不動。沒有按鍵時平常是淡淡的「—」，指標移過時變成「＋ 新增按鍵」。點一下按鍵錄製：按鍵變成強調色外框，裡面即時顯示按住的修飾鍵與閃動的游標，Esc 取消；接受時輕輕彈一下，拒絕時輕微晃動並在下方插入一行紅字；「減少動態效果」時改成淡入淡出。鍵盤：按鍵可以取得焦點，⌫ 刪除；右鍵選單有改按鍵、新增按鍵、刪除、還原預設。和其他動作重複的按鍵以系統紅色標出，下方寫「也用於「（動作）」」並附「改按鍵」「前往」。按鍵多時換行並靠右對齊。按鍵和預設不同的列，名稱前有一個強調色小點（工具提示「已自訂」）。「快捷鍵」總覽每列最多顯示兩個按鍵，其餘以「+N」表示，指標移到或點「+N」時展開，離開這一列時收起；功能頁顯示全部按鍵。每個動作最多五個按鍵；預設的按鍵也可以刪除，可以關閉的功能可以沒有按鍵，「送出並換行」「改前一個字」「改後一個字」至少留一個。

#### 4.5.1 檢查輸入法

側欄的「檢查輸入法」找出無法用 ZhuyinType 打字的常見原因。頁首寫「全部正常」或「有 N 個項目需要處理」；有需要處理的項目（注意、錯誤）時，側欄的「檢查輸入法」旁出現警示符號。檢查在背景執行，設定視窗打開、以及每次回到設定視窗時重新檢查，按「重新檢查」也可以。每一項寫出狀態（正常、說明、注意、錯誤）、一兩句說明，安全的情況下附一個按鈕；按鈕只改這位使用者自己的設定，做完後重新檢查。每一項下方的「詳細資料」展開後列出檢查了什麼、看到的值（例如文字服務 DLL 的路徑、輸入法清單、Fcitx 5 的版本、詞庫的檔案），平常收起，列表維持一項一行。

| 平台 | 檢查 | 按鈕 |
|---|---|---|
| macOS | 輸入方式已加入並可選用、執行中的是「輸入法」資料夾中的那一份（另有副本時提醒，不刪除）、安全輸入（寫出開啟它的 App）、「自動切換成文件的輸入方式」 | 加入輸入方式（和安裝程式相同，不切換輸入方式）、打開鍵盤設定、在 Finder 中顯示 |
| Windows | 64 與 32 位元的文字服務已登記、已加入這個帳號的輸入法清單、預設的輸入法是另一個（例如微軟注音，說明）、「允許我為每個應用程式視窗使用不同的輸入法」（說明：切換只對目前的視窗有效，工作列可能仍顯示 ENG）、登入時啟動與更新服務（由安裝程式安裝時）、智慧型應用程式控制已開啟，或程式碼完整性的記錄中有 ZhuyinType 的檔案被擋下（這位使用者能讀取記錄時） | 加入輸入法清單（`regsvr32 /n /i:user`，和 Active Setup 相同）、開啟語言設定、開啟進階鍵盤設定、開啟 Windows 安全性 |
| Linux | Fcitx 5 已安裝並正在執行、環境變數（`GTK_IM_MODULE`、`QT_IM_MODULE`、`XMODIFIERS`）沒有指向其他輸入法框架、ZhuyinType 在 Fcitx 5 的輸入法中、Fcitx 5 已載入 addon；Wayland 上 GNOME 的 Kimpanel 擴充功能與 Chrome／Electron 的 `--enable-wayland-ime`（說明） | 改用 Fcitx 5、加入 Fcitx 5（`fcitx5-setup framework`／`enable`）、開啟擴充功能頁面 |
| 全部 | 輸入法服務正在執行並有回應（Linux／Windows）、詞庫與模型（Linux／Windows 另外檢查模型是否載入，例如找不到 ONNX Runtime）、設定檔（無法讀取時目前用預設值；先前無法讀取的檔案留成 `settings.unreadable.json`）、版本與更新 | 在檔案管理員中顯示 |

「回報問題…」把以下內容整理成一段 Markdown 文字，貼到 GitHub 的問題回報時顯示成標題與清單；先完整顯示，再由使用者拷貝或存成檔案，不會自動送出。三個平台的段落與名稱相同（`zt_core::health::report`、`HealthReport.swift`）：

- 開頭：產生時間、結果（全部正常或需要處理的項目數）、版本、系統、桌面（Linux）、架構。
- 檢查結果：每項一行，下面縮排列出它的詳細資料。
- 版本與資料：資料夾、每個資料檔與大小或「缺少」、建置時固定的資料版本、引擎與模型的載入時間（Linux／Windows 另有模型錯誤與 ONNX Runtime 的位置）。
- 安裝：程式的位置、擁有者與權限（macOS 另有隔離標記；Windows 是安裝資料夾哪些帳號可讀取與其中的檔案）、設定檔、使用者資料夾。
- 輸入法：macOS 是目前與已加入的輸入方式、自動切換成文件的輸入方式、安全輸入與開啟它的 App；Windows 是語言、輸入法清單、預設的輸入法、每個視窗各自記住輸入法、文字服務與智慧型應用程式控制；Linux 是 Fcitx 5 的狀態、版本、輸入法與鍵盤配置、輸入法相關的環境變數與工作階段。
- 服務：啟動時間與已執行多久；Linux／Windows 另有最近一次按鍵、連線數、回應時間與端點。
- 更新：自動檢查、上次檢查與結果、已下載的更新（macOS）。
- 改過的設定：和預設值不同的設定，以鍵名列出；只有開關、選項與數字寫出值，其他寫「（已設定）」。
- 顯示與輔助功能：螢幕縮放、主題、透明效果（Linux／Windows）、螢幕閱讀器、減少動態效果、高對比或增加對比、減少透明度（macOS）。
- 最近的錯誤：ZhuyinType 自己最近的警告與錯誤（Linux／Windows：這次執行中記在記憶體的最後 40 行，`zhuyintype --health` 向執行中的服務讀取；macOS：最近一小時的錯誤記錄）。

內容不含打的字、自訂詞、記住的字詞、改字記錄、前文、字詞或 App 的清單；其他 App 的名稱只出現在 macOS 的安全輸入（開啟它的 App 是這一項唯一的線索，送出前使用者看得到全文）。路徑中的家目錄寫成 `~`，其他地方的使用者名稱寫成 `<使用者>`。

設定視窗的對話框（Linux／Windows 的提示、程式授權與回報問題）一律有不透明的底色，透明效果開啟時也一樣。

匯出的檔案預設名稱為「ZhuyinType 個人資料.txt」，包含自訂詞、記住的字詞、個人連詞、不記住的字詞與按錯習慣。匯入的資料加到這台 Mac 現有的資料中，同一筆資料保留較強的記憶。「全部清除…」清除記住的字詞、個人連詞與按錯習慣，不記住的字詞保留。

#### 4.5.2 意見與問題

「關於 › 意見與問題」有「轉換或選字不對」「當機、沒反應或無法輸入」「其他問題」「建議」，各自在瀏覽器開啟 GitHub 對應的 issue form（`.github/ISSUE_TEMPLATE/`）；「診斷資料」開啟「檢查輸入法」的問題回報。入口另有輸入法選單的「回報問題…」、更新提示的「回報問題」、「更新內容」頁，以及問題回報視窗的「拷貝並到 GitHub 回報…」（先拷貝畫面上的文字，由使用者自己貼上）。

- **網址只帶**：範本名稱、ZhuyinType 的版本、系統名稱與版本（Linux 另有桌面與 X11／Wayland）與架構；移除時另有從清單選的原因。不帶打的字、字詞、App 名稱、路徑或帳號（`zt_core::feedback`、`Feedback.swift`，都有測試）。
- **由使用者送出**：App 不連線到 GitHub，只請瀏覽器開啟網址；需要 GitHub 帳號。診斷資料不放進網址，使用者看過全文後自己貼上或附檔。
- **範本**提示內容是公開的，不要貼私人文字；例句請改寫。不能直接開空白的 issue。

**移除的原因**都是選填，不影響移除：

- Windows：解除安裝程式最後一頁（原本就有的「ZhuyinType 已移除」）多一個「為什麼移除？（選填）」的清單，預設「不說明」。選了原因再按「完成」才開啟 `uninstall.yml` 的頁面。安靜解除安裝（`/S`）沒有畫面，不問；更新由安裝程式直接覆蓋，不執行解除安裝程式；由另一位系統管理員解除安裝時也不問（瀏覽器會以那個帳號開啟）。
- macOS 與 Linux：「關於 › 移除 ZhuyinType ›」列出移除的步驟與個人資料的位置，下方可以選原因。
- 不做的：Linux 套件的移除腳本以 root 執行、沒有使用者的畫面，不開視窗或瀏覽器，也不在套件管理員的輸出中留連結；macOS 的輸入法裝在 `/Library`，App 不以管理者權限刪除正在執行的自己；移除之後不在背景留下任何程式來詢問。

### 4.6 清單

清單頁（記住的字詞、自訂詞、在候選字視窗顯示組字的 App）和其他頁用同一套設計：上方固定的列寫出上一層與頁名（內容捲到下面時才出現材質與細線），下面一行工具列有搜尋、筆數（「共 21 個」）、排序與 ＋ 或「更多」，清單在標準的卡片中，每列是字詞、灰色的讀音與右邊安靜的資訊。清單是頁面本身捲動的一部分，沒有固定高度的內層捲動，視窗多高就顯示多少，列是延遲建立的，資料多時也流暢。指標移到某一列時，右邊的資訊換成「編輯」（自訂詞）與「刪除」，版面不動；也可以點選（⌘ 多選）後按 ⌫，或用右鍵選單。刪除時那一列收合、下面的列跟著上移；新增的列淡入；搜尋時列的出現與消失也有動畫。沒有資料或搜尋沒有結果時，卡片中寫一句簡短的說明。進入下一層時內容從右邊滑入 24 pt 並淡入（0.22 秒），返回時反過來；「減少動態效果」時只淡入淡出。



### 4.7 符號與 Emoji 面板

面板和候選字視窗一樣是不會成為主視窗或鍵盤焦點的 NSPanel（`.nonactivatingPanel`），同樣的材質、圓角與外觀設定，位置在游標下方（或依「位置」設定在上方，空間不夠時換到另一邊）。由上到下：

1. 搜尋列：放大鏡、搜尋的內容（沒有時以淡灰字寫「打注音或英文搜尋」；從組字帶入的內容以選取的底色標出），右邊是目前的類別名稱或搜尋結果的個數。
2. 類別：一列圖示（最近使用為時鐘，其他是類別中的一個代表符號），目前的類別以淡強調色底標出；說明標籤是類別名稱。
3. 符號：每列九個、一次六列，反白的符號以強調色圓角矩形標出；按 ↓ 進入格子後，反白的那一列標出 1–9（按鍵在搜尋列時不標）；滑鼠移過的符號以淡灰色標出。列數多於六列時右邊有捲動位置的細條。沒有搜尋結果時寫「沒有符合「…」的符號」。
4. 下方：反白（或滑鼠下）的符號與它的 CLDR 名稱，以及目前狀態的按鍵：搜尋列時「↓ 選取　Tab 類別　Esc 關閉」，格子時「1–9 選取　Tab 類別　Esc 關閉」。

每個符號與類別都是 VoiceOver 的按鈕，名稱是 CLDR 名稱；反白移動時，面板向 VoiceOver 宣告「（名稱），第 N 個，共 M 個，（類別）」，因為 VoiceOver 的游標留在 App 中。「動畫」開啟時面板出現時和候選字視窗一樣淡入；開啟「減少動態效果」時直接出現，沒有動畫。

Linux 與 Windows 的面板沿用候選字視窗的表面、邊框、陰影、出現的動態與深淺色；寬度固定（9 欄 × 36 px），高度固定 6 列，不隨類別跳動。反白用候選字的選取色，按 ↓ 進入格子後只有反白那一列標 1–9，下方右邊寫目前狀態的按鍵（「↓ 選取・Esc 關閉」或「1–9 選取・Esc 關閉」）與列數；類別標籤一次顯示放得下的幾個，並保持目前的類別可見。原生端畫的清單（Windows、Wayland）一律橫式，不顯示「單字／修正」開關。
