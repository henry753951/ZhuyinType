# ZhuyinType 產品設計

ZhuyinType 是開源、在本機運作的 macOS 注音輸入法。

本文件寫使用者看得到的部分：按鍵、狀態、預設值與介面。程式內部的流程見 [ARCHITECTURE.md](../engine/ARCHITECTURE.md)，演算法與模型見 [MODEL.md](../engine/MODEL.md)，尚未完成的項目見 [ROADMAP.md](../ROADMAP.md)。

## 1. 設計原則

1. 每個按鍵都即時回應。按鍵處理、整句轉換與模型推論都在主執行緒同步完成。模型只用 CPU，每次數毫秒。畫面一次更新到最終結果，個人資料在背景寫入。
2. 單一行程。輸入法、引擎與模型在同一個行程內直接呼叫，切換輸入方式快速而可靠。
3. 組字顯示在游標處。組字以 marked text 顯示；使用者可以指定個別 App 改在候選字視窗上方顯示組字。
4. 標準操作優先。Backspace 刪除游標前的一個字，方向鍵移動游標，選字鍵選取候選字。容錯與選字模型都沿用這套操作。
5. 設定集中。約 15 個選項依用途分頁，少用的選項放在「進階」。
6. 資料留在本機。輸入的文字與個人詞彙都在本機處理與儲存，記住的字詞可以檢視、移除、匯出與匯入。唯一的網路連線是檢查更新，每天一次，可以關閉。系統開啟安全輸入時（例如密碼欄位），輸入法不讀取游標前的文字，也不學習。「記錄改字」預設關閉，開啟後記錄也只存在這台 Mac（§2.7）。

## 2. 功能規格

### 2.1 組字與按鍵

按鍵依使用頻率分成四組，越常用的越靠近打字的手。方向鍵的規則只有一條：上下在清單裡移動，左右沿著句子移動。設定視窗的「快捷鍵」頁依目前的設定列出同一份表。

按鍵依美式鍵盤上的位置判斷。使用 ZhuyinType 時，鍵盤配置固定為 ABC。

#### 狀態

| 狀態 | 說明 |
|---|---|
| 英文 | 所有按鍵交給 App。單按 Shift 切回中文。從其他輸入法切換到 ZhuyinType 時，一律從中文開始（「開始輸入時使用英文」開啟時從英文開始）；只是換 App 或輸入框時，維持目前的中英模式。 |
| 中文，沒有組字 | 打注音、標點、⇧ 加字母或符號鍵、⌃ 加符號鍵或 ⌥ 加數字或符號鍵時開始組字，其他按鍵交給 App。 |
| 組字中 | 組字顯示在游標處，畫面即時顯示最佳整句。按 Return 送出。 |
| 候選字清單開著 | 由 ↓ 開啟；「空白鍵」設為「開啟候選字視窗」時空白也可以。選字後回到組字中。 |
| 選取中 | 由 ⇧← 或 ⇧→ 開始。候選字視窗顯示「↩ 加入自訂詞：」與選取的字，按 Return 加入自訂詞，按 Esc 取消選取。 |

候選字清單另有兩種，預設都不開，都用 Shift 加上下鍵切換：⇧↓「單字」只列一個字，⇧↑「修正」把按錯修正與模糊音的字排在前面。清單不使用 Option 組合鍵，因為很多 App 把 Option 組合鍵當成自己的快捷鍵，有的 App 會先於輸入法處理。候選字視窗下方顯示這兩個開關與它們的按鍵，開著時以強調色顯示，也可以直接點；關閉「單字與修正按鈕」後，開關只在開著時顯示。

#### 打字

| 按鍵 | 行為 |
|---|---|
| 注音鍵 | 拼注音。整句連續輸入，畫面即時顯示最佳整句。組字超過 60 個音節時，前面一段自動送出（§2.2）。 |
| 聲調鍵 6 3 4 7 | 二聲、三聲、四聲、輕聲。 |
| 空白 | 有未完成的注音時是一聲。沒有時依「空白鍵」設定：「送出並輸入空白」（預設）送出整段，再把空白交給 App；「輸入空白，不送出」在組字中加一個空白，繼續組字（和 ⇧空白 相同）；「開啟候選字視窗」開啟候選字清單。沒有組字時交給 App。空白從不確認選字：清單開著時翻頁。 |
| Return | 送出整段。 |
| ⌫ | 刪掉一個注音符號；沒有未完成的注音時，刪游標前的字。 |
| ⌦ | 刪游標後的字。 |
| ← → | 在組字中移動游標。 |
| Home、End | 游標移到組字的開頭或結尾。 |

#### 改字

| 按鍵 | 行為 |
|---|---|
| ↓（「空白鍵」設為「開啟候選字視窗」時，空白也可以） | 開啟候選字清單。 |
| 1–9（或 A S D F G H J K L） | 選取這一頁的候選字。 |
| Return | 選取反白的候選字。 |
| ↑ ↓（直式）、← →（橫式） | 移動反白。 |
| ← →（直式）、⌥← ⌥→ | 改前一個或後一個字。清單跟著移動，維持同一種清單。橫式的 ← → 移動反白，所以用 ⌥← ⌥→。 |
| 空白 | 下一頁。翻到最後一頁後回到第一頁。 |
| Tab、Page Down（fn ↓）、⌥↓，橫式另有 ↓ | 下一頁。 |
| ⇧Tab、Page Up（fn ↑）、⌥↑，橫式另有 ↑ | 上一頁。 |
| ↓ 在一頁的最後一個字、↑ 在第一個字 | 翻到下一頁的第一個字或上一頁的最後一個字；到清單的結尾停住，不回到第一頁。這是「到頁底時 ↓ 翻到下一頁」（預設開啟，`ComposerOptions.pageAtListEdge`）；關閉時停在頁底，由 Rust 引擎實作。 |
| Esc 或 ⌫ | 關閉清單。 |
| 其他按鍵 | 關閉清單，再照組字中的規則處理。 |

#### 其他清單

| 按鍵 | 行為 |
|---|---|
| ⇧↓ | 只列一個字。清單開著時切換。 |
| ⇧↑ | 列出按錯修正與模糊音的字，排在前面，用一般的方向鍵瀏覽；再按一次還原。點候選字視窗的「⇧↑ 修正」也一樣。「按錯鍵修正」為「關閉」且沒有開啟任何模糊音時，這個鍵開啟一般清單，清單開著時不作用。 |
| `` ` `` | 打出注音本身。清單開著時是反白的部分；有未完成的注音時是這些符號；其他時候是游標前的音節。點候選字視窗上方的注音也一樣。按錯時，緊接著再按一次 `` ` `` 或按 Esc，恢復成原本的注音與字。 |

#### 少用

| 按鍵 | 行為 |
|---|---|
| 單按 Shift | 中英切換。可設定為左右 Shift、左 Shift、右 Shift 或不使用。 |
| ⇧← ⇧→，再按 Return | 選取 1–6 個字加入自訂詞。組字保留在畫面上，不送出。 |
| Esc | 有未完成的注音時清除注音，再按一次清除整段組字。「Esc」設為「只清除注音」時，第二次不清除組字。緊接在 `` ` `` 之後按時，改為復原那次 `` ` ``。 |
| ⌥⌫ | 有未完成的注音時清除注音；其他時候刪游標前的一個詞。 |
| ⇧Return | 送出並換行。 |
| 符號鍵 | `[` `]` 是「」，`'` 是、，`\` 是＼，`=` 是＝。 |
| ⇧ 加數字鍵或符號鍵 | 依「標點按法」設定。Windows（預設）：打出鍵上印的半形符號，例如 ⇧ 加逗號鍵是「<」，⇧ 加減號鍵是「_」。macOS：全形標點，，。？：；！…『』——～（）＋｜＠＃＄％＆＊。 |
| ⌃ 加符號鍵 | 中文標點。⌃ 加逗號鍵是「，」，句點鍵是「。」，`'` 是「、」，`;` 是「；」；加 ⇧ 時，`/` 是「？」，`1` 是「！」，`;` 是「：」，`[` `]` 是「『』」，`9` `0` 是「（）」，`,` `.` 是「《》」，`-` 是「——」。其他符號鍵打出全形符號。⌃ 加數字鍵、字母、`[`、`]`、`/` 交給 App（終端機裡 ⌃[ 是 Esc）。兩種「標點按法」都可以用。 |
| ⇧ 加字母 | 大寫字母，放進組字。 |
| ⇧ 空白 | 在組字中放一個空白。 |
| 在標點上按 ↓ | 列出同類的標點，包括全形與半形，例如，、；：…。 |
| ⌥ 加數字鍵或符號鍵 | 打出鍵上印的符號。例如 ⌥ 加句點鍵是「.」，⌥⇧ 加句點鍵是「>」。主要用在「標點按法」為 macOS 時。 |
| Caps Lock | 開著時打英文，正在組的字先送出。系統設定以 Caps Lock 切換輸入方式時，由系統處理。 |

組字中沒有開啟清單時，↑、Tab、⇧Tab、Page Up、Page Down 不做事，也不交給 App。沒有組字時，這些鍵與 `` ` `` 都交給 App。按 ⌘ 組合鍵、沒有對應標點的 ⌃ 組合鍵、⌥ 加字母，或輸入法不處理的其他按鍵時，先送出組字，再把按鍵交給 App。

#### 自訂按鍵

打字用的鍵固定，包括注音鍵、聲調鍵、空白、Return、⌫、Esc 與方向鍵。下表的功能可以重新指定按鍵：點按鍵，再按下新的組合；按 Esc 取消。每個功能最多三個按鍵，以「A 或 B」顯示，任一個都有作用；可以加入、移除、還原成預設值。按鍵是一個鍵加上修飾鍵，不支援先後按兩個組合。使用者自己指定的按鍵優先：新版加入的預設按鍵若已被使用者指定給另一個功能，就留給那個功能，不算衝突。舊版儲存的按鍵若和當時的預設相同，讀取時換成新的預設。筆電上以 fn 打的鍵照鍵盤上印的顯示：fn ↑、fn ↓（Page Up、Page Down）可以設為「上一頁」「下一頁」的按鍵；fn ←、fn →、fn ⌫（Home、End、向後刪除）單獨按時是固定的打字鍵，加上修飾鍵才能指定。

| 功能（設定頁的文字） | 預設按鍵 |
|---|---|
| 只列一個字，再按一次還原 | ⇧↓ |
| 列出按錯修正的字，再按一次還原 | ⇧↑ |
| 打出注音本身 | `` ` `` |
| 下一頁 | Tab 或 fn ↓ 或 ⌥↓ |
| 上一頁 | ⇧Tab 或 fn ↑ 或 ⌥↑ |
| 改前一個字（清單開著時） | ⌥← |
| 改後一個字（清單開著時） | ⌥→ |
| 往左選取，再按 Return 加入自訂詞 | ⇧← |
| 往右選取，再按 Return 加入自訂詞 | ⇧→ |
| 刪掉一個詞 | ⌥⌫ |
| 送出並換行 | ⇧Return |

以下組合無法指定，設定頁會在按鍵旁說明原因：

- ⌘ 組合鍵：「⌘ 組合鍵留給 App」；
- 不加修飾鍵的方向鍵、空白、Return、Esc、⌫、⌦、Home、End、Page Up、Page Down：「這個鍵用在打字、選字或送出」；
- 不加修飾鍵的字母、數字與符號鍵（`` ` `` 除外）：「這個鍵用在打注音、聲調或標點」；
- ⇧ 加字母、數字或符號鍵：「Shift 加這個鍵打中文標點或大寫字母」；
- ⌥ 加數字或符號鍵：「Option 加這個鍵打鍵上印的符號」；
- 已指定給其他功能的組合：「已用於「（功能）」」。

「還原預設值」回到上表。功能改用其他按鍵後，原本的預設按鍵交給 App。候選字視窗、設定頁的說明文字、預覽與 ⓘ 示範都顯示目前指定的按鍵，改了快捷鍵立即更新。

兩個功能用到同一個按鍵時（例如從舊版移轉，或重新開啟一個功能之後），兩個按鍵都以紅色標出，並寫出另一個功能的名稱；「快捷鍵」頁最上方列出所有衝突。同一個按鍵只有一個功能會作用。

舊版每個功能存一個按鍵（`shortcuts`）；讀取時當成只有一個按鍵，第一次修改後改存成按鍵清單（`keyBindings`）。

#### 可以關閉的功能

下列功能可以在「快捷鍵」頁取消勾選。關閉時，它的按鍵交給 App（有組字時先送出），其他按鍵不受影響；預設全部開啟。關閉功能只在 App 這一層處理，引擎不變。

| 功能 | 關閉時 |
|---|---|
| 打出注音本身（含緊接著再按或 Esc 恢復） | `` ` `` 交給 App |
| 點注音列打出注音 | 點候選字視窗上方的注音不做事；「顯示注音」關閉時這項沒有作用 |
| 只列一個字 | ⇧↓ 交給 App；候選字視窗下方不顯示「單字」 |
| 列出修正的字 | ⇧↑ 交給 App；候選字視窗下方不顯示「修正」 |
| 選取加入自訂詞 | ⇧← ⇧→ 交給 App |
| 翻頁（Tab、⇧Tab、⌥↓、⌥↑） | 這些按鍵交給 App；空白、Page Up、Page Down 仍然翻頁 |
| 刪掉一個詞 | ⌥⌫ 交給 App |
| ⌃ 加符號鍵打中文標點 | ⌃ 組合交給 App |
| ⌥ 加數字或符號鍵打鍵上的符號 | ⌥ 組合交給 App |
| Caps Lock 打英文 | Caps Lock 開著時仍打注音，也不顯示「中」「英」 |
| 送出後刪掉重打 | 送出後按 ⌫ 只交給 App：不算改字，下一段從句首選字 |
| 單按 Shift 切換中英 | 等同「切換鍵」設為「不使用」；再開啟時恢復原本選的 Shift |

「列出修正的字」在「按錯鍵修正」關閉且沒有開啟模糊音時，這個鍵開啟一般清單；「快捷鍵」頁在這一列寫出原因。

#### 要改哪個字

游標在句尾時，清單改最後的字詞。游標移到句中時，↓ 要改的字先以強調色粗底線標出；預設是游標右邊的字，可在「游標在句中時改」改成左邊。游標在開頭時一律改右邊的字。

清單開著時，正在改的部分以強調色粗底線加淡色底標出。反白移到不同長度的詞時，標出的範圍跟著改變。

#### 候選字清單的內容

- 一般清單只列照按鍵打出的詞與字。從要改的字開始，長的詞在前（最多 6 個字），再來是較短的詞，最後是單字；同樣長度的依前後文排序。
- 第一個是目前畫面上顯示的寫法。
- 清單只列詞庫的詞、自訂詞、記住的字詞與單字，不把轉換結果的片段拼成新詞。
- 「台」與「臺」兩種寫法的同一個詞只列一次，以設定的寫法顯示。
- 清單保留所有候選，每頁 3–9 項（「每頁的候選字」，預設 9），用選字鍵的前幾個選取。
- 修正清單把按錯修正與模糊音的字排在前面，其後是一般清單的內容。修正過的字旁邊以灰字標出修正後的注音。
- 在標點上開啟的清單列出同類的標點。

#### 選字後

在清單選了候選字後，畫面上其他的字詞維持原樣，和系統內建的注音輸入法相同。選的字在一個較長的詞中間時，這個詞在它前面的字也維持原樣；後面的字可能跟著選的字一起改對。之後只有新打的字依前後文調整。

| 字詞 | 記住選過的字詞 | 開、關 | 開 |
| 進階 | 記錄改字 | 開、關 | 關 |
| 進階 | 一併記錄游標前的文字 | 開、關（「記錄改字」開啟時才能切換） | 關 |
| 進階 › 在候選字視窗顯示組字的 App | App 清單 | App 清單 | 空白 |
| 關於 | 自動檢查更新 | 開、關 | 開 |
| 關於 | 自動安裝更新 | 開、關 | 開 |

「快捷鍵」頁的預設值見 §2.1 的「自訂按鍵」。

固定的上限：一段組字最多 60 個音節；一個詞最多 6 個字。

組字已有 60 個音節時再打一個字，前面一段先自動送出，其餘留在組字中，這個字照常打出：

- 最後一個標點（。！？，、；： 等）之後剩下 40 個音節以內時，送到那個標點為止；否則送出前面約 20 個音節，在詞與詞之間斷開，不拆開一個詞。
- 送出的就是畫面上的字，包括選過的字；和按 Return 送出一樣記住選過的字詞，也是後面組字的前文。畫面上留下的字維持原樣。
- 游標在組字中間時，只送出游標前的部分；游標在開頭時先不送出，這段組字暫時多於 60 個音節。

### 2.3 容錯輸入

- 自動處理按到相鄰鍵、多按一鍵、漏按一鍵、兩鍵順序打反（在同一個音節內或跨音節）、三聲與四聲互換、二聲與輕聲互換，以及一聲沒按空白就打下一個字。
- 幾乎同時按下（35 毫秒內）的兩鍵，順序打反或多按一鍵的修正成本很低；分開按的鍵視為刻意這樣打。
- 照按鍵打出的整句優先。修正過的整句，分數（引擎分數加上整句重排模型的分數）要比最好的未修正整句高 4.0 以上，才成為首選。
- 修正過的字詞列在修正清單（⇧↑，或點候選字視窗的「⇧↑ 修正」），旁邊以灰字標出修正後的注音。畫面上目前顯示的寫法若是修正過的，也列在一般清單的第一項。
- 選了修正過的字詞，就記住「哪個鍵常按成哪個鍵」，同樣的錯之後更容易修正。
- 「按錯鍵修正」設定：「關閉」只切分音節，按鍵照打出的解讀；「標準」；「積極」的修正成本為「標準」的 70%。
- 「接受常見的其他讀法」（預設開啟，在「選字 › 按錯鍵」）：照常見的另一種念法打也找得到要的詞。輕聲照本調或其他念法打（有什麼 打 ㄧㄡˇ ㄕㄣˊ ㄇㄚˊ）、詞裡的字照台灣讀音打，算是打對，不標注音；有邊讀邊（和睦相處 打 ㄏㄜˊ ㄌㄨˋ ㄒㄧㄤ ㄔㄨˇ）算是修正，修正過的整句要比照按鍵打的最好整句高 4.0 以上才成為首選，旁邊以灰字標出字典的讀音。每個詞最多一個字用其他讀法；單字詞與三聲變調不在內。關閉後只照字典的讀音找詞。

### 2.4 選字

- 整句轉換：詞庫、語言模型與音節對字模型一起在詞圖上找出分數最高的整句，再由整句重排模型依游標前的文字，從前 16 句中重新挑選。
- 語言模型有聊天用語與百科用語兩個。沒有前文時以聊天為主，例如打 ㄏㄨㄛˋ ㄕˋ 是「或是」。游標前的文字或最近在這個 App 打的字偏向書面用語時，百科的比重跟著提高。
- 游標前的文字：組字開始時向 App 讀取最多 128 個字，之後送出的字接在後面，最多保留 255 個字。音節對字模型讀全部，整句重排模型讀最後 24 個字。App 不提供時，改用同一個 App 在 10 分鐘內送出的字。這段文字只放在記憶體中。關閉「參考游標前的文字」後，不向 App 讀取，也不保留各 App 送出的字。
- 「台／臺」：預設寫「台」，可在「選字」改成「臺」。模型與詞庫內部照原本的字選字，只有顯示、候選字清單與送出的文字換成選定的寫法。
- 模糊音：ㄗ／ㄓ、ㄘ／ㄔ、ㄙ／ㄕ、ㄣ／ㄥ、ㄢ／ㄤ，可逐項開啟。開啟的兩個音互相通用。兩個詞同樣常用時，讀音完全符合的排在前面；另一個詞明顯更常用時才換上。
- 「一」「不」打變調後的讀音也找得到，例如一直打 ㄧˋ ㄓˊ、不要打 ㄅㄨˊ ㄧㄠˋ。罕用讀音的分數較低，例如「說」打 ㄕㄨㄟˋ 時「睡」排在前面。
- 自訂詞在選字時優先列出。
- 一段組字送出後，下一段接著前面送出的詞選字。按了交給 App 的鍵、點進文字、切換輸入框、中英切換或打了標點之後，下一段重新當作句首。

### 2.5 個人記憶

| 記住什麼 | 怎麼用 | 什麼時候學 |
|---|---|---|
| 選過的字詞 | 同樣的讀音再打一次時，直接採用選過的寫法。範圍包括整段組字、選字處前後的幾個音節、修正過的字與詞庫沒有的詞。 | 手動選字；送出後刪掉重打 |
| 個人的一、二、三連詞 | 調整語言模型，反映你在某個詞後面常接什麼。 | 每次送出。手動選的字詞權重高，直接送出的權重低。 |
| 被換掉的寫法 | 選字時被換掉的寫法，以及送出後 30 秒內刪掉重打的舊寫法，在原本的前文中個人統計減半。 | 選字時；送出後 30 秒內刪掉重打 |
| 按錯習慣 | 常把哪個鍵按成哪個鍵，修正成本跟著降低。 | 選了修正過的字詞 |

以前在同樣位置選過的字詞會保留，整句重排模型只在保留這些字詞的整句之間挑選。「同樣位置」指接在同一個詞後面；兩個字以上的詞，在任何位置選過都算。

- 短期與長期：選過的字詞與個人連詞都同時有 8 小時與 90 天兩種半衰期。手動選過 3 次以上的保留最低分數。
- 容量：選過的字詞約 20,000 筆，個人連詞 50,000 筆。滿了先刪分數最低的。
- 設為「不記住」的字詞，之後送出也不學。關閉「記住選過的字詞」後停止學習；系統開啟安全輸入時暫停學習。
- 記住的字詞在設定的「字詞 › 記住的字詞」管理，見 §4.5。

### 2.6 其他

- 自訂詞：在設定的「字詞 › 自訂詞」加入，或在組字中用 ⇧← ⇧→ 選取 1–6 個字後按 Return。加入後馬上生效。
- 標點預設為全形（見 §2.1），在標點上按 ↓ 可換成同類的其他寫法。
- 中英混打、Emoji、符號表與繁簡輸出尚未提供，見 [ROADMAP.md](../ROADMAP.md)。

「空白鍵」以前另有「送出文字」（送出整段，不輸入空白）；這個選項已移除，存著它的設定讀取時改為「送出並輸入空白」，舊版的開關設定也一樣對應。

### 2.7 改字記錄

「進階」頁的「記錄改字」開啟後，每一段有改字的組字在送出時記成一行，供改進引擎使用：重播當時的按鍵，看引擎現在能不能不靠改字就打對（`zt eval corrections`，見 [EVALUATION.md](../ml/EVALUATION.md)），以及統計常見的按錯與改字（`zt data corrections`）。

算作改字的情況：

| 改字 | 記錄的事件 | 什麼時候算 |
|---|---|---|
| 從候選字清單選字（一般、⇧↑ 修正、⇧↓ 單字） | `pick` | 選字改變了畫面上的字 |
| ⌫ 或 ⌥⌫ 刪掉注音或轉好的字，再打 | `backspace` | 刪掉之後接著打字 |
| Esc 清除注音或整段組字，再打 | `escape` | 清除之後接著打字；清除整段後 30 秒內再打的組字算同一筆 |
| `` ` `` 把字改成注音本身，以及立刻再按 `` ` `` 或 Esc 還原 | `literal_zhuyin`、`undo_literal` | 一律 |
| ⇧← ⇧→ 選取，按 Return 加入自訂詞 | `select`、`add_phrase` | 一律；加入自訂詞要成功 |
| 游標移進句中之後修改 | `cursor`，加上標為 `mid` 的打字或刪除 | 在句中打字或刪除 |
| 送出後 30 秒內按 ⌫ 刪掉剛送出的字，再打一段 | `delete_after_commit` | 新的一段開頭和刪掉的字不同 |

沒有改字的組字不記錄。每一筆記錄是一個 JSON 物件（`schema` 1）：

| 欄位 | 內容 |
|---|---|
| `schema`、`id`、`date`、`app_version` | 格式版本、隨機編號、日期（只到日）、App 版本 |
| `settings` | 影響按鍵結果的設定：按錯鍵修正、接受常見的其他讀法、模糊音、標點按法、空白鍵、台／臺、游標在句中時改、選字鍵、排列、記住選過的字詞、參考游標前的文字 |
| `context` | 引擎讀到的游標前文字（最多 255 個字），只在開啟「一併記錄游標前的文字」時記錄 |
| `keys` | 每個按鍵與點按，以 `zhuyin-cli` 批次語法寫成，第二個鍵起前面加 `<dt:毫秒>`。點選候選字寫成那一頁同位置的選字鍵，⇧↑ 修正按鈕寫成 `<sup>`，其他方式送出（點進文字、切換中英、⌘ 組合鍵）寫成 `<enter>` |
| `typing`、`replayable` | 打出最後那段組字的按鍵：不含清單的按鍵與選字，刪掉重打的部分只留重打的鍵；重播時在後面加 `<enter>`。在句中修改過、或有 `zhuyin-cli` 寫不出的鍵（⌥ 或 ⌃ 加 `>`）時，`replayable` 為 false |
| `original_typing`、`original_replayable` | 第一次打的按鍵：把每次 ⌫、Esc 的改字換回刪掉的鍵 |
| `shown` | 第一次改字之前畫面上的字；組字超過 60 個音節、前面一段已自動送出時，前面加上已送出的字 |
| `committed` | 送出的字。組字超過 60 個音節時前面一段會自動送出，同一段組字仍是一筆記錄，這裡是全部送出的字；重播 `typing` 時也一樣分段送出 |
| `corrections` | 這一段有哪幾種改字，依第一次出現的順序 |
| `events` | 依序的事件，每個有 `type`、`t`（從第一個鍵起的毫秒數）與 `shown`（事件之後畫面上的字），其他欄位依種類而定：`type`（連續打的鍵）、`open_list`、`switch_list`、`close_list`、`pick`（`before`、`after`、`start`、`removed`、`inserted`、`rank`、`list`、`via`）、`backspace`／`escape`（`shown_before`、`removed`、`deleted_keys`、`retyped_keys`、`replaced_by`、`cleared`）、`literal_zhuyin`、`undo_literal`、`cursor`（`position`）、`select`、`cancel_select`、`add_phrase`（`phrase`、`added`）、`delete_after_commit`（`deleted`、`previous_committed`、`previous_typing`、`previous_replayable`）、`commit`（`text`；自動送出前面一段時 `shown` 是留下的組字） |

`deleted_keys` 是刪掉的字當初打的鍵，`retyped_keys` 是之後補打、直到組字回到原本長度的鍵，例如打 `1j6`（ㄅㄨˊ）刪掉後改打 `1j4`（ㄅㄨˋ）。刪掉的鍵依畫面回推：回到上一次畫面有同樣多的字與注音的時候；在句中刪除時無法回推，記為空。

            {"deleted_keys": "1j6", "removed": "不", "replaced_by": "步", "retyped_keys": "1j4", "shown": "你",
             "shown_before": "你不", "t": 900, "type": "backspace"},
            {"keys": "1j4", "shown": "你步", "t": 1350, "type": "type"},
            {"shown": "", "t": 1500, "text": "你步", "type": "commit"}],

隱私：

- 預設關閉；關閉後立即停止記錄，正在打的那一段也不記錄。
- 系統開啟安全輸入時（密碼欄位）不記錄，已開始的那一段也捨棄。
- 游標前的文字只在開啟「一併記錄游標前的文字」時記錄。
- 不記錄在哪個 App 打字，也不記錄時刻，只記日期。
- 檔案是 `~/Library/Application Support/ZhuyinType/corrections.jsonl`，只有使用者本人可以讀（權限 600），在背景佇列逐行附加，結束程序前寫完；輸入法只在這台 Mac 上讀寫它。設定頁可以在 Finder 中顯示、匯出與清除。

### 2.8 使用統計

「分析」頁的「記錄使用統計」（預設開啟）計算這台 Mac 的打字次數與輸入法的反應時間，只記錄數字：

| 計數 | 內容 |
|---|---|
| 送出的字、組字、按鍵 | 送出的字數（含標點）、送出的組字數與其中一次就對的組字數、組字中由輸入法處理的按鍵數 |
| 從清單選字 | 依清單分：一般、修正（⇧↑）、單字（⇧↓）、標點；按選字鍵、Return 或點選 |
| 改字 | 組字中按 ⌫ 或 ⌥⌫、Esc 清除、送出後 30 秒內刪掉（每次送出最多算一次）、打出注音本身、恢復成原本的字 |
| 自動修正 | 整句有按錯修正的字的組字數：出現過的、送出時仍是修正後寫法的（由整句重排模型挑選的整句判斷；沒有這個模型時不計） |
| 加入自訂詞 | 打字時選取後加入的次數 |
| 按鍵反應 | 從輸入法收到按鍵到組字與候選字視窗更新完成的時間，記成分布（1 毫秒到 1 秒的 21 個區間）與最慢的一次 |

- 總數與每天一筆，保留最近 60 天。全部在記憶體中累加；`~/Library/Application Support/ZhuyinType/stats.json`（只有使用者可讀，一個小檔案）每 10 分鐘最多寫入一次，另在切換到其他輸入方式、打開設定視窗與結束程式時寫入，沒有變動就不寫。寫入在背景進行。
- 不記錄打的字、讀音、按了哪些鍵、App 名稱或 bundle ID。系統開啟安全輸入時（密碼欄位）不計數。
- 計數在 App 這一層觀察組字的結果（`UsageStatsObserver`），不改引擎。每個按鍵的成本固定：兩次讀時間、幾個整數相加與固定大小陣列的累加，不配置記憶體；自我測試量測每個按鍵的成本，超過 2 微秒即失敗（目前約 45 奈秒）。沒有在背景執行的計時器；CPU、記憶體與耗電只在「分析」頁顯示時每 2 秒讀一次。
- 「分析」頁寫出：「統計只在記憶體中累加，每 10 分鐘最多寫入一次，不影響打字。」

打字節奏（只算數字）：

| 項目 | 怎麼算 |
|---|---|
| 打字速度 | 送出的字數 ÷ 打字時間（字/分鐘）。打字時間只算連續打字中兩鍵之間的時間 |
| 打字時間、思考停頓 | 兩鍵間隔不超過停頓門檻時算打字；超過門檻、不超過 1 分鐘算思考停頓；超過 1 分鐘兩者都不算。門檻為「平常兩鍵間隔中位數的 4 倍」，至少 2 秒，在每次使用（輸入法這次被選用）開始時決定，之後不變 |
| 最長連續 | 一段連續打字（中間沒有超過門檻的停頓）送出的最多字數；另記沒有任何改字的最長一段 |
| 一次就對 | 送出的組字中，沒有選字、⌫、Esc 或 `` ` `` 的比例；清除後重打的算同一次 |
| 每個字按幾個鍵 | 按鍵數 ÷ 送出的字數，包含改字的按鍵 |
| 什麼時候打字 | 一週七天 × 24 小時送出的字數 |
| 思考停頓的中位數 | 停頓長度分布的中位數 |
- 關閉時不計數；「清除統計…」確認後刪除檔案與所有計數。

「效能」另外顯示這個程式本身的數字，不儲存：CPU 時間（`getrusage`）、目前與最高的記憶體（`proc_pid_rusage`）、耗電（`proc_pid_rusage` 的 `ri_energy_nj`，macOS 的估計；系統沒有提供時寫「macOS 沒有提供」），以及詞庫、整句重排與逐字模型上次載入的時間。

預設開啟的理由：只有次數與時間，不含任何文字，資料不離開這台 Mac；關閉時「分析」頁沒有內容可看。

## 3. 系統整合

完整的逐鍵流程、分數公式與模型位置見 [ARCHITECTURE.md](../engine/ARCHITECTURE.md)。這裡只列和 macOS 文字客戶端有關的規則。

### 3.1 行程

輸入法、引擎與模型在同一個行程內直接呼叫。引擎與模型在背景載入。載入期間打的文字鍵（不含 ⌘、⌃、⌥ 組合鍵，最多 64 個）先保留，載入完成後依序送進組字。英文模式下的按鍵與組合鍵直接交給 App。載入失敗時，保留的按鍵照原本的字元交給 App。

### 3.2 文字客戶端

| 項目 | 做法 |
|---|---|
| 組字 | 透過 `setMarkedText` 傳遞，只在文字、游標或底線改變時更新，網頁引擎型 App 也一樣。 |
| 浮動組字 | 「進階 › 在候選字視窗顯示組字的 App」清單中的 App（依 bundle ID），組字顯示在候選字視窗上方，預設清單是空的。 |
| 重複的按鍵事件 | 同一個按鍵、時間戳記相同的事件只處理一次。 |
| 單按 Shift | `flagsChanged` 依實體按鍵狀態判斷，0.35 秒內放開，且期間沒有按其他按鍵或修飾鍵，才算單按。相同狀態的事件合併處理。焦點不在可以輸入文字的地方時（遊戲、沒有文字欄位的視窗：App 回報不出選取範圍、組字範圍或游標所在的行），單按 Shift 不切換中英，也不顯示「中」「英」提示；Caps Lock 的提示也一樣。 |
| 點進文字 | App 要求結束組字時（例如點進文字），送出組字，下一段當作句首。 |
| 候選字視窗位置 | 依序採用組字起點的行高矩形、游標前的組字、組字起點、選取範圍、上一次有效位置、滑鼠位置。視窗依「位置」放在該行下方（預設）或上方，空間不足時換到另一邊，並一律留在螢幕內。 |

### 3.3 資料與設定

- 內建資料：詞庫與兩個語言模型在建置時編譯成二進位檔（`lexicon.bin`、`lm/lm.bin`、`lm_chat/lm.bin`），執行時以 mmap 對應，不佔行程本身的記憶體。目錄裡放 TSV 也能讀。
- 個人資料：`~/Library/Application Support/ZhuyinType/` 下的 `user_phrases.tsv`、`learned.tsv`、`excluded.tsv`、`typos.tsv`、`personal_ngrams.tsv`，在背景以原子寫入更新。
- 替換用的資料與模型：放在 `~/Library/Application Support/ZhuyinType/Models/`，見 §3.5。
- 改字記錄：開啟「記錄改字」時，同一個資料夾的 `corrections.jsonl`，在背景逐行附加，見 §2.7。
- 設定：存在 UserDefaults。

### 3.4 自動更新

自動更新使用 Sparkle，每天向 GitHub 上的 `appcast.xml` 檢查一次。appcast 與更新檔都以 EdDSA 簽章驗證，並盡量下載差分更新（只下載改變的檔案）。

輸入法很少結束，所以下載的更新不等程式結束才安裝，而是在所有輸入框都沒有組字時安裝並換上新版。每次按鍵後與每 5 秒各確認一次。

相關選項在設定視窗「關於」頁的「更新」區塊：

- 「自動檢查更新」，預設開；
- 「自動安裝更新」，預設開，關閉「自動檢查更新」時無法切換。關閉時，背景檢查找到新版本後以 Sparkle 的視窗詢問；
- 「檢查更新」列的「立即檢查…」按鈕，開啟 Sparkle 的視窗。

區塊下方的說明列出已下載、等待安裝的版本與上次檢查的時間。沒有設定更新來源的開發版不顯示這個區塊。

### 3.5 更新後換版

輸入法以 FSEvents 監看 app 所在的資料夾與模型目錄（`~/Library/Application Support/ZhuyinType/Models/`），檔案變動停止 2 秒後才處理。

- 裝了新版 app（版本號或執行檔改變）時，等所有輸入框都沒有組字就結束行程，下一個按鍵由 macOS 啟動新版。中英模式保留，不需要登出。
- 模型目錄裡放了新的資料或模型時，在背景載入。`lexicon.bin` 或 `lexicon.tsv` 連同 `lm/`、`lm_chat/` 為一組，`reranker/` 與 `v3/` 各自獨立。載入完成後，各輸入框在組字結束時換用新的，行程不重新啟動。移走這些檔案就換回 app 內建的。
- 載入期間打的文字鍵依 §3.1 的規則保留。
- 每個 app 附 `manifest.json`，記錄版本與每個資料、模型檔的 SHA-256。

## 4. 介面

整體採用 macOS 26 之後的系統設計語言。App 以 macOS 27 SDK 建置，並在執行檔標記實際使用的 SDK 版本，系統因此以目前的樣式繪製所有標準控制項。最低系統需求為 macOS 14。

### 4.1 候選字視窗

候選字視窗是 NSPanel，圓角 14 pt。背景在 macOS 26 以上為 Liquid Glass（`NSGlassEffectView`），較舊的系統為 popover 材質；系統開啟「減少透明度」時由系統改用不透明的背景。反白的候選字以強調色圓角矩形標出，滑鼠移過的候選字以淡灰色標出。點一下候選字即選取。

「視窗與提示」頁可以調整：

- 版面：排列（直式、橫式）、字級（13–28 pt）、每頁的候選字（3–9）、選字鍵、間距（標準、緊湊；緊湊的列高與邊距較小）；
- 內容：顯示注音、標出修正的讀音、單字與修正按鈕；
- 位置與外觀：位置（游標下方、游標上方）、外觀（跟隨系統、淺色、深色，也套用到中英切換提示）、動畫。

「動畫」開啟時，候選字視窗出現時以 0.12 秒淡入並向游標方向移動 4 pt；系統開啟「減少動態效果」時只淡入。之後的更新與關閉都立即完成。

翻頁（Tab、fn ↓、⌥↓、清單中的空白、在最後一個字按 ↓ 等）時，反白固定在原位不動；舊的一頁的字沿著清單的方向移出 10 pt，在前 0.05 秒淡出，新的一頁的字從另一邊移入，從 0.04 秒開始淡入，0.14 秒時就位（ease-out），兩層字不會同時清楚可見：直式清單下一頁往上、上一頁往下，橫式清單左右移動。頁碼同時淡入淡出。按鍵一律立即處理，反白立即出現在新的一頁；動畫進行中再翻頁，會直接從新的一頁開始，不排隊。在第一頁或最後一頁翻頁停住時，清單往翻頁的方向輕推 3 pt 再回來。同一個清單翻頁時視窗大小不變：寬度保持翻過的頁中最寬的，直式清單保留一整頁的高度。「動畫」關閉時不做任何動態；「減少動態效果」時只淡入淡出，停住時以短暫變淡代替輕推。

由上到下依序為：

1. 提示：需要時顯示一行，例如「↩ 加入自訂詞：」加上選取的字、「已加入自訂詞：」加上加入的詞，或「自訂詞需為 1 到 6 個字」。只有提示時，視窗是一個小圓角框。
2. 浮動組字：只在「在候選字視窗顯示組字的 App」中顯示，加底線。
3. 注音：要改的部分的注音，前面是 `` ` `` 的按鍵圖示。點一下打出注音本身。標點的清單不顯示這一列；關閉「顯示注音」時也不顯示。
4. 候選字：每一列前面是選字鍵。修正過的候選字旁邊以灰字標出修正後的注音（可關閉「標出修正的讀音」）。
5. 下方：「⇧↓ 單字」與「⇧↑ 修正」兩個開關，以及頁碼與 ‹ › 翻頁按鈕。開關開著時以強調色顯示，可以點。「⇧↑ 修正」只在可以修正時顯示；關閉「單字與修正按鈕」時，開關只在開著時顯示。只有一頁且沒有開關時，不顯示這一列。

按鍵圖示依目前的快捷鍵設定顯示。

### 4.2 中英切換提示

中英切換時，在游標旁以同樣的材質顯示「中」或「英」0.8 秒，再以 0.2 秒淡出（關閉「動畫」時在 1 秒後直接消失）。在中文模式下打開或關閉 Caps Lock 時也顯示，切換到其他輸入方式時立即消失。位置與外觀跟著候選字視窗的設定。可以在「打字」頁關閉「中英提示」。

### 4.3 圖示

App 圖示採用 Icon Composer 格式（`platforms/macos/Resources/AppIcon.icon`）：藍色背景加上一層玻璃材質的「ㄓ」字形，字形取自 PingFang TC。淺色、深色與透明外觀由系統繪製。圖示由 `platforms/macos/scripts/make_icons.swift` 產生，並以 actool 編譯。

輸入法圖示是 16 × 16 pt 的正方形，圓角 2.5 pt，鏤空一般字重的「ㄓ」，比例與系統內建的輸入法圖示相同。圖示為 template 向量 PDF，選單列、輸入法選單與游標旁的指示器由系統著色。輸入方式的名稱為「注音 ZhuyinType」。

### 4.4 輸入法選單

選單列的輸入法選單有「設定…」「自訂詞與學到的詞…」「關於 ZhuyinType」三項，都開啟設定視窗。

### 4.5 設定視窗

設定視窗的架構見 [SETTINGS_IA.md](SETTINGS_IA.md)。版面與系統設定相同：左側是原生 source list 側欄（彩色圖示），以小灰字的段落標題分成「概覽」（介紹、分析）、「輸入」（打字、選字、字詞）、「外觀」（視窗與提示）、「一般」（快捷鍵、進階、關於）；右側是 SwiftUI 分組表單。各頁的設定與預設值見 §2.2。第一次打開時顯示「介紹」，之後回到上次的頁面（舊版的「一般」「前文」「自訂詞」「記住的字詞」對應到新的頁面）。

- **下一層**：以「›」結尾的列開啟下一層頁面，列上顯示目前的狀態（例如「模糊音　已開啟 2 項」）。下一層的上方是「‹ 上一層」與頁名，⌘[ 也回到上一層。
- **設定列**：每一頁、下一層、總覽、分析與進階都用同一個列元件。左邊是名稱，下面可以有換行的說明；右邊依序是值、控制項，有 ⓘ 或 › 時接在最後；每一列的右邊一組都結束在卡片內容的右緣，不留空白的欄位。右邊整組對左邊整組垂直置中。縮排的子列（功能下的「快捷鍵」「往左選取」）用同一個元件，只把左邊內縮固定的距離，右緣和上一列的開關相同。開關、選單、按鍵圖示、› 與 ⓘ 在每一頁大小相同；文字按鍵與符號按鍵同高、同基線。
- **間距**：所有間距是 `RowMetrics` 中的常數，每一頁共用：頁面左右 20 pt、卡片最寬 700 pt（較寬的視窗置中）；卡片內左右各 16 pt，每列上下各 10 pt，分隔線的左右也是 16 pt；段落標題與卡片、卡片與頁尾說明相距 7 pt，段落之間 22 pt；段落標題、頁尾說明與下一層的頁名都對齊卡片內容的左緣。分析與介紹的磚塊本身就是小卡片，直接放在頁面上（不再包一層卡片），內距 14 pt、間距 10 pt。UI 預覽會量每一列與每一張卡片：右邊一組沒有置中、一列的左右內距不同，或卡片第一列上方與最後一列下方的空間不同，都會失敗；並畫出格線（名稱的左緣、右邊一組的右緣、每列的中線、卡片的外框與內容邊界）。
- **功能與按鍵**：有按鍵的功能佔兩列以上：先是功能列（名稱、說明與開關），說明可以換行；下面縮排一列「快捷鍵」（有兩個動作時各一列，例如「往左選取」「往右選取」），放按鍵欄位；按鍵和預設不同時，欄位前有文字按鈕「還原預設」，相同時不顯示。功能關閉時不顯示按鍵列，功能列寫出按鍵交給 App。被其他設定關掉的功能，說明寫原因並連到那個設定。頁尾有一個文字連結「在快捷鍵總覽中查看全部按鍵」。
- **到達提示**：每一個連到某一列的連結（總覽的列、按鍵衝突、「已關閉 ›」、介紹的卡片與摘要、「在快捷鍵總覽中查看全部按鍵」、下一層的 ›、變暗功能的原因）用同一個提示：切換頁面，捲到目標約在上方三分之一（段落標題與目標列都看得到），目標列的底色以強調色約 17% 亮一次（0.2 秒淡入、停 0.8 秒、0.8 秒淡出），所在段落的標題同時變成強調色；目標是整個段落時，整張卡片一起亮。不畫外框，不改變版面。「減少動態效果」時不做捲動動畫，只淡入淡出。
- **指標移過不改變版面**：指標移過時才出現的控制項（例如「＋」）一直佔著位置，只改變透明度；錄製、接受、拒絕與「還原預設」也不改變欄位的高度。只有狀態改變（例如出現按鍵衝突）時才加入一行說明。自我測試量欄位在平常、指標移過與錄製時的高度，必須相同。
- **說明**：每個設定一段說明，隨選項改變。ⓘ 以小示範呈現每個選項的效果，目前的選項標為「目前的設定」：空白鍵、Esc、標點按法、游標在句中時改、按錯鍵修正、記住的字詞、記錄改字、使用統計。「減少動態效果」時示範先停在結果，游標不閃爍。
- **按鍵欄位**：同一個元件用在每一處。每個按鍵組合是一個按鍵圖示，修飾鍵在裡面（「⌃]」「⇧Tab」「fn↓」）；同一個動作的幾個按鍵就是幾個圖示，不寫「或」（VoiceOver 與工具提示仍說「或」）。平常只有按鍵：指標在這一列上時，按鍵左邊出現虛線的「＋」（新增按鍵），和預設不同時再左邊出現「還原預設」；指標在某個按鍵上時，那個按鍵的右端出現 ✕，按鍵不變大。這些都一直佔著位置或疊在上面，所以版面不動。沒有按鍵時平常是淡淡的「—」，指標移過時變成「＋ 新增按鍵」。點一下按鍵錄製：按鍵變成強調色外框，裡面即時顯示按住的修飾鍵與閃動的游標，Esc 取消；接受時輕輕彈一下，拒絕時輕微晃動並在下方插入一行紅字；「減少動態效果」時改成淡入淡出。鍵盤：按鍵可以取得焦點，⌫ 刪除；右鍵選單有改按鍵、新增按鍵、刪除、還原預設。和其他動作重複的按鍵以系統紅色標出，下方寫「也用於「（動作）」」並附「改按鍵」「前往」。按鍵多時換行並靠右對齊。按鍵和預設不同的列，名稱前有一個強調色小點（工具提示「已自訂」）。「快捷鍵」總覽每列最多顯示兩個按鍵，其餘以「+N」表示，指標移到或點「+N」時展開，離開這一列時收起；功能頁顯示全部按鍵。每個動作最多五個按鍵；預設的按鍵也可以刪除，可以關閉的功能可以沒有按鍵，「送出並換行」「改前一個字」「改後一個字」至少留一個。

| 視窗與提示 | 最上方是一個預覽，畫的是真正的候選字視窗（同一個元件、字型與大小，跟著所有設定）；預覽中每頁最多列 4 個候選字（改「每頁的候選字」之後 8 秒內列出全部），清單寬度只占需要的寬度，旁邊寫出這個狀態的說明與按鍵；字級很大時整個縮小。上方的標籤切換狀態：候選字清單、修正清單、組字中、翻頁、加入自訂詞、中英切換。沒有操作時依序播放每個狀態的一小段過程（例如按 ↓ 開啟清單、按 ⇧↑ 換成修正清單、按 Tab 以真正的翻頁動態翻到下一頁），每個狀態兩個畫面、每個畫面約 1.6 秒，狀態之間淡入淡出；指標在預覽上、點了標籤或改了設定之後 8 秒內停止播放，「減少動態效果」時不自動播放。改變下面的設定時，預覽切換到顯示這個設定的狀態（例如標出修正的讀音切換到修正清單，動畫與翻頁切換到翻頁）。預覽捲出畫面時，改變設定會在指標旁浮出那個狀態約 2 秒。以下各段：「候選字清單」：排列（與改前一個字、改後一個字的按鍵）、字級、間距、每頁的候選字、選字鍵、翻頁、到頁底時 ↓ 翻到下一頁。「清單的內容」：顯示注音、點注音列打出注音、標出修正的讀音、只列一個字、單字與修正按鈕。「位置」「外觀」「動畫」「提示」（中英提示）。 |
| 字詞 | 記住選過的字詞（開關）、記住的字詞 ›、自訂詞 ›（列上顯示筆數）。下一層是清單（§4.6）。自訂詞：＋ 開啟「加入自訂詞」，輸入「詞：」後，「讀音：」自動列出可能的讀音；詞需為 1 到 6 個字。記住的字詞依常用程度由高到低排列（以五格小長條表示；引擎記的是隨時間變淡的權重，不是次數），設為不記住的字詞以「不記住」標示，「更多」選單有「不再記住所選字詞」「匯出…」「匯入…」「全部清除…」。 |
| 分析 | 見 §2.8：期間（過去 30 天、全部）、回顧（送出的字、連續天數、最多的一天、一次就對、每 100 字改幾次）、每天送出的字、打字節奏（打字速度、一次就對、最長連續、打字時間與思考停頓、一次不改字最長、每個字按幾個鍵、思考停頓的中位數、一週中每小時打的字）、打字、從清單選字、改字、你的字詞、效能 ›、「記錄使用統計」與「清除統計…」。 |
| 快捷鍵 | 所有動作與按鍵的索引，依「組字」「候選字清單」「改字與選取」「標點與符號」「中英切換」分組，只顯示、不在這裡修改。工具列搜尋；有按鍵衝突時列在最上方，每一個連到相關的列。每列有名稱、說明、唯讀的按鍵與「›」；和預設不同的列有安靜的「已自訂」標記。點一下任何一列，開啟功能的頁面並以到達提示標出它的「快捷鍵」列，在那裡修改或「還原預設」。功能的開關在各自的頁面：關閉的功能變暗，列尾是「已關閉 ›」。無法更改的按鍵收在「固定的按鍵」，點一下展開，搜尋時自動展開。頁尾是一行說明與文字按鈕「全部還原…」（先確認）。 |
| 進階 | 「改字記錄」（§2.7）、在候選字視窗顯示組字的 App ›（＋ 列出正在執行的 App 與「選擇其他 App…」）、「回復預設設定」。 |
| 關於 | App 圖示與版本、「更新」區塊（見 §3.4）、「程式授權」「詞庫授權」「詞庫資料」。 |

匯出的檔案預設名稱為「ZhuyinType 個人資料.txt」，包含自訂詞、記住的字詞、個人連詞、不記住的字詞與按錯習慣。匯入的資料加到這台 Mac 現有的資料中，同一筆資料保留較強的記憶。「全部清除…」清除記住的字詞、個人連詞與按錯習慣，不記住的字詞保留。

### 4.6 清單

清單頁（記住的字詞、自訂詞、在候選字視窗顯示組字的 App）和其他頁用同一套設計：上方固定的列寫出上一層與頁名（內容捲到下面時才出現材質與細線），下面一行工具列有搜尋、筆數（「共 21 個」）、排序與 ＋ 或「更多」，清單在標準的卡片中，每列是字詞、灰色的讀音與右邊安靜的資訊。清單是頁面本身捲動的一部分，沒有固定高度的內層捲動，視窗多高就顯示多少，列是延遲建立的，資料多時也流暢。指標移到某一列時，右邊的資訊換成「編輯」（自訂詞）與「刪除」，版面不動；也可以點選（⌘ 多選）後按 ⌫，或用右鍵選單。刪除時那一列收合、下面的列跟著上移；新增的列淡入；搜尋時列的出現與消失也有動畫。沒有資料或搜尋沒有結果時，卡片中寫一句簡短的說明。進入下一層時內容從右邊滑入 24 pt 並淡入（0.22 秒），返回時反過來；「減少動態效果」時只淡入淡出。

## 5. 專案結構

```
ZhuyinType/
├── engine/                   引擎（Rust workspace）
│   └── crates/
│       ├── zhuyin-core/      鍵盤、組字、按鍵解碼、容錯、轉換、語言模型與個人模型
│       ├── zhuyin-models/    整句重排（v2b）與音節對字模型（v3）的判斷邏輯；Linux 以 ONNX Runtime 執行
│       ├── zhuyin-ffi/       C 介面，App 經由它使用引擎
│       └── zhuyin-cli/       命令列介面，所有評測都經由它執行
├── platforms/
│   └── macos/                macOS 輸入法（Swift package）
│       ├── Sources/ZhuyinEngine/ 引擎的 Swift 包裝，以 Core ML 執行模型
│       ├── Sources/EngineBench/  不含 App 的引擎路徑，量延遲用
│       ├── Sources/ZhuyinTypeApp/
│       │   ├── IMK/          輸入控制器、按鍵對應、引擎載入與文字客戶端整合
│       │   ├── UI/           候選字視窗、中英切換提示與設定視窗
│       │   ├── Update/       自動更新
│       │   ├── Shared/       設定與快捷鍵
│       │   └── Install/      輸入方式的註冊與啟用
│       ├── Resources/        App 資訊、圖示、在地化、授權與安裝頁面
│       └── scripts/          建置、安裝、移除、打包與發布腳本
├── ml/                       研發：資料、訓練、評測（Python，uv 專案，不隨 App 出貨）
│   ├── src/zhuyintype_ml/    core、cli（zt）、eval、training、data、remote
│   └── eval-sets/            納入版本庫的評測集
├── resources/                資料與模型的固定版本（assets.json）、來源與授權、二進位格式
├── tools/                    zt 啟動器與推送前的公開檢查
├── docs/                     產品、引擎、ml、研究、每版成績與發布說明
├── appcast.xml               自動更新的版本清單（由 CI 更新；已安裝的 App 讀這個網址）
├── .github/workflows/        CI（依目錄觸發）、發布與 ZhuyinBench
├── data/                     只在本機：下載或訓練產生的資料與模型（data/build/）
└── references/               只在本機：供研究的其他輸入法
```
