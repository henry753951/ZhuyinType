# 設定視窗的資訊架構

本文件寫設定視窗的整體架構：側欄有哪些項目、每一頁放什麼、哪些設定放到下一層，以及頁面之間怎麼連結、連結到達時怎麼標出目標。各頁的細節見 [DESIGN.md](DESIGN.md) §4.5。三個平台（macOS、Windows、Linux）的側欄、頁面、段落與列的順序相同，只有標明「Linux／Windows」或「macOS」的列只在那些平台出現。

## 1. 原則

1. **一頁一件事。** 側欄的每一項管一件使用者說得出名字的事：打字的按鍵、標點、中英切換、選字、修正、字詞、候選字視窗、色彩。一頁不超過約一個半螢幕高；打開一頁，多數人會調整的選項都在眼前。側欄十四項，以小灰字的段落標題分成五段（§2）。
2. **名稱就是內容。** 頁名 2–5 個字，用台灣慣用詞（[WRITING.md](WRITING.md)），和段落標題不重複。一個功能出現在它的名稱會被找的地方：「符號與 Emoji」在「標點與符號」，「快速設定」在「中英切換」，「暫停學習」在「字詞」，「檢查輸入法」在側欄。
3. **細節與少改的設定放到下一層。** 一頁中以「›」結尾的列開啟下一層：清單（自訂詞、記住的字詞、在候選字視窗顯示組字的 App）、一整組開關（模糊音）、說明較多的功能（前文）、唯讀的查詢（所有打字的按鍵、效能、授權與資料來源）。列上直接顯示目前的狀態，例如「模糊音　已開啟 2 項 ›」。下一層的上方是「‹ 上一層」與頁名，側欄維持選取上一層。
4. **一個功能只在一個地方。** 功能的開關、它的按鍵、說明與示範放在一起：先是功能列（名稱、可以換行的說明與開關），下面縮排一列「快捷鍵」放按鍵欄位，功能關閉時不顯示這一列。不在兩頁各放一份會互相矛盾的設定；需要從別處提到時用連結，不複製控制項。
5. **按鍵在功能旁邊設定；「快捷鍵」是索引。** 每個可以自訂按鍵的功能，在自己那一頁就有按鍵欄位（§3）與「還原預設」，三個平台都一樣。「快捷鍵」頁把所有動作與按鍵列成一張表，段落和側欄的頁面一一對應（打字、標點與符號、中英切換、候選字視窗、修正、字詞），可以搜尋、看按鍵衝突；每一列的 › 到功能的頁面並標出它的「快捷鍵」列。兩處修改的是同一份資料。
6. **功能是否開啟只有一個來源。** 功能被其他設定關掉時（例如關閉「顯示注音」後，「點注音列打出注音」沒有作用），相關的列變暗，寫一行原因，並連到那個設定。
7. **0.7 加入的功能放進原本的結構，不另立「新功能」區。** 每個功能放在它所屬的頁與段落，並調整那一頁的其他列（§2.1 的理由欄）。「介紹」的功能卡片列出所有主要功能，各連到所在的列。
8. **基本與進階。** 每個人都可能調整的放在「輸入」「選字與字詞」「外觀」三段；只有特定需求才用的（改字記錄、在候選字視窗顯示組字的 App、回復預設設定）放在「進階」。
9. **每一個連結都到得了。** 連結到達時切換頁面（需要時打開下一層）、捲到目標、把鍵盤焦點放在目標上，並讓目標亮一次（§4）。所有連結的目標都列在一張表裡，自我測試確認每一個都對應到畫面上真的有的列（§4.3）。

參考：macOS 系統設定（側欄分段、以 › 進入下一層、搜尋結果到達時目標亮一次）；Windows 11 設定（「個人化 › 色彩」把淺色與深色、透明效果、輔色放在同一頁，「系統 › 疑難排解」自成一頁）；微軟注音與微軟拼音（把按鍵、外觀與學習分頁）；小麥注音（一般與鍵盤分頁）。這些輸入法的範圍與 ZhuyinType 不同，分頁只取其中適合的做法。

```

  介紹、分析

  打字、標點與符號、中英切換
```

### 2.1 每個設定放在哪裡、為什麼

| 設定 | 位置 | 理由 |
|---|---|---|
| 空白鍵、Esc | 打字 › 空白與 Esc | 常改；影響每一次打字的收尾 |
| 送出並換行、刪掉一個詞、在組字中放一個空白 | 打字 › 編輯組字 | 都是組字中的編輯按鍵；「放一個空白」原本和標點放在一起，但它不是標點 |
| 固定的打字按鍵 | 打字 › 所有打字的按鍵 | 唯讀，供查詢 |
| 標點按法、切換標點全半形 | 標點與符號 › 標點 | 從 Windows 或 macOS 換過來的人第一天就會改；原本「打字」與「標點與符號」下一層各有一份，合成一頁 |
| 符號與 Emoji 面板 | 標點與符號 › 符號與 Emoji | 打不出的符號從這裡找；和標點按法同頁，三個平台位置相同 |
| ⌃ 中文標點、⌥ 鍵上的符號 | 標點與符號 › 修飾鍵打標點 | 少改；和標點按法是同一個功能 |
| 單按 Shift、使用的 Shift、Caps Lock 打英文 | 中英切換 › 切換鍵 | 同一個功能；常改的是切換鍵 |
| 開始輸入時使用英文、中英提示 | 中英切換 › 預設與提示 | 切換的預設與回饋；「中英提示」原本在「視窗與提示」並從「打字」連過去，現在開關就在切換鍵旁 |
| 開啟快速設定 | 中英切換 › 快速設定 | 快速設定是切換中英（和全半形、繁簡、暫停學習）最快的地方，也是切回中文的方法 |
| 游標在句中時改、台／臺、繁／簡 | 選字 › 轉換 | 影響選出來與送出的字 |
| 參考游標前的文字 | 選字 › 前文 › | 一個開關在本頁；說明較多，放在下一層 |
| 送出後列出聯想詞 | 選字 › 聯想詞 | 送出後接著選下一個詞，是選字的延伸；開關改變的是打字的行為，不是視窗的樣子 |
| 按錯鍵修正、接受常見的其他讀法、模糊音 | 修正 › 按錯鍵 | 自動修正的三個來源放在一起 |
| 標示自動修正、⌫ 還原自動修正、列出修正的字 | 修正 › 修正過的字 | 看見、還原與查看自動修正；原本和按錯鍵修正擠在一段 |
| 打出注音本身、送出後刪掉重打 | 修正 › 改字 | 自己改正選字的方法 |
| 記住選過的字詞、暫停學習、記住的字詞清單 | 字詞 › 記住 | 學習的開關、暫停與結果在一起；暫停學習原本只在選單 |
| 自訂詞、選取加入自訂詞、選取的字加入自訂詞 | 字詞 › 自訂詞 | 三種加入自訂詞的方法和清單在一起；原本分散在「選字 › 改字」與快捷鍵 |
| 不要再推薦、忘記這個選字、加入自訂詞 | 字詞 › 在候選字視窗中 | 在候選字視窗管理字詞，結果出現在「記住的字詞」與「自訂詞」 |
| 排列、字級、間距、每頁的候選字、選字鍵 | 候選字視窗 › 候選字清單 | 視窗的樣子；有預覽 |
| 翻頁、到頁底時 ↓ | 候選字視窗 › 翻頁 | 在清單中使用；自成一段，清單的段落變短 |
| 顯示注音、點注音列、標出修正的讀音、只列一個字、單字與修正按鈕 | 候選字視窗 › 清單的內容 | 清單上出現的東西；有預覽 |
| 位置、動畫 | 候選字視窗 › 位置與動畫 | 視窗出現在哪裡、怎麼出現 |
| 主題、透明效果（Linux／Windows）、候選字視窗的淺色與深色、強調色 | 色彩 | 和 Windows「個人化 › 色彩」相同，一處改所有視窗的顏色；原本擠在「視窗與提示」的段落中 |
| 增加對比、減少透明度、減少動態效果 | 色彩 › 無障礙 | 系統的設定，ZhuyinType 跟著改；列出目前的狀態，使用者知道為什麼視窗變成不透明或沒有動畫 |
| 記錄使用統計、清除統計 | 分析 | 和統計的結果放在一起 |
| 檢查輸入法、回報問題 | 檢查輸入法（側欄） | 無法打字時最需要；原本藏在「關於 › 」，現在側欄一項，警示符號就在它旁邊 |
| 改字記錄、在候選字視窗顯示組字的 App、回復預設設定 | 進階 | 少用或影響大 |

## 3. 按鍵欄位（同一個元件用在每一處）

功能頁、「快捷鍵」總覽與示範的按鍵標示都使用同一個元件：

- **樣式**：每個按鍵畫成按鍵圖示，修飾鍵各自一個（⌃ ⌥ ⇧ ⌘ 依系統的順序；Linux／Windows 寫 Ctrl、Alt、⇧、Win／Super），樣式在每一頁都相同。
- **多個按鍵**：一個動作最多五個按鍵。指標移到欄位上時出現「＋」（加入另一個按鍵）；按鍵上按右鍵可以「改按鍵」「移除這個按鍵」「全部還原成預設值」。
- **錄製**：點一下按鍵開始錄製，外框以強調色緩慢明暗變化，顯示「按下新的組合…」；按住修飾鍵時即時顯示已按下的鍵；按 Esc 取消。接受時按鍵輕輕彈一下並出現綠色勾號；拒絕時欄位輕微左右晃動，下方以紅字寫出原因。「減少動態效果」時改成淡入淡出。
- **還原**：按鍵和預設不同時，功能頁的「快捷鍵」列上有文字按鈕「還原預設」；總覽標「已自訂」。
- **版面不動**：「＋」的位置一直保留，指標移過時只改變透明度；錄製、接受與拒絕也不改變欄位的高度。
- **衝突**：錄製時拒絕已用於其他動作的組合，訊息寫出那個動作的名稱。已存在的衝突以系統紅色的細外框與淡紅底顯示，下方一行紅字「也用於「列出修正的字」」，附「改按鍵」與「前往」。「快捷鍵」總覽的最上方列出所有衝突。
- **停用**：功能關閉時，欄位變暗、不能編輯，列上寫「已關閉：⌃U 交給 App」。

資料：每個動作存成有順序的按鍵清單（第一個是主要的按鍵）。舊版每個動作一個按鍵的設定，讀取時當成只有一個按鍵的清單。引擎不變。

## 4. 連結

### 4.1 到達提示

每一個連到某一列的連結用同一個機制（每個平台一處程式，見 §4.4），不在各頁各寫一套：

1. **切換頁面**：側欄選到目標頁；目標在下一層時先打開那一層（下一層的上方是「‹ 上一層」）。目標在收起的區塊中（例如「快捷鍵 › 固定的按鍵」）時先展開。
2. **捲動**：捲到目標列約在可見範圍的上方三分之一，所在段落的標題也看得到；目標是整個段落時，段落標題在上方。「減少動態效果」時直接跳到那裡，不做捲動動畫。
3. **鍵盤焦點**：焦點移到目標列（有控制項時是那一列的控制項），接著按 Tab 從那裡往下走；VoiceOver 與螢幕報讀程式讀出那一列。
4. **亮一次**：目標列的底色以強調色約 17% 亮一次（0.2 秒淡入、停 0.8 秒、0.8 秒淡出），所在段落的標題同時變成強調色；目標是整個段落時，整個段落一起亮。不畫外框，不改變版面。「減少動態效果」時只淡入淡出，不做捲動動畫。
5. 從側欄點頁面、或下一層的「‹」返回時不做到達提示（那不是連到某一列）。

### 4.3 每一個連結都有目標

每個平台把所有連結的目標集中在一處（macOS `SettingsLinks`，Linux／Windows `pages::links`），每一個目標是「頁、下一層、列」。自我測試（macOS `--self-test`，Linux／Windows `cargo test`）逐頁、逐個下一層畫出設定視窗，記下畫出的每一列的 id，確認表中每一個目標都對應到畫出來的列，也確認每個可以自訂按鍵的動作在功能頁與快捷鍵總覽各有一列。
