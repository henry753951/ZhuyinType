# 文案準則

適用於介面文字、說明、README、安裝程式與文件。

## 原則

1. **直接描述能做什麼，不描述避開了什麼。**
   ZhuyinType 本來就具備這些能力，所以文案只寫它做得到的事，不拿「別的軟體會怎樣」來對比，也不寫「不會……」「不再……」「改善了……」。
   - ✗ 「Backspace 不會一次清空整段」　✓ 「Backspace 刪除游標前的一個字」
   - ✗ 「在 Electron App 裡也能直接顯示，不會跳出視窗」　✓ 不需要提；在任何 App 裡都本來就是這樣
   - ✗ 「跟其他輸入法不同，ZhuyinType 會記住你的選擇」　✓ 「記住你選過的字詞」
2. **理所當然的事不寫。** 一般使用者預期本來就該這樣運作的行為（組字顯示在游標處、能在每個 App 打字、切換中英時保留已打的字），不必另外說明。
3. **不點名 App 或技術框架**（Electron、Chromium、某某 App），除非使用者一定要知道才能操作。
4. **短。** 設定項目的標籤用 2–6 個字；說明文字最多一句，只在選項的意思不明顯時才加。頁面不放標語或口號。
5. **用台灣正體中文與台灣慣用詞**：軟體、預設、檔案、視窗、設定、游標、選字、候選字。標點用全形（，。、：「」）。中文與英文、數字之間加半形空白（例如「左 Shift」「1–9」）。
6. **語氣平實**，像 macOS 系統設定的用語：不用驚嘆號、表情符號或行銷式形容詞。

## 提到其他專案（研究與評測文件）

研究文件常需要引用其他輸入法（靈犀注音、善解、小麥注音、新酷音等）。寫法以學術上的相關工作為準：

1. **先說明對方的貢獻與我們學到什麼**，再談比較。引用的做法、數字與結論要註明出處（連結、版本、日期）。
2. **比較寫條件，不寫輸贏**：
   - 寫出測試集由誰建立、版本、設定、正規化與逾時，並在表格旁列出限制；
   - 不用「對手」「對打」「超越」「領先」「落後」「打敗」；
   - 寫「在這組句子上 A 為 x%、B 為 y%（p = …）」。
3. **功能範圍不同時，直接說明是範圍不同**。例如對方沒有按鍵容錯的設計，就不把這一項的差距寫成對方做得不好。
4. **評價自己的不足要具體**，例如「我們的統計引擎在口語上較弱」；不評價對方的能力或用心。
5. **驗收標準用我們自己的絕對目標**；需要時才引用對方公布的數字作為參考點。
6. **不複製程式碼**：學到的做法以自己的實作重寫，並在研究紀錄註明出處；授權規則見 [research/README.md](research/README.md)。
