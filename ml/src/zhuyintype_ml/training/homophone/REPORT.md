# 相容繼續訓練（2026-10-27）

後續決定：0.4.0 採用這個模型。它沒有改壞在／再測試集的任何句子，一般開發集的差異在雜訊範圍內，詳見 [研究紀錄](../../../../../docs/research/log.md)。下面的「建議：不採用」是實驗當時的結論，保留作為紀錄。重現這條路徑的指令是 `zt train homophone`（見 [README.md](README.md)）；本報告提到的 `train_v3.py`、`export_v3.py` 現在是 `train.py`、`export.py`，路徑 `data/build/v3/`（原始 v3）現在是 `data/build/v3_030/`。

**建議：不採用。** 合乎授權的繼續訓練提高了在／再的整體正確率，但「再試試看」仍輸出「在試試看」，原本正確的「我在吃一碗麵」則變成「我再吃一碗麵」。不論整體結果是否顯著，這兩項都是明確的開發驗收失敗。針對性重試與一次參數中點嘗試也無法同時保住兩個「吃」的例子。不採用的決定在這次測試評分之前就已封存；測試集只用於追蹤。

交付的實驗套件是 `data/build/v3_homophone2/`，選定的訓練步數為 **500**，包含兩個 fp16 套件與編譯後的模型、原始詞彙表、設定、向量、PyTorch 檢查點、來源聲明與出處。它在授權上沒有問題，也通過介面驗證，但**不是完成的正式修正**。這項工作沒有改動 app、引擎、發布資產與原本的 `data/build/v3`。

## 目前 app 的成對評測

這一節的矩陣由已移除的 `ship_eval.py` 產生（在 Mac 上由 `run_compatible.py` 經 `ml/src/zhuyintype_ml/remote/run.sh` 派送到 GPU 主機）：同音字集以 `eval.py` 打字並以編輯距離對齊計分，一般開發集用 `capture_eval.py`、善解列用 `rows_eval.py`，成對統計用 `ml/src/zhuyintype_ml/eval/stats.py`。原始結果在 `data/build/homophone2/results/`。現行的對應步驟是 `zt train homophone evaluate`／`evaluate-test`，報告寫到 `homophone2/reports/`。

整個過程使用相同的凍結引擎與資料：整句重排候選數 16、**整句重排權重 0.5**、v3 權重 0.5、聊天語言模型 `data/build/lm_chat` 先驗 0.3、預設門檻 τ=8，標準鍵盤／按錯處理。在 Linux 上以 ONNX CPU 執行，使用 `ml/src/zhuyintype_ml/remote/run.sh` 的暫時副本，`REMOTE_DIR=zhuyintype/work/onnx-eval-homophone3`。基準開發集用 JOBS=24，候選與完整最終列用 40，從未超過 40。開發集決定後，選定的檢查點不再更換。不要把這些數字直接和歷史實驗 1 在不同引擎／設定下的數字比較。

成對統計使用 `ml/src/zhuyintype_ml/eval/stats.py`：exact McNemar、10,000 次成對 bootstrap 抽樣、seed 7；同音字的 bootstrap 依來源／行分群，其他資料集依列。類別檢定屬探索性；McNemar 本身不分群。位置評分使用編輯距離對齊（刪除算錯）；整句正確率要求完全相同。類別優先順序維持：固定詞 > 主詞 > 句首 > 動詞 > 地點／時間 > 其他。
